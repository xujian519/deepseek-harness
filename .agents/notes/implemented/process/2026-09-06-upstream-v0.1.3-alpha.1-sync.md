# Agent Note: upstream v0.1.3-alpha.1 sync and the session-format-v2 stream model

Status: implemented

English | [中文](2026-09-06-upstream-v0.1.3-alpha.1-sync.zh.md)

## Problem

The fork tracked upstream after the v0.1.2-rc.1 sync; upstream master advanced to `d347e70390` (released as `dsh-v0.1.3-alpha.1`, the merge-base 76fda72979 diverged by 229 upstream commits against 323 fork commits). The dominant upstream feature is session format v2: `assistant/chunk` events were removed and replaced by `assistant/message` events carrying an embedded `AssistantStream`, the `SessionPersistence` JSONL backend gained a cross-process write-ownership lease and a format migration, and a generic client file-upload service consolidated attachment admission.

## Decision

- **Chunk events retired.** `assistant/chunk` no longer exists; usage and stream content live on the `assistant/message` envelope (`usage`, `stream`). The fork's `usageOf` in `scripts/token-economy-baseline.ts` and its spec dropped the chunk branch; fixtures build `assistant/message` events with a `stream` array.
- **Session format version.** `SESSION_FORMAT_VERSION` is `2`; `SessionHeader.version` is the literal type `2`. Session fixtures and header literals that hardcoded `version: 0` were updated to `2` (self-evolve-basic tests, token-economy spec).
- **`SurfaceIntent<T>` plus `AppendOptions`.** Upstream made `SurfaceIntent` generic over the surface event type so a v2 `assistant/message` cannot cite top-level source events (`sourceEventSeqs?: never`). The fork keeps its non-surface `AppendOptions` / `ignorable` append marker (patent-teams still appends `{ ignorable: true }`); the `Session.append` signature and JSDoc combine both.
- **Packed chunk rows deleted.** Upstream removed the packed `chunk-rows` session module (the old packed-run format superseded by format v2). The fork had only sunk `isRecord` into `dsh-value`; the file and its exports were removed, and the `tsconfig.base.host.json` `dsh-session/chunk-rows` alias dropped.
- **File-upload and per-face split.** `client/file-upload`, `session-format`, `session-format-catalog`, and the v0-to-v1 / v1-to-v2 migration packages arrived. The Host aggregate `tsconfig.base.host.json` gained the new package aliases and dropped the stale chunk-rows alias; `tsconfig.host.json` references the new session-format projects.
- **Package versioning.** Test-support and session `package.json` dependencies were resolved to keep both the fork's `dsh-value` (`isRecord`, `isENOENT`) and upstream's `session-format*` packages, matching each package's source imports.
- **Fork session fixtures migrated to the v2 vocabulary.** `sidechat-seed-validation` parent logs now use `assistant/message` with an embedded stream instead of the retired `assistant/chunk`; the ui-chat `assistant/live-chunk` projection folds away null/non-object block-end and skips non-string deltas instead of throwing; and the `patent-teams-panel` snapshot was rewritten from format v0 to v2 (`migrate:packed-session-fixtures`). These were the fork's own event-shape consumers and seeds, which the v2 validator now checks.
- **Docs.** Generated catalogs (config-catalog, persistence-catalog, module-graph, capability-seams, event-producer-consumer, cordis api-catalog, known-event-types), the lockfile, and the affected bilingual doc pairs were regenerated / re-recorded; the agent-note CI paragraph keeps the fork's `workflows-disabled/` path while adopting upstream's fifth macOS x64 build target.

## Consequences

The fork shares upstream's session-format-v2 vocabulary (embedded assistant streams, `assistant/message`-carried usage, `version: 2` headers) and the write-lease / migration backend, while preserving its `ignorable` append marker and `dsh-value`-sunk helpers. The Host and Client `tsc -b` aggregates and the `tsdown` bundling step now pass. The `tsdown` failure was not a source issue: the stale, untracked `code-runtime-python` directory under `packages/code-runtime` carried a `node_modules` but no `package.json`, so tsdown's config discovery climbed to the root solution package and demanded `lib/types/{index,invariant,startup}.js`; removing that stray directory restored the build. The fork-only packages were version-bumped to `0.1.3-alpha.1` to satisfy the version constraint, the dependency-classification policy gained the new runtime export edges, `verify-package-dependencies --fix` repaired the client-package dependency sections, and `python/sdk-runtime` gained its preset plugins' peers (`dsh-tool-plugin-market`, `dsh-host-plugin-market`).

## Alternatives considered

- **Sync branch + PR into `master`, rather than merging directly to `master`.** The prior `v0.1.2-rc.1` sync landed the same way, so this keeps history reviewable and lets a `sync/upstream-*` branch be stacked. Direct-to-master was rejected because a 1679-file cross-repo merge belongs behind a reviewed PR.
- **Repair the `tsdown` root failure by editing `tsdown.config.ts`, rather than removing the stray directory.** The config was unchanged from master and declared the root package's expected entry, so editing it would have masked the real stray artifact; removing the untracked `code-runtime-python` directory fixed the cause without touching an upstream-owned file.
- **Re-generate the missing `typert.remote-client.d.ts` artifacts by hand, rather than fixing `tsdown`.** The `/remote` type declarations are tsdown/typert build products; patching them by hand would have diverged from the generator and been overwritten on the next build, so the build was repaired instead.

## Testing

`pnpm run typecheck` (Host `tsc -b` + `tsdown` + Client `tsc -b`) and `pnpm run hygiene` (16 gates) pass locally on macOS, as does `pnpm run doc-sync` after the doc format fixes. The bilingual doc pairs were re-recorded (`verify-translation-pairing`). Linux-lane CI remains the platform-of-record run for this merge.
