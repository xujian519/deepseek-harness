# Agent Note: upstream v0.1.5-rc.1 sync and the per-face build upkeep

Status: implemented

English | [中文](2026-09-10-upstream-v0.1.5-rc.1-sync.zh.md)

## Problem

The fork tracked upstream after the v0.1.5-alpha.1 sync; upstream master advanced to `aa8262ec09` (released as `dsh-v0.1.5-alpha.2` and `dsh-v0.1.5-rc.1`, 288 upstream commits against 398 fork commits from the merge-base `5dda764ed3`). The upstream delta centers on Sidebar document previews (Markdown, code, HTML, PDF, images) replacing the fork's own `ui-sidebar-textpreview`, explicit model file delivery with the new `present` tool and `sessionFeedback` remote, the `command-feedback` feedback package, `DeepSeek-V41-Flash` in the model catalog, the `ui-deliverables` per-face tsconfig split, and a third-party-notices generator that walks every client bundle.

## Decision

- **Union registrations.** The remotes mount list keeps the fork's `pluginMarketRemote` and gains upstream's `sessionFeedbackRemote`; the standard preset gains upstream's `present` tool beside the fork's plugin-catalog tools; `tsconfig.base.json` gains `chunked-list`, `tool-present`, and `command-feedback/types`, and the fork-only `tsconfig.base.host.json` face map gains the non-client subset (`chunked-list`, `tool-present`, `tool-present/types`, `command-feedback/types`).
- **Dependency classification.** `ui-trajectory` adopts upstream's move of `@tanstack/react-virtual` and `diff` to `devDependencies` while keeping the fork's `^3.14.10` floor (the debounce-timer jsdom fix); `llm-deepseek` gains upstream's `dsh-attachment-local` beside the fork's `dsh-brand`; `ui-deliverables` takes upstream's expanded devDependency set plus the fork's `dsh-value`.
- **Per-face tsconfig for `ui-deliverables`.** Upstream split the package into `tsconfig.host.json` / `tsconfig.client.json` with a solution-style root; the fork's `../../util/value` project reference moved into the client face, where its `isRecord` import lives.
- **Test adaptations follow upstream's harness.** `user-patches.spec.ts` now drives an injected fake `FSWatcher` with explicit emits, so the fork's per-call 20-second FSEvents budgets were dropped while the fork's load-average failure diagnostic stays in the `eventually` helper; `spill-local`'s boundary test uses upstream's write-then-read-back-mtime cutoff instead of the fork's whole-second pin.
- **Browser notices for the first-party sidebar.** Upstream's notices generator resolves each client bundle by the `<package>/client` tsdown config name; `dsh-better-sidebar`'s custom bundle config (lazy preview chunks, own `/sidebar/bundle` route) carried no name, so the config is named `@deepseek-ai/dsh-better-sidebar/client` and `THIRD_PARTY_NOTICES.md` records its bundled externals.
- **Version family and stale metadata.** Thirty-seven fork-only manifests moved to `0.1.5-rc.1` to satisfy the workspace version constraint, with the `SIDEBAR_SERVICE_VERSION` mirror updated; `desktop-seam`'s `repository.directory` was repaired from the stale pre-rename `packages/desktop/desktop` path.
- **Generated surfaces.** config-catalog, event-producer-consumer, module-graph, tool-catalog, persistence-catalog, slot-catalog, the cordis catalogs, and `known-event-types` were regenerated from the merged source; the zh counterparts followed through pairing, and the lockfile was regenerated by pnpm. Upstream's `2026-09-09-cancel-superseded-ci` agent note had its workflow links re-pointed at the fork's `workflows-disabled/` archive, and the fork's `ui-sidebar-textpreview` surface is superseded by upstream's `ui-sidebar-documentpreview`.

## Consequences

The fork ships upstream's v0.1.5-rc.1 baseline with its desktop, patent, self-evolve, synapse, plugin-market, openviking, and better-sidebar surfaces intact. Every client bundle that the notices generator walks now needs the `<package>/client` config name, which first-party bundles with custom tsdown pipelines must carry. The host-face alias map remains hand-maintained on each sync: an upstream package missing there fails only at bundle time with a typert resolution error, not at `tsc -b`.

## Alternatives considered

- **Sync branch + PR into `master`, rather than merging directly to `master`.** Every sync since v0.1.2-rc.1 landed behind a reviewed PR; a ~2100-file cross-repo merge keeps that history reviewable.
- **Keep the fork's whole-second cutoff pin in the spill boundary test.** Rejected: upstream's read-back of the actual post-rounding mtime tests the same strictly-older contract without coupling the assertion to `utimesSync` seconds precision.
- **Take upstream's zh catalog documents wholesale.** Rejected: they lack the fork-only package sections (patent, better-sidebar, plugin-market, self-evolve); the en regenerated catalogs plus targeted zh deltas keep both sides complete and pairing-consistent.

## Testing

`pnpm run typecheck` (Host `tsc -b` + `tsdown` + Client `tsc -b`), `pnpm run doc-sync` (34 gates, 966 bilingual pairs), and `pnpm run test` pass locally on macOS; the bilingual pairs were re-recorded with `verify-translation-pairing --write`. Linux-lane CI remains the platform-of-record run for this merge.
