# 侵权比对意见书 — 版式惯例（Conventions）

> 生成或修改本模板前必读。与 `checklist.md` 配套。

## 1. 文书结构（固定顺序）

1. 页眉（所名 + 密级；对外版可删除）
2. 文书抬头（类型徽标 / 标题 / 案卷号）
3. 案件信息表（涉案专利号 / 发明名称 / 专利权人 / 被控产品 / 委托方立场 / 报告日期）
4. 权利要求解释（权利要求 1 全文 + 解释结论）
5. 被控物特征分解
6. 全面覆盖逐特征比对
7. 等同分析（待定特征）
8. 结论与风险（含证据附录）
9. 落款 + 免责声明 + 页脚（对外版可删除）

## 2. 权利要求解释规范

- 以授权公告文本为准；引用权利要求原文，不得改写。
- 解释结论写明：功能性特征、显然区别特征、隐含特征；禁反言与捐献限制逐项列出。

## 3. 逐特征比对规范

- 特征号连续（1, 2, 3…），与被控物特征清单一一对应。
- 比对结论取值：相同 / 等同 / 未落入；结论旁附徽章（low 相同 / mid 等同-待论证 / high 未落入）。
- 每条结论给出理由；证据支撑的用 `badge-evidence`。

## 4. 等同分析规范

- 按「手段-功能-效果」三要素逐项填写，缺一不可。
- 显而易见性判断：所属领域技术人员无需创造性劳动即可想到。
- 限制因素（禁反言、捐献、现有技术抗辩）必须单独列出，影响等同认定。

## 5. 立场纪律

- 委托方立场为专利权人（主张方）时，等同主张为扩张方向；为被告（抗辩方）时，等同排除与现有技术抗辩为收缩方向。
- 结论保持同一句式模板：「被控产品/方案是否落入权利要求 1 的保护范围」+ 依据，不因立场而选择性遗漏反证。

## 6. 视觉与版式纪律

- 沿用 `assets/templates/patent/tokens.css` 品牌变量；agent 不改样式。
- 表格行避免跨页断裂（`page-break-inside: avoid` 已内置）。
- 专利号、特征号使用等宽字体（`.mono`）。

## 7. 品牌契约注入点

同 `assets/templates/patent/DOCS.md` 与 `tokens.css`。抬头所名、密级由 CSS 变量注入。
