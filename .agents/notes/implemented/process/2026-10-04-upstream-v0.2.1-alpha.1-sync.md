# Agent Note: upstream v0.2.1-alpha.1 sync

Status: implemented

English | [中文](2026-10-04-upstream-v0.2.1-alpha.1-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.2.0-rc.2` tag to the `dsh-v0.2.1-alpha.1` release: 266 upstream commits (201 without merges) across 4190 files. The merge base sat on the rc.2 release commit, so the merge reported the 128 conflicts the two releases actually share (102 content, 25 delete/modify, one modify/delete) instead of re-deriving earlier releases.

Upstream's release retires a subsystem the fork still used and moves three surfaces the fork had shaped. The runtime invariant stack is gone: `@deepseek-ai/dsh-invariants`, every package's `./invariant` companion, the five `sdk-minimal` rows, and the gates that proved them (`scripts/package-invariants.ts`, `verify-package-invariants`, `test-invariants`). The release ships an upgrade guide for it and calls the removal breaking. Workspace registration drops the explicit title argument (`create(path)` derives the display title), the shipped presets regain the `time-context` and `tool-schedule` rows that rc.1 had moved into the opt-in `dsh-experimental-schedule-bundle` — which upstream retires in the same release — and the desktop host defaults to an operating-system-assigned port. New surfaces arrive with them: `ctx.claudeCodeMods` over `experimental/claude-code-mods`, the optional `experimental/inspector-profile` developer-tools bundle, `--public-url` for Web, plugin management's agent-authored plugin entry, and unsent initial prompts.

The fork owns the Electron desktop profile directory, the `@deepseek-ai/cordis/...` event names, the `dsh-timeout-guard` and `dsh-prompt-cache` package names, and its patent, self-evolve, desktop, better-sidebar, plugin-market, and document surfaces.

## Decision

- **The runtime invariant subsystem goes with upstream's removal.** The fork's remaining companions (`patent-teams`, `patent-workflow`, `self-evolve`, `prompt-cache`) and the upstream ones it had modified are deleted with the mechanism: 18 sources and specs, five `./invariant` exports, nine `runtime-diagnostics/invariants` tsconfig references, the `apps/cli` and `examples` dependencies, the better-sidebar `SidebarInvariantsService` mirror, the two package tsdown companion entries, and the `package-invariants` gate registration. Keeping the fork's own checks would have meant re-adopting the deleted service, the retired profile rows, and the emitter rethrow behavior upstream deliberately dropped. The root and package AGENTS.md invariant rules are upstream's deletions and travel with it.
- **Version, pins, and generated artifacts move with the release.** The 46 fork-only manifests and `SIDEBAR_SERVICE_VERSION` join the root's `0.2.1-alpha.1`; the nine `snapshots/acp/*/stdout.expected.jsonl` pins follow, because `agentInfo.version` derives from the acp manifest. Every generator ran on the resolved tree (`gen-tsconfig-paths`, `gen-cordis-catalog`, `gen-client-catalog`, `gen-cordis-inspect-catalog`, `gen-tool-catalog`, `gen-config-catalog`, `gen-persistence-catalog`, `gen-doc-graphs`, `gen-module-graph`, `gen-plugin-packages`, `gen-dependency-catalog`, `gen-session-format-catalog`), and `pnpm run verify-no-unknown-casts --prune` reported no new assertion to `unknown`.
- **The notes upstream archived stay at upstream's sealed content, and the fork's links follow them.** Upstream archived 13 notes the fork had edited under `implemented/`; the merge fused both sides, which changed the sealed hashes the frozen-archive gate owns. The archived pairs are restored to upstream's content, the fork's pairing records for the removed `implemented/` sides are deleted, and the 26 links that pointed at the moved notes are repointed at `.agents/notes/archived/<kind>/`. The same pass repointed the notes' `.github/workflows/` links at `.github/workflows-disabled/`, the fork's location for those workflows.
- **`docs/capability-seams.zh.md` is mirrored, not generated.** The English page is generated and lost its `ctx.invariants` row and graph nodes; the Chinese page is authored, so the row, the graph node and edges, and the `ctx.sessions` consumer list are edited to match, and the `ctx.claudeCodeMods` row and graph node upstream added are translated in.
- **`packages/bundle/web-app` keeps both sides' publication lists.** The manifest keeps the fork's patent and document preset guides and `skills` directory, and adds upstream's `lib/public-url-*.js` chunk. `scripts/check-workspace-constraints.ts` gained a second `@deepseek-ai/dsh-web-app` entry in `packageFileExtras` from the merge (upstream's new entry landed beside the fork's); the two are folded into one list in the fork's entry, which is what the constraint requires.
- **`dsh-experimental-schedule-bundle` leaves `apps/cli`.** Upstream retired the bundle and made Automation tasks part of Web again, so the dependency, and the two empty package directories the merge left behind (`packages/experimental/schedule-bundle`, `packages/runtime-diagnostics/invariants`), are removed.
- **The desktop host adopts the operating-system-assigned port.** `--port 0` replaces the fork's inherited `19387`; the shell already reads the served URL from the readiness message. The fork's composition overlay and its `@deepseek-ai/dsh-desktop-host` resolution anchor stay.
- **Upstream's new e2e test is adapted to the fork's workspace API.** `apps/web/tests/draft-initialization.e2e.ts` called `workspaceRegistry.create(path, title)`; the fork's `create(path)` derives the title, so the fixture drops the argument and asserts against the returned `title`.
- **The preset-divergence baseline is re-recorded for the two `tool-subagent` rows.** Upstream's release denies the four schedule tools to subagents in the shared presets, which changed those rows' block hashes in the three presets that carry them; every other row's hash is unchanged.
- **The remaining conflicts resolve as unions.** `packages/boot/app-boot/src/profile-resolution/service.ts` keeps the fork's `installedByProfile` beside upstream's `refresh`; `packages/client/ui-conversation` keeps the fork's selection-and-claims activity model beside upstream's routed event dispatch, `bindDraftPersistence` rename, and the `Match`-carrying `acceptMatch`; `packages/core/tools/src/ptc.ts` keeps the fork's `run-code-flavor.ts` extraction beside upstream's argument-order text, which lands in that module; `packages/client/ui-agent-preset/src/client/AgentPresetSeat.tsx` keeps `SEAT_PRESET_LOCKED` beside upstream's structured refusal error and its `errorText` translation; `scripts/run-gates.ts` keeps the fork's mode set and adopts upstream's Electron-provisioning split; `scripts/run-gates.spec.ts` keeps both Electron assertions; `packages/schedule/schedule/src/index.ts` takes upstream's `delegationDepthOf` import and the fork's `dsh-session/types` specifier; `packages/test-support/session-snapshot/src/harness.ts` keeps the fork's `waitForPersisted` wait in place of `vi.waitFor`.
- **The lockfile, the archived manifest, and the generated pages are regenerated.** `pnpm install --lockfile-only` ran on the resolved manifests, `verify-archived-agent-notes --write` re-sealed the fork's own archived note beside upstream's, and the pairing records were re-recorded for every page either side changed.

## Consequences

The fork ships upstream's v0.2.1-alpha.1 baseline with its patent, self-evolve, desktop, better-sidebar, plugin-market, and document surfaces intact, and the history stays connected: `git merge-base HEAD dsh-v0.2.1-alpha.1` is the release commit, so the next sync reads the real conflict set. Three divergences now need attention at each release: the fork's presets are the merge's landing place for upstream's composition changes, the archived-note seals must match upstream's for the notes it retires, and the fork's notes must track upstream's workflow paths into `workflows-disabled/`.

The four fork-owned invariant checks up to the removed mechanism are gone; the payload validation they performed (patent-teams durable events, patent-workflow state, self-evolve records, the prompt-cache prefix contract) is now covered only by each package's own tests, where those exist. The debt ledger still cites the deleted `invariant.ts` files by line inside its patent-domain entries; those citations sit behind bare `src/` paths the path gate does not scan, so they stay for the next debt sweep.

`pnpm run doc-sync` gates and the full check set were run on this tree; the results are in the Testing section below, and the failures that remain are recorded there rather than fixed here.

## Alternatives considered

- **Keeping the fork's own invariant companions by restoring the service.** Rejected: it re-adopts a subsystem upstream deleted, needs the five `sdk-minimal` rows and the emitter rethrow behavior back, and re-conflicts at every later sync; the fork's AGENTS.md rule already pushed toward omitting an invariant unless the observation can diverge.
- **Keeping the merge's fused content in the archived note pairs and re-sealing.** Rejected: the frozen-archive gate treats a changed seal as an error, and there is no re-sign mode; the archived copy has to stay what upstream sealed.
- **Reseeding `apps/web/tests/draft-initialization.e2e.ts` from upstream.** Rejected: the fork's `create(path)` is the live API, and the test's point is the draft lifecycle, not the title argument.
- **Leaving the `packageFileExtras` duplicate in place.** Rejected: an object literal keeps only the later entry, so the fork's four guide files and `skills` directory would silently stop being published.
- **Dropping `packages/bundle/web-app`'s preset rows to match upstream's list exactly.** Rejected: the fork ships the patent and document preset layers, and the constraint's expected list is the union the fork's own entry declares.

## Testing

`pnpm run typecheck` exits 0 on both compiler faces; `pnpm run lint` exits 0 across 6458 files with 90 rules; `pnpm run build` exits 0 (the Host type check, both tsdown passes, the Desktop bundle, and the Web build) and records 369 client artifacts. `pnpm run constraints` passes with one version across the family, and `pnpm exec tsx scripts/release/verify.ts --family dsh` resolves 367 members at `0.2.1-alpha.1` with the publish order resolved.

`pnpm run doc-sync` reports 47 of 47 gates passing. The pre-merge tree failed one of them on material this sync owns: `verify-package-paths` cited the deleted invariant and chat-partial modules, and `verify-md-links` could not resolve the links whose target notes this release archived. Both are repointed here. The other gates this sync owes pass on the same run: `verify-archived-agent-notes` (2775 frozen artifacts), `verify-translation-pairing` (1175 pairs, recorded after this sync's edits), `verify-md-links` (2351 files), `verify-package-paths` (7154 files), `verify-no-unknown-casts` (1873 retained baseline assertions, none added), `verify-preset-divergence` (27 divergent row ids, re-recorded for the two `tool-subagent` rows), `verify-persistence-changes` (82 roots matching 12 history records), and `verify-persistence-formats` (v0 through v4).

`pnpm run test:snapshot` replays 195 keyless cases across the session, sdk, acp, and web lanes with 2 skipped. Fourteen request-header comparisons went stale when the release's model-visible text landed (the `description`-before-`command` sentence, `todo_write`'s `tags` field, the `edit` parameter text), and `pnpm run test:snapshot:refresh` rewrote 14 expected files; every diff was reviewed and holds only those wording and schema changes.

`pnpm test` passes 47,859 cases with one expected fail and the two failures this host owns, both reproduced outside the branch's surface: `packages/util/http-proxy/tests/install.spec.ts`, whose `origin.test` lookup never resolves here (it fails alone as well), and `packages/api/workspace-files/tests/changes.spec.ts`, a real-local-watcher case that passes 43 of 43 when its file runs on its own. Three failures the first run reported are fixed in this sync: `scripts/ci-workflow.spec.ts` read an archived release workflow through the live path, and the `ui-trajectory` and `ui-document-studio` built-artifact specs mounted their plugin before the locale service existed.

`pnpm run hygiene` reports 17 of 17 gates passing, with `rescope-vendor --check` gaining the release's new `cordis` preset-id sites in its allowlist. `pnpm run duplication` reports 0 repository-wide clones and the 85 tightened-domain pairs matching `scripts/duplication-baseline.json`.
