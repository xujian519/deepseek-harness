# Agent Note: upstream v0.1.6-alpha.2 sync and the built-output shadow over sources

Status: implemented

English | [中文](2026-09-18-upstream-v0.1.6-alpha.2-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.1.6-alpha.1` to `dsh-v0.1.6-alpha.2`. Upstream advanced 887 commits while the fork carried 529 of its own, so the first merge attempt conflicted in 101 files. Upstream rewrote `apps/desktop` and `apps/desktop-host` (`runProfile` plus IPC plus a local port in place of the portless protocol and the `desktop.cordis.patch.yml` overlay), moved the `dsh plugin` forwarding into `@deepseek-ai/dsh-plugin-manager`, moved the `tool-present` package from the `fs` group to `deliverables`, replaced `ISessions.open` with `uiWorkspace.openSession`, and removed `SessionListState.current` in favour of the `retainedBy` map.

Two of this sync's failures came from the working tree rather than from a conflict. Eighteen unit files failed on the merged tree, and the whole client cluster among them traced to compiled JavaScript sitting beside its TypeScript source: `DEBUG=vite:resolve` showed `@deepseek-ai/dsh-client-ui-renderer/client` resolving to the compiled `index.js` in the renderer's `src/client/` directory, which then chained into that directory's `registry.js`, `scoped-slots.js`, and `app.js`.

## Decision

- **The desktop family takes upstream's rewrite and the fork re-ports its own capabilities.** Upstream's new `apps/desktop/scripts/electron-builder-config.mjs` factory replaces the fork's config, so the fork's brand-icon selection (`iconFile`, the `assets/` defaults, `DSH_DESKTOP_ICON_DIR` override), its unsigned-darwin build (`DSH_DESKTOP_UNSIGNED` for `darwin`, `dmg.sign: !unsigned`, `mac.identity: null`, `mac.notarize: false`), and its package-target relaxation (`--unsigned` for Windows and macOS targets, not `win-x64` alone) move into it. Upstream's mandatory-update policy then requires an HTTPS deployment origin, so the fork's icon and unsigned-macOS cases carry `DSH_DESKTOP_MANDATORY_UPDATE_TEST_ORIGIN` beside the other release inputs.
- **Built output beside a source shadows that source, and the shadow is silent.** 606 untracked `.js`, `.d.ts`, and `.map` files left over from an earlier build sat inside `packages/*/*/src/`. `tsconfig.base.json` maps a workspace name to a source **directory** (`./packages/client/ui-slots/src`), and Vite's default resolution tries `.js` before `.ts`, so every aliased import loaded an outdated compile of the module it named while the sources on disk stayed correct. Upstream tracks no such file — its `src/**/*.js` matches are hand-written `css-modules.d.ts` and `vite-env.d.ts` only — so removing the residue on exactly the paths `git status --porcelain -uall` reports as untracked build output is the whole repair. `pnpm run clean` does not own these files, and a `pnpm run build` on the current tree does not re-create them.
- **A version-alignment run precedes the release tool, which refuses a split family.** `scripts/release/bump.ts` verifies that the family shares one version before it plans anything, and the merge left 38 fork packages at `0.1.6-alpha.1` beside upstream's `0.1.6-alpha.2`, so the tool could not run at all. The alignment is therefore the 38 manifests, the one version mirror (`SIDEBAR_SERVICE_VERSION`), and `pnpm install --lockfile-only`.
- **A retired package's directory survives its deletion as build residue.** The `tool-present` move from the `fs` group to `deliverables` left `lib/` and `node_modules/` under the old path, and `check-workspace-constraints` rejects any `packages/<group>/<pkg>` directory without a `package.json`. `pnpm run clean` removes that residue; the whole package tree is otherwise upstream's.
- **A fork capability that upstream's own test file does not know about keeps its assertion.** `ui-conversation`'s inject face carries the fork's `releaseViewSetter` beside upstream's keys, and the merge had taken upstream's three-key expectation while keeping the fork's four-key face. The fork's assertion returns, so the capability and its coverage stay together; the alternative is deleting a live fork behaviour to satisfy a test written before it existed.
- **A component the fork replaced keeps the fork's spec.** `ui-trajectory` is the fork's modular redesign of upstream's single large table (`TrajectoryRow` and its siblings live in twelve fork-only modules upstream does not have), and upstream's spec for the same file asserts a different design — aggregated preview galleries against per-attachment rows, and image galleries foreign to the raw view. The fork's own spec therefore returns and the two ports that had aligned the fork's rendering with upstream's assertions — the compact thinking variant and the per-attachment list — are reverted with it.
- **The upstream test that follows the fork's own test file stays upstream's, with the fork's fixture migrated.** Everything the fork's client packages gained from `retainedBy` needs a fixture that carries the map, so `ui-todo-board`, `ui-patent-teams`, `synapse`, and `ui-document-studio` fixtures mark their current session with `retainedBy: { mainView: 1 }` and provide a `uiWorkspace` stub in place of the removed `sessions.open`, and `SessionListFace` loses `current`.
- **A style contract that compares one rule against another tracks the top-level rule.** `ui-sidebar`'s promoted workbench entry must mirror `.newSession` declaration for declaration, and the assertion that the rail override wins the tie now anchors its search at a line start: upstream's Windows titlebar rules carry the same `.collapsed .newSession` prefix earlier in the sheet and matched a bare `indexOf`.
- **Two documentation ceilings rise with the fork's content rather than the fork's text shrinking.** `docs/architecture.md` documents the fork's desktop-host composition and the `dsh-host-synapse` row pair, and `packages/README.md` documents the fork's package groups; both stand at 23 and 14 words over their ceilings, so the manifest moves to 2440 and 1080 rather than dropping fork-only facts.
- **The fork's pnpm failure hints return on upstream's forwarder.** Upstream's `apps/cli/src/plugin.ts` now delegates to `@deepseek-ai/dsh-plugin-manager/operations` and prints its own hint from the shape of the forwarded argument, advising `allowBuilds` in `pnpm-workspace.yaml` — the advice the fork's `2026-09-02-pnpm-plugin-failure-hint-config-homes` note measured as misdirecting on pnpm 10.34, and the trigger that note rejected as well. The fork's `pnpmFailureHints(stderr, dir)` classification and its test return on top of upstream's forwarder, which supplies the stderr text the hints read.
- **The documentation gates' remaining failures are the sync's own debris.** Two relative links pointed at paths this merge removed or moved (the disabled Python release workflow and the deleted desktop composition patch), the archived `desktop-without-workspace-sidebar` triplet was unsealed, `packages/document` had a stale subsystem-page exemption, and the persistence-format reference set needed a `--write`.

## Consequences

The fork ships upstream's v0.1.6-alpha.2 baseline with its desktop, patent, synapse, plugin-market, self-evolve, document-studio, patent-teams, and todo-board surfaces intact, and the client test lane is green again. The residue trap is the part worth carrying forward: a fork worktree can hold build output from an earlier checkout beside the sources, and because the workspace aliases point at directories, a mixed tree hands a resolver two candidates for the same module with no diagnostic beyond a confusing assertion. The next sync should check for it before blaming a merge, because removing the files is cheap and a wrong diagnosis is not. The aligned fork versions mean `scripts/release/bump.ts` runs again, and the desktop re-ports mean the fork's unsigned-darwin packaging path keeps its own tests.

## Alternatives considered

- **Adopt upstream's `TrajectoryTable` and its spec, and retire the fork's twelve modules.** Rejected: upstream's table is a single 3511-line file with no importer for the fork's `RecordInspector`, `TrajectoryRow`, `trajectory-record-model`, `trajectory-detail-tabs`, or `trajectory-resize-handle`, so adopting it deletes a fork UI rather than syncing one, and the fork's inspector is what its desktop and workbench surfaces mount.
- **Keep upstream's assertions and finish the port instead of restoring the fork's spec.** Rejected on the same evidence: satisfying both would mean removing the raw view's per-block image galleries, which the fork's own spec asserts, so the two specs describe two designs and only one can hold for one component.
- **Revert the six client fixtures by restoring each spec file from `master`.** Rejected: every one of those files also carries upstream changes from this release, so a wholesale restore would drop upstream's coverage along with the fixture drift; the fixtures move one field at a time instead.
- **Raise the unit-test timeout for `packages/util/http-proxy` and the `browser-use-runtime` case that timed out under load.** Rejected: the same two cases fail or pass on a pristine `dsh-v0.1.6-alpha.2` worktree in this environment, so the signal is the host's DNS latency and the suite's parallel load, not the merge, and a local timeout change would hide a real regression later.

## Testing

`pnpm run test` passes 1948 files with two environment-bound exceptions verified against a pristine upstream worktree; `pnpm run test:coverage` owns the per-file gate in CI. `pnpm run typecheck` (both faces), `pnpm run lint` (0 warnings, 0 errors over 5171 files), `pnpm run duplication` (0 clones), `pnpm run hygiene` (16 gates), and `pnpm run doc-sync` (43 gates, including the corpus-wide pairing check over 1264 pairs) all pass, and `pnpm run verify-translation-pairing` re-recorded every pair this sync touched.
