# Agent Note：上游 v0.2.0-rc.1 同步

Status: implemented

[English](2026-09-29-upstream-v0.2.0-rc.1-sync.md) | 中文

## Problem

本 fork 从上游的 `dsh-v0.1.7-rc.2` tag 前进到 `dsh-v0.2.0-rc.1` 发布，上游领先 261 个提交、涉及 1109 个文件。上一次同步让历史保持连通——`git merge-base HEAD dsh-v0.1.7-rc.2` 报出 rc.2 提交——因此本次发布的合成只报出 50 个冲突（49 个内容冲突与 1 个 modify/delete），而不再重新推导此前的发布。

上游本次发布改动了三处由本 fork 塑造过的面。遥测栈成为 Cordis 服务：新增 `packages/telemetry/otel` 提供方，以及 Host 侧与浏览器侧消费方 `host-product-telemetry-otel` 与 `client-product-analytics`，并带 `ui-settings-session-log` 开关，桌面壳现在经它上报产品分析事件。Schedule 行离开默认 Web 包，进入可选包 `dsh-experimental-schedule-bundle`，因此 `dsh-schedule`、`dsh-client-ui-schedule` 与 `dsh-time-context` 从 `packages/bundle/web-app` 中移除。`sandbox-windows-acl` 增加了一个以包根资产形式分发的诊断 skill，桌面构建器获得自己的 macOS entitlements plist，上游还把桌面键盘夹具合并进 client typecheck 程序并删除 `tsconfig.desktop-keyboard-tests.json`。

产品引导声明也由双方各自持有：上游为 0.2 重写了它，本 fork 以自有品牌分发同一份声明。

## Decision

- **版本、钉值与生成物随发布移动。** 46 份仅 fork 发布的 manifest 与 `SIDEBAR_SERVICE_VERSION` 一同对齐根版本 `0.2.0-rc.1`，使 `pnpm run constraints` 与发布族检查通过（364 个成员）；九份 `snapshots/acp/*/stdout.expected.jsonl` 钉值随之移动，因为 `agentInfo.version` 派生自 acp 自身的 manifest。全部生成器在已解析的树上运行（`gen-cordis-catalog`、`gen-config-catalog`、`gen-doc-graphs`、`gen-module-graph`、`gen-persistence-catalog`、`gen-tool-catalog`、`gen-plugin-packages`、`gen-dependency-catalog`、`gen-session-format-catalog`、`gen-client-catalog`、`gen-cordis-inspect-catalog`、`gen-scoped-events`、`gen-tsconfig-paths`），且 `pnpm run verify-no-unknown-casts --prune` 报出没有新增指向 `unknown` 的断言。
- **各 manifest 解析为两边的并集，上游新增的包按 fork 的排序放入。** `apps/cli` 补入 `dsh-experimental-schedule-bundle`；`packages/bundle/base` 补入 `dsh-otel`；`packages/bundle/web-app` 补入 `dsh-client-product-analytics`、`dsh-client-ui-settings-session-log` 与 `dsh-host-product-telemetry-otel`；`packages/client/ui-chat`、`packages/api/remotes`、`apps/desktop` 与 `python/sdk-runtime` 补入同样的分析与遥测依赖。web-app 包保留上游对三处 schedule 行的删除，base 包保留 fork 早先对 `dsh-tool-call-timeout-policy` 的删除。
- **桌面壳保留 fork 的 unsigned-darwin mac 块，并吸收上游相邻的新增。** `signIgnore`、随包归档的 Office 引擎条目、`notarize: !unsigned` 与托盘接线保持为 fork 的；`macos-entitlements.plist` 路径、`DSH_CLIENT_VERSION`、分析 `track` 调用与 `desktopClientVersion()` import 落地。`apps/desktop/scripts/electron-builder-config.mjs` 解析为 fork 的 mac 块加上游的 entitlements 条目，`apps/desktop/tests/main-startup.spec.ts` 在保留 fork 的 bridge 路径断言的同时加入上游的 client 版本与分析断言。
- **删除 `tsconfig.desktop-keyboard-tests.json`，并让 `apps/desktop/src/print.ts` 加入 client 程序。** 上游在把键盘夹具并入 `tsconfig.client.json` 时删除了这份仅 fork 有的工程，但 fork 的 `apps/desktop/src/ipc.ts` import `print.ts`，而合并后的 include 列表遗漏了它，因此 `print.ts` 加入该列表（仍在该夹具注释之下）。
- **client 程序现在携带 Electron 的全局 DOM 增强，fork 的 better-sidebar chunk-loader spec 相应地为 mock 标注类型。** 并入的桌面源码 import `electron`，其声明会增强 `Document`；因此 `packages/client/better-sidebar/tests/cov-views-chunk-loader-script.client.spec.ts` 抽出一个 `captureCreatedElements()` 辅助函数，把替换实现转型为它所替换的工厂，而不再传入朴素的 `(tag: string)` 实现。
- **引导声明采用上游的 0.2 预览文案，并按 fork 品牌替换。** `packages/client/ui-settings-models/src/client/locales.ts`、其 spec、`apps/web/tests/scaffold.ts` 与 `apps/web/tests/expected/onboarding-deepseek-config/welcome.expected.md` 携带「Preview Notice」文案，其中 `DeepSeek Harness` 替换为 `DSH Patent`，与 fork 已分发的 0.1 文案一致，`WELCOME_NOTICE_VERSION` 移到 `2026-09-28.1`。
- **四处代码冲突解析为并集。** `packages/sandbox/sandbox-local/src/index.ts` 保留 fork 受校验的 `probeTimeoutMs` 标签并吸收上游的 Windows ACL 诊断 skill 注册；`packages/api/remotes/src/client/index.ts` 在 fork 的 `pluginMarketRemote` 旁加入 `productAnalyticsRemote`；`scripts/check-workspace-constraints.ts` 在 fork 的 `methodology` 条目旁为 `sandbox-windows-acl` 取 `assets`；`apps/desktop/src/main.ts` 同时传入 `DSH_DESKTOP_BRIDGE_PATH` 与 `DSH_CLIENT_VERSION`。
- **生成页重新生成，而生成器不写的中文页手工镜像。** `docs/capability-seams.zh.md` 补入 `ctx.productAnalytics` 与 `ctx.otel` 服务行及 `pkg_otel` 图边（英文页由 `gen-doc-graphs` 写出）；`packages/client/README.md` 及其中文页补入 `product-analytics/` 行；`packages/README.md` 及其中文页删去摘要中重复的分组 README 从句，以便在新增 `telemetry/` 分组行后仍处于 1080 词上限之内。
- **上游新增的 SDK `tool-scheduler-recovery` 场景按 fork 的调度器键取值。** 上游的录制按 symbol 描述定位工具调度器；fork 把 `TOOL_RUNTIME_SCHEDULER` 携带为命名空间字符串 `@deepseek-ai/dsh-tools:runtime-scheduler`，因此 `snapshots/sdk/tool-scheduler-recovery/scheduler-failure.mjs` 直接以该属性取值，而不再扫描 symbol 键。
- **配对记录重新记录，并有一篇上游新增 note 改指。** `pnpm run verify-translation-pairing --write --all` 重写了十份冲突的 `*.i18n.yaml` 记录；`.agents/notes/implemented/testing/2026-09-27-web-lane-assertions-name-their-input-state[.zh].md` 把其 CI 链接指向 `.github/workflows-disabled/ci.yml`，即本 fork 存放上游 `.github/workflows/` 位置下工作流的目录。

## Consequences

fork 携带上游 v0.2.0-rc.1 基线出包，其 patent、desktop 与 better-sidebar 面保持完整，且历史保持连通：`git merge-base HEAD dsh-v0.2.0-rc.1` 即本次发布提交，因此下一次同步读到的是真实冲突集。fork 把 `dsh-writing-patterns` 面向模型的描述、桌面 mac 块与引导声明文案视为自有内容，因此每次触及它们的发布都会再次冲突。

`pnpm run doc-sync` 在本次同步时仍有两个门禁失败，两者都是既有问题，且恰在 fork 的 CI 所跑门禁之外（`doc-quick` 不含这两项）：`verify-package-paths` 报出对 `approval.ts` 与 `quality-gate.ts` 两个模块的陈旧引用——2026-09-27 的扫描修复删除这两个文件时未更新引用它们的三个文档；文档站点构建在 `docs/tool-catalog.md` 上失败——其 fork 自有的 patent 工具描述包含裸 `<writing_skills>` 与 `<g>` 文本，Vue 把它们读作未闭合元素。站点构建的输入与合并前的树逐字节一致，因此两者都不是本次同步造成的。两者已于 2026-10-01 清除：笔记已改指当前树，那两处描述也把这两个词包进了行内代码。

## Alternatives considered

- **经中间 tag 分阶段合成本次发布。** 不需要：merge base 已落在上一次同步的 tag 上，因此单次合成报出的正是两个发布真正共享的 50 个冲突。
- **保留 fork 单独的桌面键盘 tsconfig。** 已否决：上游在同一提交中弃用了该工程并把其文件并入 client 程序，而保留一份 `files` 列表与 client include 列表重复的工程，等于让同一份清单有两个来源。
- **在本次 PR 内修复既有的 package-path 与站点构建失败。** 已否决：它们早于本次合成，且站点构建的修复会改写本次同步本不触及的、面向模型的工具描述。
- **抬高 `packages/README.md` 的词数上限而不做删减。** 已否决：该摘要只是重述了前一句已给出的事实，因此所需 telemetry 行以重写位置而非抬高预算的方式纳入。
- **把上游的 `bundle/web-app` schedule 行取回。** 已否决：上游把那些包移入可选包，而 fork 自身的 Schedule 面保留其包，因此该删除是本次发布的组装决定。

## Testing

`pnpm run typecheck` 覆盖两个编译面并以 0 退出，`pnpm run lint` 以 0 退出，`pnpm run build` 的 host 与 client 打包均成功，`pnpm run constraints` 在 46 份仅 fork 发布的 manifest 处于根版本时通过。`pnpm exec tsx scripts/release/verify.ts --family dsh` 在 `0.2.0-rc.1` 解析出 364 个成员且发布顺序已解析。`pnpm exec vitest run` 覆盖已解析的各面——`apps/desktop/tests`、`packages/client/ui-settings-models`、`packages/client/better-sidebar`、`packages/llm/llm-deepseek`、`packages/sandbox/sandbox-local`、`packages/api/remotes`、`packages/experimental/webworker-runtime`、`packages/extensions/tool-cordis`——通过 244 个文件、4054 个用例。`pnpm run doc-sync` 报 47 个门禁中 45 个通过，两个失败即上述既有问题；`pnpm run verify-translation-pairing` 接受全部配对，`pnpm run verify-type-equiv` 保持 1:1 块配对。`pnpm run test:snapshot` 在 sdk、session 与 acp 通道无密钥回放 191 个用例，2 个跳过。完整的 `pnpm test` 通过 46,483 个用例，四个失败不属于本次改动：三个观测与文件监视用例在把四个文件一起重跑时通过，以及 `packages/util/http-proxy/tests/install.spec.ts`——本主机上 `origin.test` 的解析始终不返回（本次合成只改动了该包的版本行）。`git merge-base HEAD dsh-v0.2.0-rc.1` 报出本次发布提交。
