## 3. 发现

每条给出 issue 号与该 issue 正文内的复现命令；本节只给判定要点。

### 3.1 行为与声明不符（3 条）

- **#312 专利输出级门禁从未接线**：`PatentOutputGate`（`patent-workflow/src/output-gate.ts`，373 行）与 `processPatentOutput`（`quality-gate.ts:415`）除测试外零调用点；而 `patent-rule/src/runtime/patent-compliance.ts:236` 的 `selectGateRules()` 以「已由关键词门禁处理」为由排除 `PAT-RISK-001`/`PAT-APPROVAL-001`/`PAT-ABS-001`。两条链互相引用对方的覆盖，其中一条不存在。preset persona 的「输出前强制质量门禁与免责声明」在代码上不成立。
- **#314 文档模式占位符文法两套**：渲染侧 `doc-template/src/vars.ts:24` 用 ASCII `\w`，门禁侧 `document-deliver/src/checks.ts:84` 用 `[^{}\n]{1,80}`。实测 `{{机构名称}}` / `{{doc-no}}` 的 `residual` 为空、`gateHits` 命中——模型按技能指示「清空 residul 再交付」仍会被门禁打回；且这两个形式**既不被变量替换也不被报告**。
- **#319 免责声明映射缺一类**：`doc-style/src/types.ts:36-41` 的 `DISCLAIMER_CATEGORY_KEYS` 无 `patent-report`，而 5 个模板（`claims-spec`、`invalidation-opinion`、`oa-response-sati`、`patentability-opinion`、`search-report`）的 `category` 正是它，于是撰写稿拿到「本分析…不构成正式法律意见」而非「本文书…需经专利代理人审阅」。

### 3.2 门禁与记录的盲区（6 条）

- **#315 `ui-document-studio` 豁免理由失效**：注释称「bundle-spec 无法映射 eval 产物」，实际 5 个 jsdom spec 直接 import 全部 6 个 src 文件；真实缺口是分支覆盖（见 §1 数字）。豁免仍需要，理由与跟踪方式都需要改。
- **#316 覆盖率豁免注释的复现命令不可复现**：注释称 `--coverage.include='packages/patent/*/src/**/*.ts'` 是被豁免包被插桩的原因；实测该 include **不覆盖** `coverage.exclude`（writing-patterns 产出 0 条目）。改为覆盖 `exclude` 才得到条目，且文件数已由 102/77/19/15/9/7 漂到 107/78/20/16/9/8（百分比仍成立）。
- **#321 preset 技能引用了未注册的工具名**：`ask_user` 19 处 / 15 个文件（注册名是 `ask_user_question`，`interaction/tool-ask-user/src/index.ts:20`，无别名机制），`document-word/SKILL.md:25` 的 `ls` 不存在（`tool-fs` 只有 read/write/edit/read_image）。`verify-skill-invocation-metadata` 只扫 `.agents/skills`，`verify-patent-team-roster` 是单点，随包 preset 技能正文无人校验。
- **#322 跨 preset 无一致性门禁**：6 个 preset 中出现在 2 个以上者 33 个 row id，其中 27 个块取值不同；`verify-agent-preset-config` 只判「单行与插件 schema 相符」，没有任何东西记录哪些差异是有意的。新模式要复制约 100 行。
- **#325 `verify-suppression-reasons` 不覆盖 `v8 ignore`**：1204 处 `v8 ignore (next|start)` 现状全部带理由，但门禁的 `DIRECTIVE` 只认 oxlint/eslint/`@ts-expect-error`——合规靠自觉，而它决定覆盖率门禁看见什么。
- **#326 四条通道在任何工作流都不执行**：`apps/web/tests/*.snapshot.ts`（4 个，组装式 Web 快照）、`check:ci:snapshot`、`check:ci:artifacts`（仅 `package.json` 定义）与两条手工 perf/stress 通道。进程级快照车道已在 09-26 接线，本条是它未覆盖的 Web 组装面。

### 3.3 可配置性与外部依赖（2 条）

- **#317 两个模式各有一处「从未审视」的预算**：`patent-data` 整包无 `Config`（`DEFAULT_COMMAND_NAME='ego-browser'`、90s/300s/500KB、`createEgoSession()` 无参），`document-deliver/src/checks.ts:79` 的 `MAX_FINDINGS_PER_CHECK = 5` 无理由文本。反证是同仓 `office-to-pdf` 的 19 个字段全部进 `Config`。
- **#313 专利模式写死仓外依赖**：`127.0.0.1:8100/:8001` 与 Neo4j `7687` 共 16 处分布在 persona、两份 preset README 与 3 个技能，`patent-data/src` 无 `Config`；三个仓外检索技能（`cnipr-search-download`/`cnipa-query`/`google-patents-search`）被 persona 列为主通道但未登记为前置条件；`docs/subsystems/patent.md:5` 的「no MCP bridge」与 `presets/patent.md:65` 描述的可挂 MCP 桥措辞矛盾。**注**：preset README 的 Prerequisites 已把 cnlaw 记为可选增强，本条经复核从「未登记」降级为「措辞与出口不一致」。
