# Agent Note: 上游 v0.1.2-rc.1 同步与 Host/Client 分面隔离

Status: implemented

[English](2026-09-04-upstream-v0.1.2-rc.1-sync.md) | 中文

## 问题

fork 在 v0.1.2-alpha.4 同步之后追踪上游；上游 master 前进到 `76fda72979`（发布为 `dsh-v0.1.2-rc.1`）。三项上游改动主导本次迁移：`SessionPersistence` 改为按会话句柄访问（以 `list`/`stat`/`open` 取代 `listSnapshots`/`inspect`）、`agentLoop.create` 变为异步、以及收紧的规则——每个客户端程序在自己分面编译，Host 聚合不得把 `packages/*/src/client` 拉进其程序。本次合并要带着 fork 独有包（patent、self-evolve、better-sidebar、synapse、plugin-market、patent-teams 仪表盘）跨过这些破坏。

## 决策

- **句柄式持久化。** fork 侧 `SessionPersistence` 消费者改走新句柄 API。Synapse 的 `listSnapshots()` 改为 `list()`，其两处 `inspect(id)` 改为 `open(id, 'read')` + `read()` + `close()`。
- **异步 `create`。** `agentLoop.create` 现在返回 `Promise<Agent>`；`tool-calls.spec.ts` 中唯一未 `await` 的调用补上了 `await`。
- **Host/Client 分面隔离。** rc.1 规则要求 Host 程序排除客户端源码。Host 聚合通过 `tsconfig.base.json` 的 `paths` 把每个 `@deepseek-ai/dsh-*` 包解析到源码，因此任何导入 `/client` 子路径的 Host 测试都会把整张客户端源码图（含 JSX/CSS）拖进无 JSX 的 Host 程序。新增 `tsconfig.base.host.json`，由 `tsconfig.base.json` 去除全部 `/client`→src 映射派生而来；`tsconfig.host.json` 改为继承它，Host 程序遂通过各包 `exports` 把 `/client` 解析到其构建产物 `lib/types` 声明而非客户端源码。`pnpm run typecheck` 重排为先跑客户端 `tsc`，使这些 `lib/types` 在 Host 构建消费前已存在。
- **`ui-patent-teams` 更严格类型。** rc.1 的 `exactOptionalPropertyTypes`、`readonly` 节点数组、`SessionId` 品牌类型撞上 fork 的 Teams 测试：共享的 `ConversationViewBuilder.replace`/`apply` 现要求传入 `timeline` 快照（fork 构建器接受并忽略之）；纯 DAG 测试改名为 `teams-dag.client.spec.ts`（客户端聚合）；裸横幅 fixture 省略 `description` 而不把它设为 `undefined`；`viewEntry.inject` 不再接收会话 id，fixture 改为无参调用；三个几何常量补了 JSDoc。
- **存储迁移与删除。** 上游把 `session-persistence` 的存储移入 `./storage.ts` 并删除 `coordinator.ts`；`docs/TECH_DEBT.md` 指向该已删除文件的条目随之移除。
- **平台/策略。** `.github/issue-management/policy.mjs` 采纳上游的 project-V2 快照；`pnpm-workspace.yaml` 保留 fork 的 node-pty 降级并新增上游的 `@yao-pkg/pkg` 补丁；`python/sdk-runtime/package.json` 依赖按 rc.1 包集重建。
- **生成面。** `api-catalog`、`config-catalog`、`persistence-catalog`、`event-producer-consumer`、`module-graph`、工具目录、模块图、`known-event-types` 均已再生；五个变更的双语文档对已和解并重录。

## 后果

fork 与上游共享 rc.1 的句柄式会话词汇与分面编译隔离，同时保持每个 fork 独有包对新 API 可编译。`pnpm run typecheck`（Host 与 Client）、`pnpm run doc-sync`（32 项门禁）、`pnpm run lint` 本地全绿。

## 落选方案

**让 Host 聚合继续拉取客户端源码，并给 Host 配置加 JSX/CSS 支持。** 拒绝：这会把 rc.1 刻意隔离的两个分面重新合并，恢复该拆分本要避免的 `Context` 交错合并。

**逐个改掉导入 `/client` 子路径的 Host 测试，而不是改解析。** 拒绝：`lib/types` 路线是一次解析层的改动，覆盖当前与今后所有 `/client` 导入；逐文件编辑需要为每个新导入重做，而且其中若干 Host 测试本身就是引用客户端类型的宿主行为测试。

## 测试

`pnpm run typecheck`（Host + Client 聚合）、`pnpm run doc-sync`（全部 32 项文档门禁）、`pnpm run lint` 在 macOS 本地通过。Linux lane 的 CI 是本次合并的平台级验证。
