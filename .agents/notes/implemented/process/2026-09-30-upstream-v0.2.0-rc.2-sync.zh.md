# Agent Note：上游 v0.2.0-rc.2 同步

Status: implemented

[English](2026-09-30-upstream-v0.2.0-rc.2-sync.md) | 中文

## Problem

本 fork 从上游的 `dsh-v0.2.0-rc.1` tag 前进到 `dsh-v0.2.0-rc.2` 发布：140 个提交（含合并 187 个）、涉及 1022 个文件。合并基点落在 rc.1 发布提交上，因此本次合并报出两个发布真正共享的 52 个冲突，而不再重新推导此前的发布。

上游本次发布改动了三处由本 fork 塑造过的面。打包的桌面壳获得内置 `dsh` 命令（`apps/desktop-host/src/cli.ts`、`scripts/prepare-cli.ts`）：插件命令现在经该安装的 pnpm 针对保留的 Electron profile 运行；macOS 与 Linux 的图形界面启动在第一个 Host 启动前读取账户登录 shell 的环境；桌面 README 随之新增这两节。Client 侧的 Cordis inspect 查询变为有界（按配置超时，并保留首个失败诊断，另有离线快速路径），并新增 `cordis-inspect-liveness` 与 `cordis-inspect-timeout` 两个会话快照。`ask_user_question` 获得 timed 模式，其迟到回答以限定的 `user-question-reply` 消息来源到达，由持久化记录 `2026-09-21-user-question-reply` 确认。到期的 Schedule 提醒变为计划用户消息；升级指南目录随其 skill 与 `verify-upgrade-guides` 门禁一并落地。

本 fork 持有 Electron 运行时 profile 目录（`profiles/desktop-runtime`）、`@deepseek-ai/cordis/...` 事件名、`dsh-timeout-guard` 包名，以及 patent、self-evolve、desktop、better-sidebar 与 plugin-market 诸面。

## Decision

- **版本、钉值与生成物随发布移动。** 46 份仅 fork 发布的 manifest 与 `SIDEBAR_SERVICE_VERSION` 一同对齐根版本 `0.2.0-rc.2`；九份 `snapshots/acp/*/stdout.expected.jsonl` 钉值随之移动，因为 `agentInfo.version` 派生自 acp 自身的 manifest。全部生成器在已解析的树上运行（`gen-tsconfig-paths`、`gen-cordis-catalog`、`gen-client-catalog`、`gen-cordis-inspect-catalog`、`gen-tool-catalog`、`gen-config-catalog`、`gen-persistence-catalog`、`gen-doc-graphs`、`gen-module-graph`、`gen-plugin-packages`、`gen-dependency-catalog`、`gen-session-format-catalog`），且 `pnpm run verify-no-unknown-casts --prune` 退役了十条过期基线条目。
- **内置桌面命令以本仓库自己的名字管理 Electron profile。** 上游为名为 `desktop` 的 profile 放行插件命令。本 fork 的 Electron profile 目录是 `profiles/desktop-runtime`，因此 `apps/cli/src/args.ts` 导出 `ELECTRON_PROFILE_NAMES`（`desktop` 与 `desktop-runtime`）与 `isElectronProfile`，解析器规范化这两个名字，`plugin.ts` 以该判定进入保留 profile 分支：同一套初始化守卫、共享 profile 写锁与内置 pnpm 现在作用于 Electron 壳真正持有的目录。`apps/desktop/README.md` 与 `apps/cli/README.md` 写明内置命令所到达的 profile。
- **桌面壳保留 fork 的 mac 块，并吸收上游相邻的新增。** unsigned-darwin 守卫、随包归档的 Office 引擎条目与托盘接线保持为 fork 的；`signMacOSRuntime` 新增的 `target.arch` 参数、`desktopTargetPlatform(targetName).arch`、登录 shell 环境（`hostEnvironment`、`prepareHostEnvironment`）与 `DSH_DESKTOP_BRIDGE_PATH` 在 `prepare-dsh.ts` 与 `main.ts` 中同行落地。
- **fork 的事件重命名贯通到上游新增的夹具。** 上游新写的 `cordis-inspect-liveness` 与 `cordis-inspect-timeout` 夹具订阅 `cordis/inspect-query` 与 `cordis/inspect-query-resolved`；两者现在改用运行器实际发出的 `@deepseek-ai/cordis/...` 名称，新增的 `tests/inspect-registry.spec.ts` 亦然。否则夹具永不回应，场景持续偏离直至回放脚本耗尽。
- **持久化历史跨同步连成一条链。** 上游的 `2026-09-21-user-question-reply` 与 fork 的 `2026-09-22-fork-source-attribution` 都确认同样的四个根，历史校验器将其判为分叉。fork 的记录现在声明上游的记录为其前驱，并用 `persistence-changes --update` 从合并后的树重新推导；合并后的 schema 同时带有 `user-question-reply` 与 fork 的三个归因类型，因此每段转换都保持同版本。
- **两个手写的压缩快照被重新标定。** 它们的触发点落在某段历史与其压缩替代之间，而上游更长的 `bash`、`pwsh` 与 `ask_user_question` 描述抬高了估算上下文。其模型 `contextWindow` 从 8,382 移到 8,520，夹具中记录的 `request/context` 事实与两处说明注释随之更新。
- **Host 类型检查预算随本 fork 自己的树上升。** 上游给 Host 程序 4 GB，本 fork 更大的程序已经装不下：合并后的树上冷启动 `tsc -b tsconfig.host.json` 会在 mark-compact 阶段以 `Ineffective mark-compacts near heap limit` 中止，而合并前的提交 `f2b2c524cc` 能完成；合并后的树在 4,608 MB 下完成。`build:lib:host` 与 Wine 的 Host 编译现按 6,144 MB 运行，`scripts/ci-workflow.spec.ts` 在它所钉住的 Wine 命令里记录该预算。Client 程序仍处于 Node 默认上限之内，未作改动。
- **其余冲突按并集解析。** `scripts/check-workspace-constraints.ts` 在 fork 的 `config/desktop.cordis.patch.yml` 旁加入 `lib/cli.js`；`scripts/run-gates.ts` 保留 fork 的模式集（无 `ci-snapshot`/`ci-artifacts`）并采纳 `ci-unit`，fork 的 spec 现以它取代已删除的 `ci-artifacts` 条目；`packages/client/ui-tool/package.json` 在 fork 的依赖表中加入 `dsh-user-questions`；`packages/interaction/user-questions/src/index.ts` 在保留 fork 共享的 `isRecord` import 的同时加入上游 timed-wait 的 import；`packages/client/ui-commands/src/client/popup.ts` 保留 fork 的 `errorMessage` import 并加入上游的搜索辅助 import；`packages/extensions/cordis-host-runner/src/{index,inspect-registry}.ts` 保留 `assertResolvedConfig` 与命名空间化事件，同时采纳上游的超时管线；`packages/client/ui-theme/tests/expected/radius-exceptions.expected.json` 加入上游的 `ui-deliverables` 行。
- **生成的页面重新生成，无生成器写出的中文页与其英文侧同步更新。** `docs/tool-catalog.zh.md` 接收上游对四处工具描述的改动；desktop、CLI、better-sidebar 与 tool-ask-user 各页承接上游新增内容；`pnpm run verify-translation-pairing --write --all` 重录变更过的配对，`verify-persistence-formats --write` 刷新格式索引。

## Consequences

本 fork 在保留 patent、desktop、self-evolve 与 better-sidebar 诸面的同时交付上游 v0.2.0-rc.2 基线，且历史保持连通：`git merge-base HEAD dsh-v0.2.0-rc.2` 即发布提交，因此下一次同步读到的是真实冲突集。此后每次发布有三处偏离需要处理：CLI 保留本 fork 的 Electron profile 名，而上游的桌面说明并不知道它；Host 类型检查预算是 6,144 MB，而上游的根脚本与 Wine 门禁写的是 4 GB；两个手写压缩快照会在任何面向模型的工具描述改变长度时重新标定。

`pnpm run doc-sync` 报告 46 个门禁通过，以及 rc.1 同步已记录的两处失败：`verify-package-paths` 仍在三份 Agent Note 与 `docs/patent-workbench-tasks.md` 中找到指向已删除的 `packages/patent/patent-workflow/src/approval.ts` 与 `quality-gate.ts` 的过期引用；`docs:build` 仍无法编译生成的 `tool-catalog.md`，因为 fork 自有的 patent 工具描述带有 Vue 会当作元素的裸 `<writing_skills>` 文本。两者都不是本次同步引入的。

## Alternatives considered

- **在 `resolveProfileDir` 内把保留名 `desktop` 映射到 fork 的目录。** 否决：那会改动所有 profile 名都要经过的 app-boot 公共解析函数，而新增一个名字既保留上游的保留名，也不动它的说明。
- **让内置命令的文档仍写 `--profile desktop`。** 否决：该路径在本仓库既不由 Electron 壳初始化，也没有任何 CLI profile 使用它，照文档操作会得到初始化错误。
- **删除上游的 `2026-09-21-user-question-reply` 记录而不串链。** 否决：该记录记载了上游已交付的转换，而历史校验器接受这条链，两份确认因此都得以保留。
- **重录制压缩场景而不是重新标定。** 否决：录制器按设计跳过手写夹具，且 fork 此前那次标定提交走的也是调整 context window 的路子。
- **只在 fork 的 CI 工作流内抬高上限。** 否决：`build:lib:host` 在命令行上直接传 `--max-old-space-size`，它优先于 `NODE_OPTIONS`，因此该车道必须放弃运行那条成文的构建命令才能拿到更大的堆。
- **保留上游的 `ci-artifacts` 模式以使它的 spec 条目原样编译。** 否决：没有任何 fork 工作流调用该聚合，fork 是连同它的 `check:ci:*` 脚本一起有意删除的。
