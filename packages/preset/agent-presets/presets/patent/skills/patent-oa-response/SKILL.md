# 审查意见答复

对审查意见通知书逐条答复，产出意见陈述书与（必要时）修改后的权利要求书。

## 必查清单（先查再分析）

- 先定答复期限：用 patent_deadlines 取本次答复期限——给出 patentType、filingDate、claimsPriority，并把收到的通知书放进 notices（如 {kind: 'office-action-first', dispatchDate: '…'}）；期限的月数与起算口径由该工具按现行细则与指南给出，不要自行写死月数或口算，也不要因为材料里没写送达日就按申请日估算。
- 用 patent_workflow_run（manifestId=patent_oa_response_v1；input=通知书正文，claims=权利要求书，chartTargets 传审查员引用文献）跑解析与撰写：parse 阶段为确定性解析，claim-chart 阶段（mode=oa-response）把这些引用文献逐要素映射到权利要求，draft 阶段同时读到解析结果与对照表。人工确认门会暂停运行，放行时重新调用并带上 approveStageIds。
- 只做解析时用 parse_office_action（text=通知书正文）：返回驳回类型（按首现位置排序去重）、引用文献与相关性类别、涉及权项、审查员论点。未标注相关性类别的文献不推断类别；涉及权项是同句共现、不是审查员的权威对应，须人工核对；解析不判定理由是否成立。
- 用 patent_wiki_search / patent_case_search 取对应驳回类型的审查标准与在先答复案例；法条、指南、判例的原文按纪律核验后引用，不凭记忆写条号。

## 答复流程

1. 定主策略：按解析出的驳回类型（充分公开 / 不清楚或不支持 / 新颖性 / 创造性 / 修改超范围 / 形式缺陷）确定主策略；多种类型并存时以最核心的驳回理由为主。解析器未命中具体条款时（`未识别条款`）不替文书定条款，按正文人工归类后再答复；正文出现解析器不单列类型的理由（如实用性 22.4、不授权客体 25 条）时同样按正文归类。
2. 答复方向四选一并写明理由：①纯争辩（不修改）——事实认定有误、结合无技术启示、区别特征认定错误；②修改+争辩——将从属特征并入独权即可克服；③混合策略——重写权利要求（增补区别特征/重新划界）并争辩剩余争议；④放弃答复——缺陷无法克服（如公开不充分涉及全部实施例）时须向当事人明示。
3. 逐条答复每一项被驳权利要求；引用对比文件的具体段落指出区别；修改后列出权利要求全文，且不得超出原说明书与权利要求书记载的范围（A33）。
4. 创造性争辩走三步法：锁定最接近现有技术 → 逐条列出区别特征并按客观作用确定实际解决的技术问题（不得包含区别特征自身的指引）→ 反驳结合启示与公知常识认定，强调预料不到的技术效果。
5. 输出小节按序：驳回类型 → 答复策略 → 逐条答复 → 修改对照（如有）→ 结论。

## 约束

禁止编造实验数据；禁止无逻辑链的空泛断言；凡引用法条/指南/判例须带来源（含 source_path），拿不出来源就删除该断言。

## 输出

意见陈述书 + 修改对照表（逐权项列修改前/修改后/修改依据）；正式交付按 patent-document-polish 走模板渲染。

## 质量门禁与人工确认

答复策略、修改范围与是否放弃答复先 ask_user 确认再起草；结论附免责声明；交付前经 patent-quality-gate。
