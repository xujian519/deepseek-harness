# 专利文档输出规范

把已定稿内容（各成员/角色的分析结论、起草稿）转化为**符合场景的正式交付文档**。只做文本组织、矫正与美化；**不改变实体结论**（权利要求布局、无效理由组合、诉请金额等判断仍归对应角色与 HITL）。

## 场景 → 模板映射

正式文书一律优先用 `render_patent_document` 的场景模板渲染；无对应模板的简单函件走 md 起草 + docx/HTML 公文式输出。

| 场景 | 模板 id | 说明 |
|---|---|---|
| 立案 / 可专利性初判 | `patentability-opinion` | 可专利性分析意见书 |
| 检索 | `search-report` | 检索报告 |
| 撰写 | `claims-spec` | 权利要求书 + 说明书 + 摘要 |
| 答复审查意见 | `oa-response` | 意见陈述书 + 修改对照 |
| 补正 | `rectification-response` | 补正书（对补正通知书答复 + 替换页清单） |
| 复审 | `re-examination-request` | 复审请求书 |
| 无效 | `invalidation-opinion` | 无效宣告请求书 / 无效意见 |
| 侵权比对 | `infringement-opinion` | 侵权比对意见书 |
| 诉讼文书 | `litigation-pleading` | 起诉状 / 答辩状 |

## 矫正清单（输出前逐项检查）

1. **术语一致**：技术特征、部件名、参数名与权利要求书/对比文件/分析稿完全一致，同义改写但不得引入新概念。
2. **法条引用**：格式统一为「专利法第 X 条第 Y 款」「专利法实施细则第 X 条」，引用处可见出处（工具/本地基线/审查指南），正文与证据附录一致。
3. **数字与日期**：期限、日期、费用以工具计算结果为准（禁止心算）；日期统一 ISO（YYYY-MM-DD）；金额单位一致。
4. **编号层级**：章节用 1. / 1.1 / 1.1.1；条款、理由、证据编号连续无跳号；交叉引用（「如权利要求 X 所述」「前述第 X 项理由」）指向正确。
5. **称谓与落款**：文书中当事人、代理人、合议组/裁判称谓与场景立场一致（无效请求人/专利权人、原告/被告）；落款、日期、文号齐全；正式版去除内部标记（密级、草稿水印）。
6. **无模板味**：删除空话套话、重复结论、无出处断言；每条实体结论保留来源类型与 pin-cite。

## 美化清单

1. **选对模板**：按上表映射选择，模板 slot 逐项填充；缺输入即打回补证，禁止留空渲染。
2. **渲染**：`render_patent_document` 传 `template`、`outputName`（`<caseId>-<场景>_v<版本>`）、`caseId` 使产物落 `data/cases/<caseId>/outputs/`；有事务所品牌时传 `brand` / `brandPath`。
3. **版式**：遵循模板品牌契约（A4、`16mm 18mm 18mm 18mm` 边距、`--sati-doc-*` 变量、语义徽章色）；结论/风险用语义色徽章而非装饰。
4. **docx 交付**（officecli / docx 能力可用时）：由渲染/定稿 md 转换而来，修订以 tracked changes 呈现，输入原件未被改动；否则交付 html/pdf + md 定稿。
5. **失败降级**：PDF 失败时 HTML 已存在即算渲染成功，如实报告 `pdfError`。

## 交付流程与 HITL

1. 收齐定稿内容与输入（来源、对比文件路径、法条出处、数字计算依据）。
2. 按场景选模板 → md 定稿（矫正清单 6 项）→ 渲染（美化清单 5 项）→ 产物与交付摘要。
3. 交付放行确认与 `patent-quality-gate` 的收口 ask_user **合并为一次**：向用户展示产物路径、矫正要点、渲染结果（含 PDF 失败项），用户确认后才交付；不重复打扰。
4. 产物登记：`_matter-log.md` 追加交付记录（时间/动作=交付/产物路径/审批人=用户），文件头保留来源与版本元数据（见 patent-matter 审计链）。

## 边界

- 不参与实体判断：权利要求布局、无效理由组合、争辩策略、诉请金额均由对应角色决策并过 HITL，文档专员只整理、矫正、美化。
- 对抗场景中，双方文书各行其是；文档专员对同一份定稿做文体整理，不评判立场对错。
- 单会话（未建团队）同样适用本规范：输出正式文档前走一遍矫正清单与渲染。
