# Agent Note: upstream v0.1.2-alpha.4 sync and the continuable-subagent rebase

Status: implemented

English | [中文](2026-09-02-upstream-v0.1.2-alpha.4-sync.zh.md)

## Problem

The fork tracked upstream `dd6322d604` (v0.1.2-alpha.3) with 283 fork commits on top. Upstream master moved to `4e84901e64` (v0.1.2-alpha.4): 297 commits, ~2,400 files, dominated by the experimental `code-runtime-python` backend, the breaking `refactor(session)!: distinguish event seqs from log offsets`, web fetch enabled by default across sdk/headless/base, and Web UI performance work. The merge had to carry fork-only packages (patent, self-evolve, better-sidebar, synapse, plugin-market) across upstream's session API break and upstream's deletion of the invariant-companion layer.

## Decision

This merge is the fork-regular `sync/upstream-v0.1.2-alpha.4` integration. The dispositions:

- **Session API break.** `session.events` is gone; fork consumers now read `session.snapshotEvents()`, and cold/resume lineage reads `session.inheritedEventCount` / `header.isSeeded` instead of `header.seedLength`. Synapse's persisted thread bookkeeping keeps its own `seedLength` field and fills it from the durable `session/end-seed` marker (`sessionLiveStart`) when restoring, because the restored header no longer carries the length.
- **Continuable subagents.** Upstream made continuable children first-class (`startContinuable`, `sendMessage`) and removed both `SubagentRuntime.followup` and `registerContinuableSetup`; the provider contract states the manager owns composition and "a provider never sees the child's Agent". Patent-teams therefore dropped its member-selection bridge (`installMemberSelectionRuntime`/`withPending`/`MemberSelectionRuntime`): the member's provider/model now rides the creation request's `agentOptions` and is seeded into the durable descriptor, which covers both fresh composition and cold resume. `deliverToMember` and the retired-member guard moved to `sendMessage`.
- **Invariant-companion layer.** Upstream deleted most `src/invariant.ts` companions and their mappings. The merge adopts the deletions, including `guard/timeout-guard`'s orphaned companion (closing the alpha.1 sync note's follow-up 4). Fork-only packages keep theirs; the generated alias region was regenerated (`gen-tsconfig-paths`) and the fork-only non-derivable package aliases stay hand-written in `tsconfig.base.json`.
- **Generated surfaces.** `docs/persistence-catalog` regenerated from source; the tool-name roster, `api-catalog`, and `slot-catalog` taken from their generators; translation pairs re-recorded after owner resolution.

## Consequences

The fork shares upstream's seq/log-offset session vocabulary, descriptor-seeded continuable children, and experimental Python backend while keeping every fork-owned package compiling against the new APIs. The member model route is now enforced by the durable descriptor alone; the retired-member guard still blocks direct `sendMessage` cold-resumes of retired members. `pnpm-lock.yaml` was regenerated after dropping the deleted `dsh-tool-subagent-report` from the examples manifest.

## Alternatives considered

**Keep a fork-side continuable-setup hook by patching the subagent runtime.** Rejected: upstream declares provider invisibility of the child's Agent a contract, so a patch would fight every future upstream change; the descriptor now carries exactly the routing state the hook used to install.

**Re-derive member routing at cold resume from the team record instead of the descriptor.** Rejected: it would let the team record and the durable descriptor disagree silently; the descriptor is the single composition truth the runtime already honors.

## Testing

Fork-owned suites run green locally after the adaptation (patent, self-evolve, better-sidebar, synapse, session consumers); `verify-tsconfig-paths`, translation pairing, and the staged lint hooks pass. Linux-lane CI is the platform-of-record run for this merge.
