# Agent Note: upstream v0.1.5-rc.2 sync and the client-face type subpath upkeep

Status: implemented

English | [中文](2026-09-11-upstream-v0.1.5-rc.2-sync.zh.md)

## Problem

The fork tracked upstream after the v0.1.5-rc.1 sync; upstream master advanced to `c291e7961a` (released as `dsh-v0.1.5-rc.2`, 134 upstream commits since `aa8262ec09`). The upstream delta centers on the public package manifest (`dsh-package-manifest` types with plugin format, tags, and host compatibility), the agent preset selection setting, composer command menu grouping with plan/compact/shield glyphs, sidebar previews of file and skill references, typed `remote-mock` native mocks, deprecation of synchronous session event reads, and desktop boot hardening (immediate window, in-place profile, unsigned local builds). Upstream also rewrote the linux scope's empty-cgroup release to query `TasksCurrent` and issue `systemctl --user stop`, and its new desktop boot tests mock Electron without the fork-only `BridgeServer` and `globalShortcut` seams.

## Decision

- **Client-face type-only subpaths for the descriptor seam.** `subagent`'s descriptor imports `SessionEvent` and `ToolRestriction` from `@deepseek-ai/dsh-session` and `@deepseek-ai/dsh-tools`; under the fork's per-face tsconfig split, a client program resolving those bare specifiers pulls the host `Context` augmentation in and fails with ~27 wrong-face errors. `SessionEvent` now imports from `@deepseek-ai/dsh-session/types`, and `ToolRestriction` moved from the `dsh-tools` host index into `types.ts` (the index re-exports it), so the descriptor imports it from `@deepseek-ai/dsh-tools/types`. `scripts/type-equiv.manifest.json` follows the declaration to `packages/core/tools/src/types.ts`, matching existing non-index manifest entries.
- **Hand-maintained host alias map gains the new package.** The fork-only `tsconfig.base.host.json` overrides the workspace `paths` with a host-face map; upstream's new `@deepseek-ai/dsh-package-manifest` alias (generated into `tsconfig.base.json`) does not reach host programs, so `packages/util/package-manifest/README.md`'s doc-typecheck block failed with TS2307 until the alias was added to the host map beside `dsh-output-retention`.
- **linux scope: upstream's empty-range release first, the fork's residue settle second.** The conflict-resolved `rangeActive()` had kept the fork's residue-settle block (terminated scope with a live request file and no live members) ahead of upstream's `emptyRange` check, so a scope whose cgroup emptied was never released and the new `systemctl --user stop` test failed. The `emptyRange`/`releaseEmptyRange` check now runs first; the fork's settle block runs after it, and the duplicate downstream empty-range block was removed. The fork zombie case (nonzero tasks) still skips the empty-range release and settles through the residue block.
- **Desktop boot tests adopt upstream's Electron mock plus the fork's seams.** Upstream's new `main-startup.spec.ts` mocks Electron without `BridgeServer` or `globalShortcut`; the fork's mock factory adds `globalShortcut` (`register`/`unregister`/`unregisterAll`/`isRegistered`) and `app.getName()`, keeping all 13 startup tests green.
- **Web roster inject edges stay within roster rows.** The fork-only `ui-todo-board` no longer lists `@deepseek-ai/dsh-tool-todo` in `dsh.client.inject` — upstream's `assembly-bundle-roster` gate rejects inject targets that are not themselves roster rows; the dependency stays for the type import.
- **Upstream CI notes follow the fork's workflow archive policy.** The merged `2026-09-09-blacksmith-failover-leg` note's `ci.yml` link re-points at `.github/workflows-disabled/ci.yml`, matching every other implemented note.
- **Generated catalogs and their zh counterparts.** `gen-config-catalog`, `gen-persistence-catalog`, and `gen-doc-graphs` regenerated the English config catalog, persistence catalog, and event producer/consumer graph from the merged source. The zh counterparts were rebuilt through pairing rather than re-translated wholesale: sections and list rows missing from the merged upstream zh (all fork-only packages) were re-inserted from the fork master's reviewed zh with fences and source links synced to the regenerated English, the event tables mirror the English rows verbatim under the translated header, and every pair was re-recorded with `verify-translation-pairing --write` (988 pairs consistent).

## Consequences

The fork ships upstream's v0.1.5-rc.2 baseline with desktop, patent, self-evolve, synapse, plugin-market, openviking, and better-sidebar surfaces intact. The client-face import discipline now covers `dsh-tools/types` beside the existing `dsh-session/types` and `dsh-subagent/client` subpaths: new shared types that client programs consume must live in (or be re-exported through) the package's `types.ts`, or the same wrong-face failure returns at `tsc -b tsconfig.client.json`. The host-face alias map stays hand-maintained on each sync, and a missing entry now surfaces at doc-typecheck time because every new package's README carries a compiled example block.

## Alternatives considered

- **Keep `ToolRestriction` in the `dsh-tools` index and map only the doc manifest.** Rejected: the descriptor is a client-reachable module and the host index drags the host `Context` augmentation into client programs regardless of where the doc manifest points.
- **Take upstream's zh catalog documents wholesale and defer fork sections.** Rejected, as in the rc.1 sync: upstream's zh lacks every fork-only section, and the pairing gate compares headings, fences, table shapes, list counts, and link targets structurally — the fork master's reviewed zh translations merge forward mechanically, so deferral would leave doc-sync red for no translation gain.
- **Re-resolve the linux scope conflict keeping the fork's block first.** Rejected: the residue-settle precondition (`existsSync` of an unconsumed request file) is true in the empty-cgroup case too, so it starved upstream's `stop` release outright; ordering the shared release first preserves both behaviors without merging the predicates.

## Testing

`pnpm run typecheck` (Host `tsc -b` + tsdown + Client `tsc -b`), `pnpm run doc-sync` (34 gates), and `pnpm run test` pass locally on macOS: 27667 tests passed with two known environment flakes — `util/http-proxy` bypass-direct (pre-existing on the master baseline worktree) and the HMR file-watch timing case, which passes 3/3 in isolation. The bilingual pairs were re-recorded with `verify-translation-pairing --write`. Linux-lane CI remains the platform-of-record run for this merge.
