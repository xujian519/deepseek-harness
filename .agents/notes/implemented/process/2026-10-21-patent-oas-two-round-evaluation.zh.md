# Agent Note: A two-round OA evaluation with scripted review opinions

Status: implemented

[English](2026-10-21-patent-oas-two-round-evaluation.md) | 中文

## Problem

审查意见答复不是一次成稿。实务流程是审查意见 → 答复 → 再审查 → 修订答复,而代价最高的失败是修订后仍未克服所指缺陷、修改超出原申请文件范围,或引入新缺陷。`oa-answer` case 只测第一次答复,因此无法区分「一次答得好」与「能在第二份意见下修订」的执行者——后者才是这个 benchmark 要比较的行为。

接一个真实第二审查模型会给测量引入变动变量:分数会把执行者的修订能力与审查者的措辞混在一起,同一次运行也无法复现。评测需要的是一个固定在金标里、无需另一个模型即可重放的第二回合。

## Decision

**多轮 case 固定为两轮。** `cases/<case-id>/rounds/02/statement` 存放开启第 2 轮的脚本化审查意见。`loadGold` 只接受这一个轮次目录;其它轮次编号(`03`、不连续)、`rounds/` 下的散落文件、轮次目录里的多余文件,以及空意见都会被拒绝,而不是被静默降级成单轮运行。

**每一轮用同一份 rubric 评分。** 运行器每轮为执行者启动一个进程,并为每个 rubric 维度启动一个评估者,因此两轮都产生逐维度观测。`RunCase.rounds` 保留这些观测、开启该轮的审查意见摘要(`statementDigest`;第 1 轮没有)以及每次运行一个交付物摘要。`RunCase.dimensions` 只保留最后一轮,门禁的 case、节点、聚合判定与基线 Δ 因此始终同类比较。

**第 2 轮修订第 1 轮的交付物。** 它的工作目录是 `run-N/round-2/`。运行器复制第 1 轮的 agent state,把第 1 轮交付物保留为 `previous-deliverable.md`,并删除旧的 `deliverable.md` 与 `agent.log`。执行者因此必须写出新交付物,而不是留下一个会被记为第 2 轮结果的旧文件;每轮日志也各自分开。

**金标摘要覆盖后续轮次。** 新增 `rounds` 条目会改变 `goldDigest`,因此一个 case 增加第 2 轮后,不显式重录摘要与基线就无法与旧基线比较。多轮 case 的 run 记录必须带 `rounds`,单轮 case 不得带:两种分数定义不可比,静默混用会让门禁拿终局分与首轮分作比较。

**门禁只判最后一轮。** `caseRoundScores` 为报告算出每轮的加权总分,`formatVerdict` 打印 `R1 … → R2 …`,但判定使用终局的 `RunCase.dimensions`。修订是进步还是回退一目了然,而通过规则不变。

## Alternatives considered

**允许任意轮数。** 暂不采纳:更多轮次会成倍增加调用,引入未定义的停止规则,并让评测滑向测「收敛」而不是本议题划定的修订行为。扩展轮数需要单独预注册的设计。

**用真实审查模型产生第二份意见。** 否决:审查者的措辞成为不受控变量,同一次采集无法复现,分数也不再只隔离执行者的修订能力。

**把每一轮做成独立 case。** 否决:第 2 轮的 case 收不到第 1 轮交付物,要测的连续性消失,而且同一份工作要付两次费用。

**按逐轮均值判定。** 否决:交付质量由最终答复决定。均值会奖励「首轮很强、随后回退且未克服所指缺陷」的情形。

**复用 agent state 但不删除旧交付物。** 否决:不重写 `deliverable.md` 的执行者会留下第 1 轮的文件,采集就会把一份未修改的文档记为第 2 轮结果。

## Consequences

多轮 case 的调用量为 `runsPerCase × rounds × (1 + rubric 维度数)`;`--dry-run` 的计划包含轮次。run 记录每轮多一条观测,但足以复算逐轮总分并识别每个分数判定的交付物版本。

随仓的金标目前还没有多轮 case:布局、采集、记录与门禁路径由无 key 的 spec 覆盖,真实的脚本化审查意见与配套基线需要带 key 采集。那次采集必须在同一变更里重录 `goldDigest` 与基线。
