# 内部无效宣告分析意见 — 版式惯例（Conventions）

> 生成或修改本模板前必读。与 `checklist.md` 配套。本模板产出**内部件**：可载引用日志、逐权项结论分档与缺口披露。对外提交件用 `invalidation-opinion`（专利无效宣告请求书）模板，两者的章节集合不同。

## 1. 文书结构（固定顺序）

1. 页眉（所名 + 密级）
2. 文书抬头（类型徽标 / 标题 / 分析编号）
3. 案件信息表（涉案专利号 / 专利名称 / 授权公告日 / 专利权人 / 委托方 / 分析日期）
4. 一、分析范围与依据
5. 二、涉案专利权利要求分析（特征分解表）
6. 三、证据清单
7. 四、无效理由逐条分析（按法条逐条组织）
8. 五、逐权利要求结论与成功率分档
9. 六、引用日志
10. 七、缺口与待补事项
11. 分析结论（收尾小节，不带中文数码）
12. 落款 + 免责声明 + 页脚

「分析结论」不写中文数码：章节编号只用于章节级标题且须连续递增，收尾小节参与编号会与七节体例争位。渲染器的合规检查（`packages/patent/patent-document/src/document/documentCompliance.ts`）据此跳过它。

## 2. 无效理由法条体系

法条与理由的对应以确定性理由表为准：`packages/patent/patent-core/src/notice/grounds.ts`。下表按该表口径列出，改动其一须同步另一处。细则条号为 2023 年修订（2024-01-20 施行）后的条号；识别他人文书时，2024-01-20 之前出件的旧条号（细则第20条第2款、第43条第1款）按同一理由归入，本所出件一律写现行条号。

| 法条 | 适用场景 |
|---|---|
| A22.2 新颖性 | 权利要求全部技术特征被一篇现有技术单独公开 |
| A22.3 创造性 | 权利要求相对于现有技术结合显而易见 |
| A22.4 实用性 | 不能制造或使用、无积极效果 |
| A2 / A5 / A25 客体 | 不属于技术方案；违反法律、社会公德或妨害公共利益；属于不授予专利权的范围 |
| A26.3 充分公开 | 说明书未清楚完整地公开技术方案 |
| A26.4 清楚支持 | 权利要求不清楚、得不到说明书支持 |
| 细则第23条第2款 必要技术特征 | 独立权利要求缺少解决技术问题的必要技术特征 |
| A33 / 细则第49条 修改超范围 | 超出原说明书与权利要求书记载的范围；分案申请同理 |
| A9 重复授权 | 同样的发明创造 |

**不属于无效理由的条款**：单一性（A31条第1款）不在无效理由之列，内部件同样不得把它写成无效理由——内部评估放宽的是分档与缺口披露，不是法条口径。

### 2.1 从属权利要求的法条路径

本件与对外件同口径，见 `invalidation-opinion/references/conventions.md` §2.1：

- **不得以附加技术特征被公开为由认定从属权利要求不具备新颖性。** 从属权利要求的技术方案是所引用权利要求的全部技术特征与附加技术特征的组合，判断新颖性、创造性时比对的是全部技术特征。
- **从属权利要求与其引用的权利要求使用同一法条路径。** 引用权利要求以 A22.3 主张的，从属权利要求以 A22.3 承接，结论写「在引用权利要求不具备创造性的基础上，权利要求 X……不具有创造性」。
- 附加技术特征无对比文件直接覆盖时，主张其为本领域常规技术选择，按 §3 四段式给出事实与理由。内部件可把这类权项标为「难以无效」并列入 §7 缺口，但**不得**因此更换法条路径，也不得把「本项无覆盖」写成理由。

## 3. 无效理由四段式

每个无效理由按以下结构组织（节标题与四段式小标题由渲染器按草案结构生成，模型只填三段正文）：

1. **事实认定**：涉案专利权利要求 / 说明书对应内容。
2. **证据分析**：D1/D2/本领域常规技术选择的公开内容 + pin-cite。
3. **法条适用**：引用具体法条及审查指南章节。
4. **结论**：权利要求是否无效。

节标题形如 `4.1 权利要求 1 不具备创造性（专利法第22条第3款）`：法条、理由名与被主张的权项号取自草案的结构化字段。**起草时不得手写小节标题**，也不得为未主张的理由补写小节。

## 4. 证据时间线

- 对比文件公开日必须早于涉案专利优先权日 / 申请日；有优先权的以优先权日为准。
- 中间文件（P）的公开日介于优先权日与申请日之间。
- 抵触申请（E，同一申请人的在先申请在后公布）单独标注。
- 原始申请文件不是现有技术，只作修改超范围（A33）的核对基线，与对比文件分列。

证据清单的列名与登记口径与对外件同口径，见 `invalidation-opinion/references/conventions.md` §4.1：标识列对出版物写 ISBN、对原始申请文件写「—」，标识列不留空，同一份证据全件只用一个编号。

## 5. 逐权项结论分档

本件是内部件，逐权项结论表写「结论档 / 法条路径 / 依据与风险」三列：

- 三档：**可无效（证据充分）**、**可无效（存疑）**、**难以无效**；徽章按对委托人有利程度取 `badge-risk-low`（证据充分）/ `badge-risk-mid`（存疑）/ `badge-risk-high`（难以无效）。
- 法条路径写法：`A22.2`、`A22.3`、`A26.4`、`A33` 等；从属权项写「承接权 N」并说明引用关系。
- 分档须有证据覆盖与时间线作依据，并与「七、缺口与待补事项」对同一权项的说法一致；分档下调的条件写在「依据与风险」列里。
- **对外件不得写分档**：请求书只写请求的结果（请求宣告无效 / 部分无效），分档属内部评估。

## 6. 内部件与对外件的分离口径

本件**可**载：

- 引用核验记录与 source_path 清单
- 逐权项结论分档、成功率判断与最坏情形说明
- 缺口与待补事项、待填项、交付前检查项
- 修订记录、内部任务编号、证据篇数口径

对外件（`invalidation-opinion`）**不得**载上述任何一项，其 `references/conventions.md` §6.1 列出禁止清单。两件不合并发布：需要对外提交时另起对外件，正文只保留实际主张的理由、证据清单与请求结论。

发送口径：本件的密级为「机密 · 仅供委托方使用」，不进入任何对外程序或对方当事人可见的卷宗；本件不写「请求宣告……无效」一类对外请求句。

## 7. 视觉与版式纪律

- 沿用 `assets/templates/patent/tokens.css` 品牌变量；agent 不改样式。
- 表格数字列使用 `tabular-nums`，编号列用等宽体。
- 无证据支撑的断言在引用日志中降级为「模型推断」或「假设」——该降级只在内部件出现。

## 8. 品牌契约注入点

同 `assets/templates/patent/DOCS.md` 与 `tokens.css`。抬头所名、密级、免责声明由 CSS 变量注入。
