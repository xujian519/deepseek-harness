# Agent Note: upstream v0.1.2-rc.1 sync and the per-face Host/Client separation

Status: implemented

English | [中文](2026-09-04-upstream-v0.1.2-rc.1-sync.zh.md)

## Problem

The fork tracked upstream after the v0.1.2-alpha.4 sync; upstream master advanced to `76fda72979` (released as `dsh-v0.1.2-rc.1`). Three upstream changes dominate the migration: `SessionPersistence` moved to per-session handles (dropping `listSnapshots`/`inspect` for `list`/`stat`/`open`), `agentLoop.create` became async, and the Rule tightened so each client program compiles in its own face — the Host aggregate must not pull `packages/*/src/client` into its program. The merge had to carry the fork's packages (patent, self-evolve, better-sidebar, synapse, plugin-market, patent-teams dashboard) across those breaks.

## Decision

- **Handle-based persistence.** Fork consumers of `SessionPersistence` read through the new handle API. Synapse's `listSnapshots()` became `list()`, and its two `inspect(id)` calls became `open(id, 'read')` + `read()` + `close()`.
- **Async `create`.** `agentLoop.create` now returns a `Promise<Agent>`; the one un-awaited call in `tool-calls.spec.ts` gained `await`.
- **Host/Client face separation.** rc.1's Rule requires the Host program to exclude client source. The Host aggregate resolves every `@deepseek-ai/dsh-*` package to source through `tsconfig.base.json`'s `paths`, so any Host test importing a `/client` subpath dragged the whole client source graph (and its JSX/CSS) into the no-JSX Host program. Added `tsconfig.base.host.json`, derived from `tsconfig.base.json` with every `/client`→source mapping removed; `tsconfig.host.json` now extends it, so the Host program resolves `/client` through each package's `exports` to its built `lib/types` declarations instead of client source. `pnpm run typecheck` was reordered to run the client `tsc` first so those `lib/types` exist before the Host build consumes them.
- **`ui-patent-teams` stricter types.** rc.1's `exactOptionalPropertyTypes`, `readonly` node arrays, and branded `SessionId` broke the fork's Teams tests: the shared `ConversationViewBuilder.replace`/`apply` now require a `timeline` snapshot (the fork builder accepts and ignores it); the pure-DAG test was renamed to `teams-dag.client.spec.ts` (client aggregate); the bare-hero fixture omits `description` instead of setting it `undefined`; `viewEntry.inject` no longer takes a session id, so the fixtures call it with no argument; three geometry constants got JSDoc.
- **Storage relocation and deletions.** Upstream moved `session-persistence`'s storage into `./storage.ts` and deleted `coordinator.ts`; the `docs/TECH_DEBT.md` entries pointing at the deleted file were removed.
- **Platform/policy.** `.github/issue-management/policy.mjs` adopted upstream's project-V2 snapshot; `pnpm-workspace.yaml` kept the fork node-pty downgrade and added upstream's `@yao-pkg/pkg` patch; `python/sdk-runtime/package.json` dependencies were rebuilt for the rc.1 package set.
- **Generated surfaces.** `api-catalog`, `config-catalog`, `persistence-catalog`, `event-producer-consumer`, `module-graph`, the tool catalog, the module graph, and `known-event-types` were regenerated; the five changed bilingual doc pairs were reconciled and re-recorded.

## Consequences

The fork shares rc.1's handle-based session vocabulary and per-face compiler separation while keeping every fork-owned package compiling against the new APIs. `pnpm run typecheck` (Host and Client), `pnpm run doc-sync` (32 gates), and `pnpm run lint` are green locally.

## Alternatives considered

**Let the Host aggregate keep pulling client source and add JSX/CSS support to it.** Rejected: this re-merges the two faces that rc.1 deliberately isolated, restoring the interleaved `Context` merge the split exists to prevent.

**Patch each Host test that imports a `/client` subpath instead of changing resolution.** Rejected: the `lib/types` route is a single resolution-layer change that covers every current and future `/client` import, whereas per-file edits would need re-doing for each new one, and several such Host tests are genuinely Host-behavior tests that only reference client types.

## Testing

`pnpm run typecheck` (Host + Client aggregates), `pnpm run doc-sync` (all 32 documentation gates), and `pnpm run lint` pass locally on macOS. Linux-lane CI is the platform-of-record run for this merge.
