# Agent Note: 跨会话任务看板视图

Status: implemented

[English](2026-09-02-cross-session-todo-board.md) | 中文

## 问题

已退役的桌面 demo（历史独占的 PR #374 合并）带有一个 Mission Control 看板：把每个会话最新的 `todo/write` 列表聚合成三列 kanban，每张卡片带一个可跳回所属会话的徽标。随附的 Web GUI 没有跨会话的待办表面——停靠栏的 Todo 条带（[todo 计划在下一轮次清空](2026-07-28-todo-plan-clears-on-next-turn.zh.md)）只显示当前会话当前回合的有效计划，用户无法一眼看到其他会话正在做什么，而且一个已结束会话的最后一份清单会在下一个 `turn/start` 从界面上消失。

## 决策

看板以 `Board` tab 的形式进入 Web GUI 的会话视图环，与 Chat、Trajectory 并列。该 tab 由新的客户端插件包 `@deepseek-ai/dsh-client-ui-todo-board` 拥有，渲染的是对浏览器既有数据的纯投影。

### `todosLatest` 投影单元

`dsh-tool-todo` 在有效计划 `todos` 单元旁注册第二个投影单元：同一整表 `todo/write` 折叠，但永不清空——整日志最后写入胜出。看板（而非停靠条带）是它的消费者。有效计划单元保留其轮次边界生命周期与 `stateVersion`；新单元从 `stateVersion` 1 起步，没有先前的持久状态。两个键都在 `dsh-tool-todo` 的类型出口合并进 `SessionProjectionMap`，并经由既有载体到达浏览器：会话列表投影列与 `session/projection` 推送帧。没有 wire 变更、没有新事件、也没有客户端侧折叠。

### 范围与导航

看板把范围定为当前会话所属的工作区，通过工作区目录的 `sessionIds` 匹配——与侧边栏浏览器分组使用的成员关系一致；不属于任何工作区的当前会话会把看板范围定为所有工作区之外的会话。每张卡片逐字显示待办内容，外加一个携带所属会话显示标题的徽标；激活徽标调用会话控制器的 `open`。在范围内任一会话写入待办之前，看板渲染三列的虚线幽灵预览，让首次使用者看到真实数据将落入的形状。

### 模型写入的标签

看板的标签筛选读取 `TodoItem` 新增的可选字段 `tags`。这有意推翻了该类型最初「刻意保持最小」的立场：跨会话分组需要一个模型写入的字段，而整表替换让标签与其描述的内容同行——不引入条目级身份。工具把标签规范化（已修剪、非空、条目内唯一；缺席与空数组合并为无键），持久化不变量在回放侧执行同一形状，看板渲染角标加「全部 + 各标签」的筛选条，自身不拥有任何标签状态。字段可选，因此旧日志回放不变，模型也可让任一条目不带标签。

## 已考虑的替代方案

- **看板复用 `todos` 投影** — 其有效计划生命周期在 `turn/start` 清空，任何会话一开始新回合看板就会清空；两个表面真正想要不同的生命周期。
- **工作区级的主区视图切换** — 最接近 demo 的 Mission Control 形态，但意味着对 `ui-layout`/`ui-conversation` 契约做布局手术；视图环才是其他活动视图的既成扩展位。
- **客户端回扫日志取待办** — 在浏览器里重新折叠会话日志，复制了宿主投影接缝；投影列本就为每个列表会话投递整值。
- **用户手写标签存客户端** — 卡片没有稳定身份（每次写入整表替换），客户端存的标签无法在重写后跟随原卡片，除非做脆弱的内容键匹配；且需要新的持久化接缝，或退化为 localStorage 的设备本地状态。

## 后果

用户在一个视图中看到范围内每个会话的最新清单，包括早已结束的会话与后台运行的会话；范围内任何会话的写入无需刷新即落到看板。停靠 Todo 条带与看板读取同一事件的两种折叠，因此新回合保持条带的当前回合语义，而看板保持最后一份清单可见。覆盖：tool-todo 投影规格（整日志最后胜出、跨轮次存活、无工具时键缺席）、携带 `todosLatest` 的 connection fixture、看板 client 规格（列投影、标签筛选及其在激活标签消失时的重置、注册、落位 Chat 视图的重试、fiber 卸载生命周期），以及对 fixture 会话钉住渲染列、计数与徽标的装配期望输出测试。
