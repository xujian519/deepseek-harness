# Agent Note：加载时自动修复含孤儿工具调用的转录

状态：implemented

[English](2026-08-16-auto-heal-orphaned-tool-calls.md) | 中文

## 问题

被早期双副本调度器 bug 损坏的会话会永久不可用：孤立的 assistant `tool_calls` 消息位于转录中段，每次重试都在模型运行前被提供方拒绝；轮次错误平衡修复只能防止新损坏，无法修复已写入的日志。用户只能分支或新建会话。

## 决策

扩展加载时修复：`dsh-session` 新增 `orphanedToolCallReplacements`，扫描日志，把每个调用从未得到应答的 assistant `tool_calls` 消息替换为纯文本 user 角色说明（harness 正是以 user 角色承载生产者注入的上下文），使用表面替换机制——与 compaction 使用的同一套持久化中段重写。接入持久化协调器的 `prepareCore` 后，每次冷加载/恢复都会自动修复；`commitRepair` 持久化替换事件。幂等：修复后的消息不再携带工具调用。部分应答会随消息一起被遮蔽，因为消息消失后这些结果本身也会悬挂。

## 备选方案

**在日志尾部追加合成结果。** 已对真实提供方验证：tool 消息必须紧跟在 `tool_calls` 消息之后，因此尾部追加无法满足中段孤儿。不采纳。

**在投影层丢弃孤儿消息。** 派生消息缓存假设节点投影一旦折叠即稳定；在投影层做静默手术也违反逐字直通契约。不采纳。

**不做自动修复。** 会让所有损坏会话卡死；用户的真实会话已处于该状态。不采纳。

## 影响

- 单元测试钉住替换形态、部分应答范围与幂等性；session/persistence 共 762 个测试通过。
- 已通过 `persistence.prepare` 应用到用户的三个损坏会话；其派生转录现为 0 个孤儿工具调用、各含 1 条修复说明，已安装应用可干净恢复。
- 原始日志保留原消息；只有模型可见表面将其遮蔽。

## 剩余风险

- 修复时仍处于 live 状态的会话不会在应用打开期间被修复，需关闭应用（或释放会话）后由协调器冷加载执行修复。
- 修复会改变模型所见（一条说明取代失败的工具调用）；这是有意为之——否则转录将永远被拒绝。
