# Agent Note：self-evolve 评估决策规则

Status: implemented

[English](2026-10-12-self-evolve-eval-decision-rule.md) | 中文

## 问题

P1-10 门禁原先在配对净胜分的百分位 bootstrap 区间**严格高于零**时判 `continue`（[评估脚手架](../feature/2026-08-21-self-evolve-p110-eval-scaffold.zh.md)）。在这个规模下，这条判据有三处不对。

**配对二值结果上的 bootstrap 在这里功效不足。** 战役把同一任务在双臂上配对，因此每个任务只贡献三种结果之一：赢、输、平。重采样任务差值丢掉了配对结构，而不是直接检验不一致对（discordant pairs）；而 Bowyer 等（[arXiv:2503.01747](https://arxiv.org/abs/2503.01747)）指出，区间方法恰恰在观测数少于几百、中心极限定理最不可靠的地方最依赖它。

**"区间不含零"会放行没有实际意义的效应。** 在 n = 60 时，净胜 5 题就能让区间越过零。一条会为了两个百分点的增益而默认开启的规则，不是任何人都能据以行动的规则。

**同一个固定子集无法被免费地反复消费。** 候选是针对该子集自身的反馈提出的，于是搜索会自适应地过拟合那个评判它的集合。REUSE（[arXiv:2609.33180](https://arxiv.org/abs/2609.33180)）把这种模式的假晋升率量到最高 20.7%，并证明限制回传给搜索的反馈才是消除它的关键。脚手架记录决策时并未记录它出自哪个子集，因此针对同一 digest 的重复决策与首次决策无法区分。

## 决策

**用精确检验 + 预注册最小效应量做门禁。** `mcnemarExact(wins, losses)` 在不一致对上计算双侧精确 p 值（较小者服从 `Binomial(wins + losses, 0.5)`），并在对数空间累加各项，使合理的子集规模不会让 `0.5^n` 下溢。`decide` 仅在该 p 值低于显著性水平**且** `winRateDelta` 达到 `--min-effect`（默认 0.05）时建议 `continue`。bootstrap 区间仍然计算并记录，但降级为描述，不再作为判据。

**给判据加版本。** `EvalDecision.criterionVersion` 提升到 2，`readDecision` 会拒绝在另一版本下写成的记录，而不是让门禁去执行一条已不适用的规则。不同版本的记录不可比，而这个错误必须响亮：请重新跑评估。

**按重用次数收紧水平。** `--prior-reuses N` 把显著性水平除以 `N + 1`，对应 REUSE 里的顺序误差论证。决策覆盖的摘要通过 `--subset` 记录（子集文件的 SHA-256），于是"重用"是关于某个 digest 的事实，而不是一句声明。

**给流程留一个去处。** `selectSubsetWithReserve` 返回子集与一份不相交的留存池，两者出自同一次确定性洗牌；CLI 把两者都写出并打印子集摘要。`selectSubset` 保留原签名并委托给它，因此既有调用方与已入库的 `subset.json` 都不受影响。

## 备选方案

**保留 bootstrap 作门禁，只加最小效应量。** 否决：最小效应量修好了第二处问题，却留下第一处。与设计相称的检验是配对检验。

**只用 McNemar 做门禁。** 否决：在 n = 60 时净胜 8 题就能通过 0.05 水平，可它把解决率推动了 13 个百分点——但 n = 40 时净胜 5 题同样会通过。规则应当用维护者真正关心的单位表述，也就是解决率差值，而非 p 值。

**用贝叶斯后验替代精确检验。** 暂否决：那是对记录格式与门禁的更大改动，而 REUSE 提供的顺序误差控制是以频率派框架表述的。重用调整以更少的机械装置覆盖了同一顾虑。

**自动发现并轮换留存池。** 否决：仓库里没有任何东西追踪某个 digest 被消费过几次，自动轮换只能靠猜。在决策台账出现之前，重用次数是一个显式输入。

## 后果

- `pnpm exec vitest run packages/test-support/self-evolve-eval` 通过（155 个测试，+13）；精确检验覆盖了尾部的两侧，包括 `discordant === 0` 与上限截断到 1 的分支。
- 两处 CLI 接口变化：`subset` 增加 `--reserve`/`--reserve-out` 并打印 `subsetDigest`；`decide` 增加 `--subset`、`--alpha`、`--min-effect`、`--prior-reuses`。RUNBOOK 与其中文版都记录了两者。
- `spec.md` 与 `check_list.md` 用新术语重述回滚条件：门禁在精确检验未能拒绝，或效应未达预注册最小值时触发，而不是在区间跨零时触发。
- 按旧规则写成的决策记录不再能加载。当前没有这样的记录入库，因此今天不会破坏什么；该拒绝是有意为之，而不是静默地重新解释。
- 仍然未决：评估本身尚未运行，因此这条规则还没有数据。`verify-self-evolve-eval` 在记录为 `rollback` 时依然失败，这仍是把负面结果转成 CI 红灯的机制。
