## 3. 发现

### 3.1 门禁自身不可达 / 看不见（3 条）

- **`check:ci:snapshot` 与 `check:ci:artifacts` 必然抛错**（P1）。`package.json:99-100` 映射了这两个脚本，`run-gates.ts:18-36` 的 `Mode` 与 `:268-290` 的 `gatesForMode` 都完整实现了它们，但 `:132-156` 的 `parseMode` 没有对应 case，落到 `default` 直接抛。类型系统认为可达、实现已写好、脚本入口挂着，唯一的运行入口拒绝了它们。判定：**上游同步的 merge artifact**（#326 的收口删掉了这两个模式，同步把其中三处带回来、漏了 `parseMode`）。
  - **补充（本轮新增证据）**：`.github/workflows/ci-fork.yml` 的 **8 个 job**——`node-checks` / `node-built-suites` / `node-snapshots` / `node-web-snapshots` / `node-hygiene` / `node-coverage` / `benchmarks` / `python-checks`——**无一调用** `check:ci:snapshot` / `check:ci:artifacts`。所以「必然抛错」在 CI 上不可见，只有人手动跑才会撞见。这使「按 #326 原决定删除」成为更小的一步。
- **`verify-preset-divergence` 看不到「整行缺失」**（P2）。它的语义是按 row id 求交集后比内容（`verify-preset-divergence.ts:109-116` 的 `if (files.length < 2) continue`），一个 preset 少挂一整行时交集里就没有它。实测：`standard` 的 6 个顶层行在 document / patent / 自媒体 bundle 里整行不存在（`openviking` 另计，见 §2），而基线 `scripts/preset-divergence-baseline.json` 的 `rows` 分区共 **24** 个 row id 无一覆盖它们。功能后果最重的是 **`time-context` 缺失**——三个模式都拿不到当前日期，而三者都以日期敏感为核心纪律（专利：答复期限、年费；文档：页脚版本与日期、来源时效；自媒体：热点选题）。
- **`verify-preset-tool-refs` 忽略 `config` 级工具裁剪**（P2）。`mountedToolNames` 只认 `disabled === true`（`:123`），工具集按包名从目录取全集（`:126`）。而 `tool-web` 的 `Config.search` / `Config.fetch` 是真实注册开关（`tool-web/src/index.ts:81-86`）。于是 `document.patch.yml` 设了 `fetch: false`、模型目录里没有 `web_fetch`，门禁却把它算作已挂载——技能文本引用一个看不见的工具不会报错。这是 #321 收口（09-27 分诊 §10.1 补的 `disabled` 那条）的**同族盲区**。
- **`verify-patent-oas-gold` 在默认状态下静默休眠**（P2，本轮新增）。`scripts/verify-patent-oas-gold.ts:166-170` 在基线缺失时只打印「回归层休眠」并**以 0 退出**；而基线 `config.baselinePath` 不在仓库里（与 `patent-workflow/src/llmRunner.ts:22` 同形的本地基线路径），所以「基线缺失」是默认状态。叠加 ci-fork.yml 无任何 job 调用它，「有脚本 + `verify-*` 命名 + 能 exit 0」构成一个假绿门禁。

### 3.2 同一平台事实两个结论，且只有一侧有理由（1 条）

- **文档模式与自媒体模式关掉 `web_fetch`**（P2）。`patent.patch.yml:436-451` 为「是否开 fetch」写了 10 行理由，核心论据是「每个随包组合都挂了 http fetch provider（`dsh-base` 组合 `dsh-web-fetch-http`，没有 bundle 关掉它）」，因此 `fetch: true`；同一段话抄进 `patent.md:25` 与 `:77`。`document.patch.yml:311-317` 是同一份 `tool-web` 行、相反取值，注释只解释了「web 服务留在宿主」，**一个字没提 fetch**。而文档模式的 persona（`:32`）与两个技能都要求「每个事实性断言必须附可验证来源（URL / 文件路径）」——唯一能打开来源页面的工具不在目录里。
  - 该差异**已**被 `preset-divergence-baseline.json:149-155` 记为三个哈希，但基线是内容哈希，不承载理由；同一族里一侧有理由、一侧没有，读记录的人分不出哪侧是有意。
  - 自媒体 bundle 侧同样 `fetch: false`，人设 `:84` 写成已知限制，说明是**已知但未决**。
