# Agent Note: upstream v0.2.0-rc.1 sync

Status: implemented

English | [中文](2026-09-29-upstream-v0.2.0-rc.1-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.1.7-rc.2` tag to the `dsh-v0.2.0-rc.1` release, 261 upstream commits further on across 1109 files. The previous sync left the history connected — `git merge-base HEAD dsh-v0.1.7-rc.2` reported the rc.2 commit — so the release merge reported 50 conflicts (49 content, one modify/delete) instead of re-deriving earlier releases.

Upstream's release moved three surfaces the fork had shaped. The telemetry stack became a Cordis service: a new `packages/telemetry/otel` provider plus the Host and browser consumers `host-product-telemetry-otel` and `client-product-analytics`, with a `ui-settings-session-log` switch, and the desktop shell now reports product analytics through it. The Schedule rows left the default Web bundle for the opt-in `dsh-experimental-schedule-bundle`, which removed `dsh-schedule`, `dsh-client-ui-schedule`, and `dsh-time-context` from `packages/bundle/web-app`. The `sandbox-windows-acl` package gained a diagnosis skill shipped as package-root assets, the desktop builder gained its own macOS entitlements plist, and upstream folded the desktop keyboard fixture into the client typecheck program, deleting `tsconfig.desktop-keyboard-tests.json`.

Both sides also own the product-onboarding notice: upstream rewrote it for 0.2 and the fork ships the same notice under its own brand.

## Decision

- **Version, pins, and generated artifacts move with the release.** The 46 fork-only manifests and `SIDEBAR_SERVICE_VERSION` join the root's `0.2.0-rc.1` so `pnpm run constraints` and the release family check pass (364 members); the nine `snapshots/acp/*/stdout.expected.jsonl` pins follow, because `agentInfo.version` derives from the acp manifest. Every generator ran on the resolved tree (`gen-cordis-catalog`, `gen-config-catalog`, `gen-doc-graphs`, `gen-module-graph`, `gen-persistence-catalog`, `gen-tool-catalog`, `gen-plugin-packages`, `gen-dependency-catalog`, `gen-session-format-catalog`, `gen-client-catalog`, `gen-cordis-inspect-catalog`, `gen-scoped-events`, `gen-tsconfig-paths`), and `pnpm run verify-no-unknown-casts --prune` reported no new assertion to `unknown`.
- **The manifests resolve as unions of both sides, with upstream's new packages placed where the fork sorts them.** `apps/cli` gains `dsh-experimental-schedule-bundle`; `packages/bundle/base` gains `dsh-otel`; `packages/bundle/web-app` gains `dsh-client-product-analytics`, `dsh-client-ui-settings-session-log`, and `dsh-host-product-telemetry-otel`; `packages/client/ui-chat`, `packages/api/remotes`, `apps/desktop`, and `python/sdk-runtime` gain the same analytics and telemetry dependencies. The web-app bundle keeps upstream's removal of the three schedule rows, and the base bundle keeps the fork's earlier removal of `dsh-tool-call-timeout-policy`.
- **The desktop shell keeps the fork's unsigned-darwin mac block and adopts upstream's adjacent additions.** `signIgnore`, the beside-archive Office entry, `notarize: !unsigned`, and the tray wiring stay the fork's; the `macos-entitlements.plist` paths, `DSH_CLIENT_VERSION`, the analytics `track` calls, and the `desktopClientVersion()` import land. `apps/desktop/scripts/electron-builder-config.mjs` resolves to the fork's mac block plus upstream's entitlements entries, and `apps/desktop/tests/main-startup.spec.ts` keeps the fork's bridge-path assertions alongside upstream's client-version and analytics assertions.
- **`tsconfig.desktop-keyboard-tests.json` is deleted and `apps/desktop/src/print.ts` joins the client program.** Upstream deleted the fork-only project when it folded the keyboard fixture into `tsconfig.client.json`, but the fork's `apps/desktop/src/ipc.ts` imports `print.ts`, which the folded include list omitted, so `print.ts` joins the list under the fixture comment.
- **The client program now carries Electron's global DOM augmentation, and the fork's better-sidebar chunk-loader spec types its mock accordingly.** The folded desktop sources import `electron`, whose declarations augment `Document`; `packages/client/better-sidebar/tests/cov-views-chunk-loader-script.client.spec.ts` therefore extracts one `captureCreatedElements()` helper that casts its replacement to the factory it replaces instead of passing a plain `(tag: string)` implementation.
- **The onboarding notice takes upstream's 0.2 preview text under the fork's brand.** `packages/client/ui-settings-models/src/client/locales.ts`, its spec, `apps/web/tests/scaffold.ts`, and `apps/web/tests/expected/onboarding-deepseek-config/welcome.expected.md` carry the "Preview Notice" copy with `DeepSeek Harness` replaced by `DSH Patent`, consistent with the 0.1 text the fork already shipped, and `WELCOME_NOTICE_VERSION` moves to `2026-09-28.1`.
- **Four code conflicts resolve as unions.** `packages/sandbox/sandbox-local/src/index.ts` keeps the fork's validated `probeTimeoutMs` label and takes upstream's Windows ACL diagnosis-skill registration; `packages/api/remotes/src/client/index.ts` adds `productAnalyticsRemote` beside the fork's `pluginMarketRemote`; `scripts/check-workspace-constraints.ts` takes `assets` for `sandbox-windows-acl` beside the fork's `methodology` entry; `apps/desktop/src/main.ts` passes both `DSH_DESKTOP_BRIDGE_PATH` and `DSH_CLIENT_VERSION`.
- **The generated pages are regenerated, and the Chinese pages that no generator writes are mirrored by hand.** `docs/capability-seams.zh.md` gains the `ctx.productAnalytics` and `ctx.otel` service rows and the `pkg_otel` graph edge, which the English page receives from `gen-doc-graphs`; `packages/client/README.md` and its Chinese page gain the `product-analytics/` row; `packages/README.md` and its Chinese page drop the summary's redundant group-README clause to stay inside the 1080-word ceiling after the new `telemetry/` group row.
- **The new SDK `tool-scheduler-recovery` scenario reaches the fork's scheduler key.** Upstream's recording locates the tool scheduler through a symbol description; the fork carries `TOOL_RUNTIME_SCHEDULER` as the namespaced string `@deepseek-ai/dsh-tools:runtime-scheduler`, so `snapshots/sdk/tool-scheduler-recovery/scheduler-failure.mjs` indexes that property directly instead of scanning symbol keys.
- **The pairing records are re-recorded, and one new upstream note is repointed.** `pnpm run verify-translation-pairing --write --all` rewrote the ten conflicted `*.i18n.yaml` records; `.agents/notes/implemented/testing/2026-09-27-web-lane-assertions-name-their-input-state[.zh].md` points its CI link at `.github/workflows-disabled/ci.yml`, the fork's location for the workflow upstream keeps under `.github/workflows/`.

## Consequences

The fork ships upstream's v0.2.0-rc.1 baseline with its patent, desktop, and better-sidebar surfaces intact, and the history stays connected: `git merge-base HEAD dsh-v0.2.0-rc.1` is the release commit, so the next sync reads the real conflict set. The fork treats `dsh-writing-patterns`' model-facing descriptions, the desktop mac block, and the welcome-notice copy as its own, so each release that touches them conflicts again.

Two `pnpm run doc-sync` gates still failed at this sync, both pre-existing and outside the gates the fork's CI runs (`doc-quick` excludes them): `verify-package-paths` reported stale references to the `approval.ts` and `quality-gate.ts` modules that the 2026-09-27 scan fixes deleted without updating the three notes citing them, and the documentation site build failed on `docs/tool-catalog.md`, whose fork-owned patent tool descriptions carried raw `<writing_skills>` and `<g>` text that Vue reads as unclosed elements. The site build's inputs are byte-identical to the pre-merge tree, so neither failure was this sync's. Both were cleared on 2026-10-01: the notes were repointed at the current tree and the two descriptions now wrap those tokens in code spans.

## Alternatives considered

- **Merging the release in stages through an intermediate tag.** Not needed: the merge base already sat on the previous sync's tag, so the single merge reported the 50 conflicts the two releases actually share.
- **Keeping the fork's separate desktop keyboard tsconfig.** Rejected: upstream retired the project in the same commit that folded its files into the client program, and keeping a program whose `files` list duplicates the client include list leaves two homes for one list.
- **Fixing the pre-existing package-path and site-build failures in this PR.** Rejected: they predate the merge, and the site-build fix would rewrite model-facing tool descriptions that this sync does not otherwise touch.
- **Raising the `packages/README.md` word ceiling instead of condensing.** Rejected: the summary restated a fact the preceding sentence already made, so the required telemetry row fits by relocating rather than by raising a budget.
- **Taking upstream's `bundle/web-app` schedule rows back.** Rejected: upstream moved those packages into an opt-in bundle, and the fork's own Schedule surfaces keep their packages, so the removal is the release's composition decision.
