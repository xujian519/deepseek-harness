# 质量门禁

输出前必查。任何一项不满足即把产出打回补证，检查不过不得交付。

## 检查清单

1. 免责声明在场：面向用户的专利分析输出必须含免责声明。
2. 法条核验：每条法条引用有出处（patent_case_search / 已挂载的 web_fetch / `99-知识库/` 基线），引用时核一遍、输出前再核一遍。
3. 检索证据链：新颖性/创造性结论有检索报告支撑，每个对比文件已打开验证，公开日早于申请日/优先权日。
4. 数字计算：期限/日期/费用用 tool-bash 计算，命中数与页码以工具返回为准，禁止心算。
5. 检查清单对照：撰写产物对照权利要求/说明书缺陷检查清单（清楚、支持、充分公开、单一性、修改超范围）。
6. 证据附录完整：法条来源、对比文件路径、检索式与日期、数字计算依据、检索未覆盖领域显式列出。
7. 对立审查：必要时 subagent_fork 一个对立审查员角色，以审查员视角对交付稿攻击性评审（不清楚、不支持、超范围、缺必要技术特征）。
8. HITL 放行：交付放行前用 ask_user 向用户确认；权利要求布局已在 plan-mode 获批（L3 强制确认点）。
9. 正式文档交付：交付文书按 patent-document-polish 走场景→模板映射，矫正（术语/法条引用/数字/编号/称谓）与美化（模板/品牌/A4）已完成、渲染成功（PDF 失败时 HTML 存在并如实说明）；docx 交付额外确认由 md 起草转换而来、修订以 tracked changes 呈现、输入原件未被改动。
10. 放行去重：文档专员的交付放行与收口确认合并为一次 ask_user，不重复打扰。

## 流程

按顺序逐项核查 → 记录不满足项 → 打回补证 → 补证后重新过门禁 → 放行前 ask_user 确认 → 用户确认才交付。法条/证据/数字项已由 patent-fact-check 执行时，此处仅核对结论与留痕，不重复执行。

## 免责声明模板

"本分析由 AI 辅助生成，不构成正式法律意见。专利申请和专利性判断应由具备资质的专利代理人或专利律师确认。"
