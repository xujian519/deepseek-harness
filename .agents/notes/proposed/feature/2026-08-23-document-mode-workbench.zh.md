# Agent Note: 文档模式工作台

Status: proposed

[English](2026-08-23-document-mode-workbench.md) | 中文

## 问题

[文档交付工作室](../../implemented/feature/2026-08-23-document-delivery-studio.zh.md)为文档智能体会话提供交付物标签：产物文件、HTML/文本预览、打开 / 在文件夹中显示 / 打印。文档交付工作线仍剩四个缺口：

- **质量门只有文字**。`document-quality-gate` 是清单技能；模型的通过报告只是消息文本，无法按交付物渲染检查项。
- **管线不可见**。brief → 大纲 → 模板 → 成品 → 质量门 → 交付，在最终文件出现前都是黑盒。
- **交付物是会话孤岛**。没有跨会话历史、检索或归档。
- **预览止步于文本与惰性 HTML**。`.docx`/`.pptx`/`.pdf` 无内联预览；JS 驱动的工件（Deck、仪表盘）在 `sandbox=""` 下只渲染首帧。

文档 preset 同时服务交付前核验（交付前过质量门）与交付后消费（查看/导出），但今天两者都发生在 GUI 之外。

## 提案

**应用级文档工作台：当当前会话的 preset 是文档智能体时呈现，独立于会话内交付物标签。** 它把质量门状态、管线进度与交付物清单汇聚到一个界面；现有工作室标签保持不动。

### 数据通路

三个来源，按权威性排序：

1. **既有派生词汇（全部历史）**。复用工作室的 `documentDeliverables` 折叠（locations → turn 数据 → 会话级视图目标）；工作台读取同一会话级目标，因此每个历史会话都能渲染交付物清单。
2. **结构化交付登记工具（新会话）**。新增宿主工具 `document-deliver`，放在由文档 preset 挂载的新包中，模型在质量门通过后调用。参数记录 `{files, formats, gate: {p0[], p1[]}, briefRef}`。工具调用进入会话日志，客户端用同一 conversation-node 机制折叠，因此 "model-visible ⟺ logged" 按构造成立——不新增会话事件类型、不改 `SessionEventMap`。未调用该工具的会话降级到通路 1，显示"无质量门数据"徽标。`document-quality-gate` 技能增加最后一步：P0 通过后调用登记工具。
3. **宿主聚合查询（v2）**。跨会话历史、检索与批量导出需要宿主侧对会话投影的查询；推迟到 v2。

### 应用级视图槽

GUI 只有一个视图环形槽，即会话级 `'conversation.view'`；`workspace.*` RPC 是数据接口而非 UI 槽。工作台需要一个新应用级槽（暂定 `app.view`，workspace scope）加导航入口，按[槽系统标准](../../implemented/architecture/2026-07-22-slot-type-chain-implementation.zh.md)设计。槽行及其宿主入口是跨包 SlotMap 变更，实现前先评审。

### 经 agent 修订

工作台组装结构化修订请求（改哪个文件、改什么、目标格式、约束）；用户确认后，请求经现有 `Session.prompt` 通道作为会话提示注入（与 composer 等价的接受语义，可记录、可重放）。文档智能体按指令重跑交付技能。不新增宿主写 RPC；会话日志仍是唯一写路径。

### 可执行预览与信任边界

HTML 工件在沙箱 iframe 中以 `sandbox="allow-scripts"` 渲染——不含 `allow-same-origin`（不透明源：无父页 DOM 或存储）、不含 `allow-popups`、不含 `allow-forms`。只有会话日志记录的产物文件允许执行（产物清单即白名单）。网络请求默认放行，因为 Deck/仪表盘需要取数；这是唯一待定的安全决策（见风险）。这是 GUI 第一个执行工件的表面。

### 分层预览

- PDF：浏览器原生渲染，零依赖。
- HTML：上述沙箱执行。
- `.docx`/`.pptx`（v1）：宿主侧 officecli 转换管道渲染 HTML 快照；officecli 不可用时工作台降级为应用内打开。
- 文本：沿用现有 `readFileText` 预算（调用方 1 MiB，绝对上限 4 MiB）。

### 范围

- MVP：工作台骨架、交付物富列表、PDF/HTML-JS 预览、经 agent 修订。
- v1：officecli 预览、质量门可视化、管线时间线。
- v2：宿主聚合查询、检索、批量导出、归档。
- 明确不做：宿主直写文件、面板布局自定义引擎、非文档 preset 的同类工作台。

## 曾考虑的替代方案

- **就地扩展工作室标签**——工作台是应用级、跨会话，工作室是每会话一个标签；单一入口无法同时服务两种范围。
- **面板直写宿主文件**——今天不存在宿主写 RPC；新增会跨越沙箱与审批表面，并破坏"会话可重放"规则；经 agent 修订经由已记录的提示通道达成同样结果。
- **客户端解析模型的 JSON 质量门报告**——脆弱、无模式约束；登记工具沿用工作室已有的"工具调用 → 日志 → 客户端派生"模式。
- **自由执行或只保留 `sandbox=""`**——`sandbox=""` 无法渲染 JS 驱动工件；自由执行没有信任边界；不透明源 `allow-scripts` 沙箱加产物白名单是中间路线。
- **完整 mini-app 平台**——由[对话内渲染节点提案](2026-08-20-inline-rendered-conversation-nodes.zh.md)推迟；本提案不做。

## 验收标准

- 文档 preset 生效时出现应用级工作台入口；工作室标签仍可用。
- 交付物清单带格式、来源会话与质量门状态；新会话的质量门条目从登记工具的已记录调用渲染，旧会话显示降级徽标。
- PDF 内联预览；HTML 工件只在不透明源沙箱中、且仅当为会话产物时执行。
- 修订确认后注入会话提示；agent 以修订后的文件作答。
- keyless snapshot 覆盖可见 GUI 变更；`test:gui` 与仓库门禁通过。工作台包与工作室一致，加入客户端车道覆盖率豁免，配 jsdom 与真实注册表 spec。

## 风险

- **可执行预览是新的安全面**——GUI 第一个执行工件。含脚本的产物文件在不透明源沙箱中运行，无弹窗、无表单，读不到应用或宿主，但可以发起网络请求。默认放行网络；阻断（注入 CSP `connect-src 'none'`）会以 Deck/仪表盘功能换取更严表面，需产品决策。
- **登记工具依赖模型纪律**——漏调会将会话降级为 locations 派生清单；降级可见，不静默。
- **新应用级槽是跨包 SlotMap 变更**——契约评审成本；若评审否决槽行，工作台回退为现有环形槽内的全屏工作室标签。
- **officecli 转换依赖用户级技能**——不可用时预览降级为应用内打开。
- **词汇重复**——工作台必须复用工作室的折叠而非另起一套，否则两个视图漂移。
