# Agent Note: upstream v0.1.6-alpha.1 sync and the host-face alias map upkeep

Status: implemented

English | [中文](2026-09-16-upstream-v0.1.6-alpha.1-sync.zh.md)

## Problem

The fork tracked upstream from the `dsh-v0.1.5-rc.2` sync point to the `dsh-v0.1.6-alpha.1` release on upstream master. Upstream advanced 666 commits while the fork carried 495 of its own, so the first merge attempt conflicted in 122 files.

The upstream delta renames two package families (`code-runtime*` to `ptc-runtime*`, `workflow-worker-thread` to `workflow-ptc`), retires the `e2b/*` provider family in favour of the `sandbox/` seam, adds the `ssh/*`, `computer-use-cua-driver-*`, `browser-use-*`, `lsp`, `mcp/mcp-resources`, `compaction/compaction-image-offload`, `util/lazy-require`, `api/terminal-controller`, `client/ui-sidebar-terminal`, and `experimental/auto-review` packages, moves the root version to `0.1.6-alpha.1`, adds the `docs/persistence-changes/**` release retrospective set, widens `SubprocessHandle` with a required `control` channel, tightens the Typert manifest validation to require a strict codec with a `create()` factory, deletes the `agent/session-start` event and folds its `source` field into `agent/created`, retires the design-system `IconSendOutline16` glyph in favour of the paper-plane slot, adds `mcp-client/src/server-context.ts` as the registration owner for MCP server resources and instructions, reverts the transactional Cordis reload (upstream's `Revert #932 transactional Cordis reload changes`), and deletes `scripts/verify-vendored-links.ts`.

The fork-side difficulty is that one conflict hunk can hold an upstream removal and a fork-only addition at the same time, and a census of which names appear on which side cannot tell the two apart — yet they resolve in opposite directions.

## Decision

- **A one-sided name in a conflict proves nothing; which side introduced it decides.** Two hunks in this sync look alike by that measure and resolved oppositely. `surfaceInstructions` exists on the fork side only: the fork's `packages/mcp/mcp-client/src/index.ts` grew `inject` to `['tools', 'systemPrompt']`, made the flag a required field on both transport variants with a zod default of `true`, and registered `mcp:${serverName}:instructions` from its own `ctx.effect` block — and neither the `dsh-v0.1.5-rc.2` sync point nor upstream/master has any of it. Upstream's counterpart for the same subject arrives in this release as a new file, `packages/mcp/mcp-client/src/server-context.ts`, whose `registerServerContext` registers the last connected server's instruction text as the section `mcp:<server>` at `systemPrompt.getSectionOrder('MCP_SERVERS')` with `interpolate: false`. The fork's capability is kept and upstream's file is kept as the single registration owner — two registrations of one section name would collide — so the union threads the flag through upstream's registration and leaves the flag required on both public transport configs, preserving the fork's decision that a resolved config carries the flag instead of a construction site defaulting it. By contrast `agent/session-start` was an upstream event present at the merge base that upstream deleted after folding `source` into `agent/created`; the fork's only consumer (`openviking`) migrates to `agent/created` rather than the event being restored, and the case that emitted the dead name itself now emits the live name, because an own-emitted event can never reveal a listener that rotted. That migration leaves the retired name absent from every `.ts`/`.tsx` outside build output, so a future merge cannot resurrect it silently without a case going red.
- **`mcp-client`'s two transport schemas stay parallel and are marked as deliberate repetition.** `pnpm run duplication` passes on each parent and fails only on the merged tree: the fork's `surfaceInstructions` field and upstream's new `maxInstructionBytes` field now sit between the same neighbours in both the stdio and the Streamable HTTP variant, so the run the two `z.object` literals share — `toolCallTimeoutMs` through `reconnect` — reports as a 7-line / 71-token clone against `.jscpd.json`'s `minLines: 6` and `minTokens: 60`, where each parent reports none. Each variant keeps its complete schema visible at the declaration and the exception is a source-range pragma — `/* jscpd:ignore-start */` … `/* jscpd:ignore-end */` around the union with the reason inline — the same mechanism upstream uses in `packages/ui/acp-agent/src/index.ts` for its two front-door config schemas, and it covers the `Config` declaration alone.
- **The host-face alias map stays hand-maintained.** `tsconfig.base.host.json` is not a stale copy to delete: the v0.1.5-rc.2 sync note records it as a standing convention ("The host-face alias map stays hand-maintained on each sync"). This sync adds the aliases the host face needs (`dsh-ptc-runtime`, `dsh-ptc-runtime-node`, `dsh-client-modules/client`, `dsh-api-terminal-controller`, `dsh-mcp-resources`) and removes the entries whose targets the renames deleted, and two entries that were never dangling — merely pointed at the wrong path (`api-plugin-market-controller/invariant`, `node-addon-landlock-run`) — are repointed instead.
- **The event-relations generator refused exported dispatch helpers.** `eventNamesFromParameter` returned early on `hasExportModifier(owner)`, which made the repository-wide call-site index that `callSitesFor` builds for exactly that situation unreachable for exported declarations. The fork's extraction of `collectSessionCallbacks` and `invokeContainedSessionObservers` into an exported `observers.ts` module therefore left `session/created`, `session/disposed`, `session/event`, and `session/flush` with zero dispatchers and made `gen-doc-graphs` throw. The gate is wrong here rather than the fork: an exported function is callable only from another module, which is the case the gate must not exclude. The export test is dropped while `provenLocalCallee` still decides whether the same-file fast path is sound, so the change adds call sites without inventing any, and a spec case now fails when the guard is restored.
- **The fork's Cordis reload guard keeps upstream's reverted semantics.** Upstream carries the transactional-reload revert that the fork lacked, and merged `vendor/README.md` item 8 states the pinned "eager, non-transactional" behavior. The fork's cycle guard still fires through `EntryGroup.update` → `validate()`, so an illegal config is rejected and the last good tree is retained; only the observable form changed from a rejecting `refresh()` to a logged warning. The fork-only nested-row collision case now asserts resolution, the warning, and the retained tree.
- **`better-sidebar` paired a v6-generation addon with a v5 core.** It declared `@xterm/addon-fit@^0.11.0` beside `@xterm/xterm@^5.5.0`, so pnpm's virtual-hoist directory resolved `@xterm/xterm` to 5.5.0 for `@xterm/addon-serialize@0.14.0` — which declares no `dependencies` or `peerDependencies`, leaving its declaration-level `import("@xterm/xterm")` only the hoisted copy — while `@xterm/headless@6.0.0` types the addon against 6.0.0. `packages/api/terminal-controller/src/terminal.ts:40` failed with TS2345. The pin moves to `^6.0.0`, matching `ui-sidebar-terminal`, and a single `@xterm/xterm` remains.
- **Fork-only workspace versions follow the release.** 38 fork packages still carried `0.1.5-rc.2` while the constraint gate requires every package to match the root, so all 38 move to `0.1.6-alpha.1` together with the one lockstep constant that mirrors its manifest (`SIDEBAR_SERVICE_VERSION`), and the two build-residue directories left behind by the `code-runtime-python` → `ptc-runtime-python` and `workflow-worker-thread` → `workflow-ptc` renames are removed.
- **Generated artifacts are regenerated, never hand-merged — except where build output would corrupt them.** The config catalog, module graph, client slot catalog, dependency catalog, session-format catalog, scoped events, Cordis catalog, tsconfig paths, third-party notices, and graph documents were all re-emitted from the merged tree. The persistence catalog trio and its schema were *verified* rather than re-emitted: `scripts/persistence-schema.ts` `trackedSource()` accepts `lib/types/**/*.d.ts` as a tracked source, so a built worktree rewrites every recorded pointer away from its committed `src/*.ts` form, and the accepted content is the clean-checkout content. The sync's own persistence ledger entry was authored instead, acknowledging the nineteen event roots and one optional event-body property the fork has added since the last sync point.
- **Hybrid Chinese sides follow the regenerated English through pairing.** `capability-seams.zh.md` and `event-producer-consumer.zh.md` gained the fork sections the upstream side never had, and `config-catalog.zh.md` was rebuilt by three-way merge because the conflict resolution had taken the upstream side wholesale, dropping the added Chinese lines the fork carried since the merge base (among them the fork-only sections for `patent`, `better-sidebar`, and `plugin-market`). Pair records were re-recorded with `verify-translation-pairing --write`.
- **The pairing gate alone cannot prove structural fidelity.** `verify-translation-pairing` skips its structural checks for a pair whose recorded hashes are stale, so a stale record reports only "out of sync". Structural proof in this sync came from calling the repository's own primitives directly (`translationStructureDiff`, `translationStructureSignature`, `partitionGeneratedRegions`, `hasLanguageSwitcher`, `translationLinkLocaleViolations`) and requiring zero violations.

## Consequences

The fork ships upstream's v0.1.6-alpha.1 baseline with the desktop, patent, self-evolve, synapse, plugin-market, openviking, better-sidebar, prompt-cache, ui-document-studio, ui-patent-teams, and ui-todo-board surfaces intact. The host-face alias map is again correct for the renamed and added packages, and it stays hand-maintained on each sync: a missing entry surfaces at host `tsc -b` and at documentation typecheck time. Because a stale pair record short-circuits the pairing gate's structural checks, any structural claim about a regenerated hybrid document pair needs the shared primitives, not the gate's exit status. Upstream deleted `scripts/verify-vendored-links.ts`, which was the only guard on the fork invariant that every vendored name resolves to a workspace link; nothing in the tree references the script and no other gate absorbed the check, so that invariant is unguarded until something restores it. The `agent/session-start` removal also shows the shape of the next such break: an event listener on a name upstream already retired compiles only because the event map tolerates it, so a host-face build failure naming an event is the signal to look for a superseded name rather than a missing alias. The persistence generators carry a trap this sync uncovered and deliberately did not repair: because `trackedSource()` accepts `lib/types/**/*.d.ts`, any regeneration performed in a built worktree rewrites the catalog's recorded pointers and reports a spurious diff, so those artifacts must be verified on a clean tree or after removing the offending package's `lib/`; the trap and its workaround are recorded in `docs/TECH_DEBT.md` rather than fixed here.

## Alternatives considered

- **Restore `surfaceInstructions` by reinstating the fork's own registration block, and delete the `agent/session-start` listeners.** Rejected: upstream's `server-context.ts` now owns the registration of that section, so a second registration would collide, and the two cases differ only in which side introduced the change while resolving in opposite directions. The flag is kept as the fork's contribution and threaded through upstream's registration; `agent/session-start` is an upstream event that upstream replaced with a wider payload, so its consumer migrates.
- **Keep the fork's section name and order (`mcp:<serverName>:instructions` at 155).** Rejected: the fork's note argued 155 against the band occupancy that existed when it was written, and upstream has since made MCP server context a named slot of its own (`getSectionOrder('MCP_SERVERS')`) inside the file that owns the registration. Preserving 155 would mean patching an upstream-owned file on every sync to hold a prompt-ordering preference that buys no capability, so the fork's note pair was corrected to describe the current contract instead.
- **Delete `tsconfig.base.host.json` and extend `tsconfig.base.json` directly.** Rejected: the file is documented by the previous sync note as a hand-maintained host-face map whose maintenance cost is accepted deliberately, and host programs do resolve client-face subpaths through their own package-level `tsconfig.host.json` references, so a host map that excluded all client aliases would not describe the host program that exists.
- **Re-attach the fork's cycle validation to upstream's refresh window so `refresh()` rejects again.** Rejected: upstream deliberately reverted the transactional reload, and re-rejecting would un-revert it inside a sync. The guard still rejects the illegal tree and the last good tree survives, so the protection is intact and only its observable form moved.
- **Make `surfaceInstructions` optional on the resolved config to avoid touching upstream test files.** Rejected: the resolved config carries the decision the schema defaulted, and an optional field would let a construction site silently drop the flag; the two upstream cases that build a transport config state the flag instead.
- **Extract the server-independent fields the two `mcp-client` transport schemas share and spread them into both.** Rejected: `verify-config-catalog` statically walks every schemastery schema expression and rejects a non-plain key inside `z.object({…})` (`schema object property '…' is not a plain key.`), so a spread cannot reach the config catalog at all; the shape that walk does accept, `z.intersect` with a named shared schema, would replace the two declared object schemas with composed ones to save the repetition.
- **Take upstream's Chinese catalogs wholesale and defer the fork sections.** Rejected, as in the previous two syncs: upstream's Chinese side lacks every fork-only section and the fork master's reviewed translations merge forward mechanically, so deferral would leave the documentation gates red for no translation gain.
- **Add a second `@xterm/xterm` resolution rule for `@xterm/addon-serialize`.** Rejected: the skew originates in `better-sidebar` pairing a v6-generation addon with a v5 core, and pinning elsewhere would leave a client on a core its own addon no longer matches.

## Testing

`pnpm run typecheck` (Host `tsc -b` + tsdown, Client `tsc -b`), `pnpm run lint`, `pnpm run duplication`, `pnpm run test:docs`, `pnpm run doc-sync`, `pnpm run constraints`, `pnpm run hygiene`, `pnpm run verify-package-dependencies` (69 packages), `pnpm run verify-translation-pairing`, the persistence gates (`verify-persistence-catalog`, `verify-persistence-changes`, `verify-persistence-formats`, `verify-persistence-releases`), and the affected package suites including `packages/mcp/mcp-client`, `packages/memory/openviking`, `packages/client/better-sidebar`, `packages/experimental/ptc-runtime-python`, `packages/core/session`, `packages/session/session-persistence-jsonl`, `packages/boot/app-boot`, and the `scripts/gen-doc-graphs.spec.ts` gate case. The event-relations fix was verified by restoring the `hasExportModifier` guard and observing the new spec case fail, then removing it and observing it pass. The bilingual pairs were re-recorded with `verify-translation-pairing --write`. That sweep followed a per-side drift audit: of the 44 stale records, 40 had moved on both sides and 4 — the `patent` preset README and three patent notes — on the English side alone, each because the banned term gave way to wording that names the exact field. All four Chinese counterparts were compared against the new English and state the same fact, so those records were re-taken; a one-sided drift whose moving side was retranslated must bring the other side along before any record is written. A further 24 pairs move their English against fork `master` while their Chinese side stays byte-identical to `upstream/master`'s own; those are upstream's bilingual state, where upstream re-recorded after its term cleanup without following in Chinese, so the fork mirrors it instead of diverging. `pnpm run duplication` first surfaced only in CI, since the local pre-push checkpoint runs typecheck alone; re-run against the merged tree after the pragma it reports zero clones across 2350 files, where before the pragma the same command reports one clone and exit 1, and each parent reports none — the failure belongs to neither side but to their union. `pnpm run hygiene` reports `publint` failures until the three client-face packages this release adds or renames — `dsh-api-terminal-controller`, `dsh-client-ui-sidebar-terminal`, and `dsh-client-ui-settings-unarchive-sessions` — are bundled: in a tree where only typecheck has run, `publint` reads their `lib/client.js` as missing, and the full sixteen gates pass once `tsdown` emits them. The `EXPORTS_GLOB_NO_MATCHED_FILES` finding on `./src/*`, carried by 309 packages because `files` publishes `lib/` alone, is a warning and never fails the gate.
