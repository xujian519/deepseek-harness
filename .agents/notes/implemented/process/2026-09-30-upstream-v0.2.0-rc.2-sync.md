# Agent Note: upstream v0.2.0-rc.2 sync

Status: implemented

English | [中文](2026-09-30-upstream-v0.2.0-rc.2-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.2.0-rc.1` tag to the `dsh-v0.2.0-rc.2` release: 140 commits (187 with merges) across 1022 files. The merge base sat on the rc.1 release commit, so the merge reported the 52 conflicts the two releases actually share rather than re-deriving earlier releases.

Upstream's release moved three surfaces the fork had shaped. The packaged Desktop shell gained a bundled `dsh` command (`apps/desktop-host/src/cli.ts`, `scripts/prepare-cli.ts`): plugin commands now run against the reserved Electron profile through that installation's pnpm, macOS and Linux GUI launches read the account login shell's environment before the first Host starts, and the desktop README gained both sections. Client Cordis inspect queries became bounded (a configured timeout that reports the first retained failure, and an offline fast path), with the `cordis-inspect-liveness` and `cordis-inspect-timeout` session snapshots. `ask_user_question` gained a timed mode whose late answers arrive as a qualified `user-question-reply` message source, acknowledged by the persistence record `2026-09-21-user-question-reply`. Due Schedule reminders became scheduled user messages, and the upgrade-guide tree arrived with its own skill and `verify-upgrade-guides` gate.

The fork owns the Electron runtime profile directory (`profiles/desktop-runtime`), the `@deepseek-ai/cordis/...` event names, the `dsh-timeout-guard` package name, and its patent, self-evolve, desktop, better-sidebar, and plugin-market surfaces.

## Decision

- **Version, pins, and generated artifacts move with the release.** The 46 fork-only manifests and `SIDEBAR_SERVICE_VERSION` join the root's `0.2.0-rc.2`; the nine `snapshots/acp/*/stdout.expected.jsonl` pins follow, because `agentInfo.version` derives from the acp manifest. Every generator ran on the resolved tree (`gen-tsconfig-paths`, `gen-cordis-catalog`, `gen-client-catalog`, `gen-cordis-inspect-catalog`, `gen-tool-catalog`, `gen-config-catalog`, `gen-persistence-catalog`, `gen-doc-graphs`, `gen-module-graph`, `gen-plugin-packages`, `gen-dependency-catalog`, `gen-session-format-catalog`), and `pnpm run verify-no-unknown-casts --prune` retired ten stale baseline entries.
- **The bundled Desktop command manages this tree's Electron profile by its own name.** Upstream admits plugin commands for the profile named `desktop`. The fork's Electron profile directory is `profiles/desktop-runtime`, so `apps/cli/src/args.ts` exports `ELECTRON_PROFILE_NAMES` (`desktop` and `desktop-runtime`) with `isElectronProfile`, the parser canonicalizes either name, and `plugin.ts` takes its reserved-profile branch on the predicate: the same initialization guard, shared profile write lock, and bundled pnpm now apply to the directory the Electron shell actually owns. `apps/desktop/README.md` and `apps/cli/README.md` name the profile the bundled command reaches.
- **The desktop shell keeps the fork's mac block and adopts upstream's adjacent additions.** The unsigned-darwin guard, the beside-archive Office entry, and the tray wiring stay the fork's; `signMacOSRuntime`'s new `target.arch` argument, `desktopTargetPlatform(targetName).arch`, the login-shell environment (`hostEnvironment`, `prepareHostEnvironment`), and `DSH_DESKTOP_BRIDGE_PATH` travel together in `prepare-dsh.ts` and `main.ts`.
- **The fork's event rescope reaches upstream's new fixtures.** The authored `cordis-inspect-liveness` and `cordis-inspect-timeout` fixtures subscribed to `cordis/inspect-query` and `cordis/inspect-query-resolved`; both now use the `@deepseek-ai/cordis/...` names the runner emits, as does the new `tests/inspect-registry.spec.ts`. Without that, the fixtures never answered and the scenarios diverged until the replay script ran out.
- **Persistence history chains across the sync.** Upstream's `2026-09-21-user-question-reply` and the fork's `2026-09-22-fork-source-attribution` both acknowledged the same four roots, which the history validator rejects as a fork. The fork's record now declares upstream's record as its predecessor and was re-derived from the merged tree with `persistence-changes --update`; the merged schema carries both `user-question-reply` and the fork's three attribution kinds, so each transition stays same-version.
- **Two authored compaction snapshots were re-calibrated.** Their trigger sits between a history and its condensed replacement, and upstream's longer `bash`, `pwsh`, and `ask_user_question` descriptions raised the estimated context. Their model `contextWindow` moved from 8,382 to 8,520, and the recorded `request/context` fact and both explanatory comments follow.
- **The Host type-check budget rises with the fork's own tree.** Upstream allots the Host program 4 GB, which the fork's larger program no longer fits: a cold `tsc -b tsconfig.host.json` on the merged tree aborts in mark-compact with `Ineffective mark-compacts near heap limit` where the pre-merge commit `f2b2c524cc` completes, and 4,608 MB completes on the merged tree. `build:lib:host` and the Wine Host compile now run at 6,144 MB, and `scripts/ci-workflow.spec.ts` records that budget in the Wine command it pins. The Client program stays under Node's default ceiling unchanged.
- **The remaining conflicts resolve as unions.** `scripts/check-workspace-constraints.ts` takes `lib/cli.js` beside the fork's `config/desktop.cordis.patch.yml`; `scripts/run-gates.ts` keeps the fork's mode set (no `ci-snapshot`/`ci-artifacts`) and adopts `ci-unit`, which the fork's spec now exercises in place of its removed `ci-artifacts` entry; `packages/client/ui-tool/package.json` adds `dsh-user-questions` to the fork's dependency list; `packages/interaction/user-questions/src/index.ts` keeps the fork's shared `isRecord` import beside upstream's timed-wait imports; `packages/client/ui-commands/src/client/popup.ts` keeps the fork's `errorMessage` import beside upstream's search helpers; `packages/extensions/cordis-host-runner/src/{index,inspect-registry}.ts` keep `assertResolvedConfig` and the namespaced events while taking upstream's timeout plumbing; `packages/client/ui-theme/tests/expected/radius-exceptions.expected.json` gains upstream's `ui-deliverables` rows.
- **The generated pages are regenerated, and the Chinese pages that no generator writes are updated with their English side.** `docs/tool-catalog.zh.md` receives upstream's four tool-descriptions changes; the desktop, CLI, better-sidebar, and tool-ask-user pages carry the upstream additions; `pnpm run verify-translation-pairing --write --all` re-records the changed pairs, and `verify-persistence-formats --write` refreshes the format index.

## Consequences

The fork ships upstream's v0.2.0-rc.2 baseline with its patent, desktop, self-evolve, and better-sidebar surfaces intact, and the history stays connected: `git merge-base HEAD dsh-v0.2.0-rc.2` is the release commit, so the next sync reads the real conflict set. Three divergences now need attention at each release: the CLI reserves the fork's Electron profile name, which upstream's desktop statements do not know; the Host type-check budget is 6,144 MB where upstream's root script and Wine gate carry 4 GB; and the two authored compaction snapshots re-calibrate whenever a model-facing tool description changes size.

`pnpm run doc-sync` reports 46 passing gates and the two failures the rc.1 sync already recorded: `verify-package-paths` still finds stale references to the deleted `packages/patent/patent-workflow/src/approval.ts` and `quality-gate.ts` in three Agent Notes and `docs/patent-workbench-tasks.md`, and `docs:build` still fails to compile the generated `tool-catalog.md` because fork-owned patent tool descriptions carry raw `<writing_skills>` text that Vue reads as an element. Neither is this sync's.

## Alternatives considered

- **Mapping the reserved `desktop` name onto the fork's directory inside `resolveProfileDir`.** Rejected: it changes a public app-boot lookup that every profile name resolves through, while the additional name keeps upstream's reserved name and its statements untouched.
- **Leaving the bundled command's documentation at `--profile desktop`.** Rejected: that path is initialized by neither the Electron shell nor any CLI profile in this tree, so the documented flow would fail with an initialization error.
- **Deleting upstream's `2026-09-21-user-question-reply` record instead of chaining.** Rejected: the record documents a shipped upstream transition, and the history validator accepts the chain, which keeps both acknowledgements.
- **Re-recording the compaction scenarios instead of re-calibrating them.** Rejected: the recorder skips authored fixtures by design, and the fork's earlier calibration commit took the same context-window route.
- **Raising the ceiling only inside the fork's CI workflow.** Rejected: `build:lib:host` passes `--max-old-space-size` on the command line, which wins over `NODE_OPTIONS`, so the lane would have to stop running the documented build command to get a larger heap.
- **Keeping upstream's `ci-artifacts` mode so its spec entry compiles unchanged.** Rejected: no fork workflow invokes that aggregate, and the fork removed it deliberately with its `check:ci:*` script.
