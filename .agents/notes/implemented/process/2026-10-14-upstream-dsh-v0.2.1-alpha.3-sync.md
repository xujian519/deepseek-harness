# Agent Note: upstream dsh-v0.2.1-alpha.3 sync

Status: implemented

English | [中文](2026-10-14-upstream-dsh-v0.2.1-alpha.3-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.2.1-alpha.2` tag to `dsh-v0.2.1-alpha.3`: 852 commits, 3,311 files, +120,978/−16,632 lines. The merge base sat on the alpha.2 release merge, which the previous sync landed as a merge commit (PR #381), so one `git merge` reached the tag and no upstream commit was re-derived. `git merge-tree` predicted 132 conflicting files, against 276 for alpha.2.

The fork carries content the release does not — 48 package manifests, the `dsh-timeout-guard` rename, the `apps/desktop` branding layer, `workflows-disabled/`, and roughly 60 packages including the patent, self-evolve, better-sidebar, plugin-market, and document groups — so the merge has to absorb the release without dropping any of it.

The previous sync's lesson was that a three-way merge resolves shared files quietly, and that only running the suite over the merged tree reports what it dropped. This release added a fourth shape to that lesson: **a merge can drop an entire upstream feature from a file it never marked as conflicted, and the resulting tree compiles.** `packages/core/tools` is the case. The release threaded a `Context` into `createRunCodeTool`, added `PtcCalls` to cancel in-flight programs when the sandbox policy changes, and keyed retained PTC environments per Agent through a `stateOwner` argument. The merge added `ptc-calls.ts` and left `ptc.ts` on the fork's older body, so the package shipped a module with no importer, a `run_code` tool that never passed `stateOwner`, and a `run-code-flavor.ts` whose text the release had replaced with a language-parameterized factory. `tsc`, `lint`, `build`, and 51,970 passing tests all read the tree as healthy. The signal came from a translation gate: `docs/tool-catalog.zh.md` carried the release's new `run_code` description against a generated English page that still held the old one, and the English page is a projection of the source.

## Decision

- **The sync branch merge-forwards the release tag.** `sync/upstream-dsh-v0.2.1-alpha.3` carries the merge, and the PR lands it as a merge commit whose first parent is the fork's `master`. A squash would remove upstream's commits from the fork's graph and push the next sync's merge base back to the previous tag.
- **Conflicts are resolved by class, never by line range.** Side-taking by line range preserved shared lines that held for only one side in the alpha.2 sync, leaving imports in the surviving region and their uses in the deleted one.

  | Class | Count | Resolution |
  |---|---|---|
  | `.i18n.yaml` sidecars | 21 | Take the release's, then `verify-translation-pairing --write` |
  | `snapshots/**` | 13 | Take the release's, then refresh |
  | `package.json` manifests | 24 | Union |
  | Markdown | 29 | Regenerate the generated pages; hand-merge the authored Chinese counterparts |
  | Source `.ts` | 18 | Per file: the fork's version, then the release's change edited into it |
  | Generators, lockfile, tsconfig | 27 | Union, then re-run the generator |

- **The merge keeps the fork's divergences.** `dsh-timeout-guard` (upstream `dsh-tool-call-timeout-policy`), `workflows-disabled/`, the `apps/desktop` branding layer (`DSH_DESKTOP_PRODUCT_NAME`, `DSH_DESKTOP_ICON_DIR`, `mac.signIgnore`, the Office engine beside the archive), `coldReadConcurrency` in `packages/subagent/subagent/src/list-children.ts`, and every fork-only package group.
- **The release's Host heap ceiling does not fit the fork, so the fork's returns.** `scripts/compile-referenced-projects.ts` arrives with the release and pins the Host aggregate to `--max-old-space-size=4096`. The fork's Host aggregate is larger than the release's — the fork's own groups sit on top of the release's new `cua`, `cua-macos`, `remote-access`, `harness-dev-context`, and `ui-secret-mask` compiler faces — and it peaks near 5.5 GB on a clean tree, so every lane that type-checks or builds from a fresh checkout exhausted the heap. `hostHeapArgs` returns the fork's 6144, the ceiling `package.json`'s `build:lib:host` already gives the same program.
- **The release's PTC cancellation and state-owner wiring is ported, not restored.** `ptc.ts` gains `PtcCalls(ctx)`, the `stateOwners` weak map keyed by Agent, the `stateOwner` argument on `runtime.resolve`, and the `run(callSignal)` closure that resolves the sandbox mode lazily; `index.ts` threads its `Context` into `createRunCodeTool`. `run-code-flavor.ts` adopts the release's parameterized factory, which names only this package's call rules and leaves evaluation syntax, output rules, and state retention to `PtcRuntime.executionInstructions`. This was also the root cause of the `ptc-persistent` replay failing: with no `stateOwner`, the runtime never retained the environment per Agent, so a second `run_code` could not read the value the first one set.
- **The release's Office progressive loading lands; the fork's Office chain stays.** `packages/skill/skill-office` takes the release's routing skill plus `office-render`, `office-recalculate`, and `office-export-pdf`, and the Python runtime's `_resources.py` drops its `check_office.py` entry. `build_patent_filing` and `verify_patent_filing` remain the native DOCX path, `render_doc_template` remains the template path, and both presets still route to officecli for the work the fork's own engines do not cover. `check_office.py` had no fork consumer — only its own SKILL.md files, its tests, and the runtime's require list — so the merge accepts the deletion.
- **`docs/defensive-patterns.md` becomes a directory and its inbound references move with it.** The release splits the page into a README router plus `general.md`, `package-surface.md`, `remote-and-api.md`, `client-components.md`, and `conversation-and-session.md`. `AGENTS.md` and the four skills that cite it are repointed. The nine remaining references are inside `archived/` notes, which are sealed against content edits and skipped by the documentation gates.
- **The gates the release tightened are satisfied rather than waived.** `verify-package-dependencies` gains a rule that `@types/react` and `@types/react-dom` are declared only in the root manifest, because each package-local pnpm link is one more location TypeScript scans for every JSX file; the five fork client packages that declared them locally drop the entries, and `pnpm-lock.yaml` loses the 21 corresponding lines. `rescope-vendor` gains the release's `v0.2.1-alpha.1` preset-composition upgrade guide as a site naming the `cordis` **delegation tool** rather than the package, alongside the preset-id sites the alpha.1 and alpha.2 syncs recorded.
- **The persistence history fork is reconciled by a new record.** The release's `2026-10-13-user-rpc-principal` artifact describes its own shape for four roots the fork also carries, and that shape has none of the fork's attribution source kinds. `docs/persistence-changes/2026-10-14-alpha3-sync` chains after it and registers the shape the merged tree actually has, with the fork-only `event:self-evolve/mined` following `2026-09-16-upstream-sync`. Every difference is additive and same-version: a reader that predates the added kinds still renders the messages that carry them.
- **Mechanical alignment.** The root manifest, 47 fork-only manifests, and `SIDEBAR_SERVICE_VERSION` move to `0.2.1-alpha.3` across 388 manifests with no version behind; `pnpm install --lockfile-only` changes `pnpm-lock.yaml` only for the type-package removal above. Nine `snapshots/acp/*/stdout.expected.jsonl` files re-pin `agentInfo.version`. The `verify-test-skips` and `no-unknown-casts` baselines are re-recorded (the latter pruning five entries the release retired), and `docs/TECH_DEBT.md`'s counters are updated.
- **The deleted-file sweep runs against the fork-only configuration.** The release deletes 18 files. Every fork-only `vitest.*.config.ts`, `lefthook.yml`, workflow, and `tsconfig*` was grepped for each deleted path and for each deleted basename; none names one. That is the check the alpha.1 sync lacked when the release's Vitest-config cleanup orphaned `vitest.race-stress.config.ts` and 71 test files failed collection.

## Consequences

The fork ships upstream's v0.2.1-alpha.3 baseline with its patent, self-evolve, desktop, better-sidebar, plugin-market, and document surfaces intact. The unit suite reports the two failures the Testing section names, both of which are red on this host before the sync and belong to no file this merge touches.

The lesson this release adds is that "the merge compiled" is not evidence a shared file kept the release's content. `packages/core/tools` compiled in every gate and had lost a feature. Nothing in the merge's exit status, in `tsc`, or in the suite distinguishes that from a clean merge; the distinguishing artifacts are the generated pages, which project the source and therefore carry the source's own drift. Reading a generated page's diff against its hand-written counterpart is now the cheapest detector for it.

Three divergences still need attention at each release, unchanged from the previous sync: the fork's presets are the merge's landing place for upstream's composition changes, the archived-note seals must match upstream's for the notes it retires, and the fork's notes must track upstream's workflow paths into `workflows-disabled/`. The fourth the alpha.2 sync added — that the fork's own manifests name packages the release may move into `experimental/` — did not recur this release.

The fork's `ptc-runtime-python` still does not carry the release's sandbox support or its stdin bootstrap; the split into `config`/`supervisor`/`output-ledger`/`frame-reader` modules and upstream's single `index.ts` with file-confinement policy remain unreconciled, exactly as the previous sync recorded. Absorbing that confinement is still its own change.

## Alternatives considered

- **Re-resolving the merge conflict by conflict without naming the checks first.** Rejected: the alpha.2 sync's losses were in files the merge auto-resolved, and this release's PTC loss was in a file the merge never marked. Naming the orphan-reference, silent-loss, and generated-page checks before the merge is what makes them run.
- **Rebasing the fork's commits onto the release instead of merging forward.** Rejected: the fork's divergence is an ongoing set of decisions — the timeout-guard rename, the desktop branding layer, the archived workflows — not a patch series to reapply. A rebase re-derives each one at every release, and the previous sync's merge base is what lets one merge reach the next tag.
- **Adopting the release's `apps/desktop` packaging and updating the fork's specs.** Rejected: the branding parameters are shipped, documented fork behavior with an Agent Note, and the fork's local packaging recipe depends on them.
- **Keeping `check_office.py` beside the release's progressive-loading skills.** Rejected: nothing in the fork calls it, its own SKILL.md files are replaced by the release's routing skill, and carrying it means maintaining Python that no test in the merged tree exercises.
- **Restoring the fork's `run_code` flavor text instead of porting the release's factory.** Rejected: the fork's text restated evaluation syntax, output rules, and state retention that `PtcRuntime.executionInstructions` already supplies, so the model received the same instructions twice and the two copies could drift.
- **Adding a repository gate that compares a generated page against its hand-written counterpart.** Rejected for this sync: the pairing gate already reads both sides, and a new gate would report the same class of drift a second time. The mechanism that found the PTC loss is the existing translation pairing check, not a new one.

## Testing

`pnpm run test` reports 2 failing cases in 51,970 passing, one expected fail, and 218 skipped (52,191 total). Both failures are red on this host before the sync and belong to no file this merge touches: `packages/util/http-proxy/tests/install.spec.ts` (an `origin.test` lookup that does not resolve here) and `packages/subprocess/subprocess-local/tests/spawn-runner.spec.ts` (the launching shell exports `NoDefaultCurrentDirectoryInExePath`, which CI does not). The two `ui-trajectory` cases the previous sync carried as residual gaps now pass: the release rewrote that package's request-status model, which is what they were asserting against.

`pnpm run test:snapshot` replays 223 keyless cases across the session, sdk, acp, and web lanes with 2 skipped and no failures. Three scenarios needed their job ids re-tokenized after `test:snapshot:refresh` wrote raw values into a committed normalization fixed point.

`pnpm run typecheck` exits 0 on both compiler faces, `pnpm run lint` exits 0 with one non-fatal unused-disable warning, `pnpm run build:artifacts` and `pnpm run build:check` exit 0, and `pnpm run duplication` reports 0 repository-wide clones. `pnpm run constraints` passes with one version across the family, and `pnpm exec tsx scripts/release/verify.ts --family dsh` resolves 384 members at `0.2.1-alpha.3` with the publish order resolved and no unordered peer declaration. `pnpm run hygiene` reports all 21 gates passing; two were red on the merged tree and are fixed in this sync, both on material the release made this sync own: `rescope-vendor` on the release's preset-composition upgrade guide, and `verify-package-dependencies` on the five fork manifests that still declared the type packages the release moved to the root. `pnpm run doc-sync` reports 50 of 51 gates passing. The one failure is `verify-repository-references`, and it is an artifact of a full-history clone rather than a defect: `python/sdk/uv.lock` records a byte size `6344383` whose hex prefix matches an object that exists in this clone, and the gate's own contract states that an object absent from a shallow history cannot match. CI's shallow clone cannot see that object, so it cannot report the line.

CI's first run against this branch was red in five lanes, and every one of them failed in the same place: `tsc` on the Host aggregate, out of heap. Four lanes died inside `pnpm run build` and one inside `pnpm run typecheck` — the cold-tree shape of the ceiling the Decision section restores. The heap restoration is the whole repair: on a clean tree the same commands now pass, with the Host aggregate peaking near 5.0 GB.

The second run greened every lane but the assembled Web drivers. The release added the `minimal-compact` and `minimal-read-image` cases and the `subagent-fork-schedule` driver, and recorded their goldens from its own client plugins. The fork mounts its own on top — the `Deliverables`, `Board`, and `Teams` tabs from `ui-document-studio`, `ui-todo-board`, and `ui-patent-teams`, and the `market_*` catalog tools plus the `Plugin Catalog Discovery` system-prompt section from `tool-plugin-market` — so four goldens had to be re-recorded from the fork's own bundles: the two new ARIA goldens, and the `fresh-round-trip` system-prompt and tool-schema pins that the new driver reads. `pnpm run test:web:built snapshot` reports 5 drivers and 15 cases passing. The lane's other 158 files stay out of CI, 67 of them red on `master` against the same class of drift, which `docs/TECH_DEBT.md` already registers as its own repair.
