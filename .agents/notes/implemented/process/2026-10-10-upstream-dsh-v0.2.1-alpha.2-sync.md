# Agent Note: upstream v0.2.1-alpha.2 sync

Status: implemented

English | [中文](2026-10-10-upstream-dsh-v0.2.1-alpha.2-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.2.1-alpha.1` tag to `dsh-v0.2.1-alpha.2`. The merge base sat on the alpha.1 release merge, so the merge read the real conflict set — three conflicts, all in generated files (`docs/tool-catalog.i18n.yaml`, `docs/tool-catalog.zh.md`, `scripts/preset-divergence-baseline.json`) — and no upstream commit was re-derived.

A three-way merge cannot reconcile two sides that each changed the same file in different places when one side's change is structural. This merge resolved a set of shared files to the incoming side and left the fork's side of them behind, and it migrated several production call sites without moving the specs that stub them. Nothing in the sync process ran the unit suite over the merged tree, so the loss was invisible: `pnpm run test` reported **141 failures across 24 files**, every one reproducible from the merge commit.

Two further shapes of loss came with the release. The release moved five packages (`skill-badge`, `tool-ralph`, `hook-protocol`, `hooks-claude-code`, `hooks-codex`) into `packages/experimental/`, retired `backgroundMode`, and replaced the fork's `subagent/continuation.ts` with its own managed-activation `manager.ts`; the fork's manifests, presets, and docs still named the old shapes. And the release added gates the fork had never satisfied (`verify-product-use`, `verify-plugin-record-callers`, `verify-default-product-isolation`, `verify-runtime-closure`) plus a stricter `publint`.

The sync also landed on the wrong base. It was committed onto a `master` that stopped at PR #377, while `origin/master` had advanced 16 commits through #380.

## Decision

- **The sync branch merge-forwards `origin/master` before review.** `sync/upstream-dsh-v0.2.1-alpha.2` carries the merge and its fixes, then merges `origin/master`, so the PR reads against the fork's current master and the review sees the 16 patent commits as ordinary history rather than as an absence. Three generated files resolve to the incoming side there and are regenerated after.
- **The dropped fork content is restored, not re-derived.** `packages/subagent/subagent` regains the `coldReadConcurrency` field and its `listDescendants` argument; the root manifest regains 19 gate registrations and the larger host-build heap; `packages/bundle/web-app` regains the patent and document preset guides, their patch sheets, `skills`, and both bundle-patch entries; `gen-tool-catalog`'s `document_deliver` recipe stops mounting `LocalFileSystem`, which the release's shared harness now owns. Each restoration is the fork's own earlier commit replayed onto the release's structure, not a re-invention.
- **The release's own changes are followed where the release made them.** `backgroundMode` leaves the fork's own preset layers with the upgrade guide that retires it; the shared preset layers lose the codex/claude-code/ralph rows and the `{{cwd}}` suffix the release removed; the five packages the release moved into `experimental/` lose every release-member dependency on them, and the fork's `document` preset stops mounting `tool-ralph` directly, because the release reaches that tool through `dsh-experimental-ralph-bundle` in `OPTIONAL_BUNDLES`. The preset-divergence baseline is re-recorded for the resulting 24 rows.
- **`apps/desktop` keeps the fork's release branding and Office placement.** The Agent Note `2026-09-09-desktop-release-branding-parameters` names these as shipped fork behavior: `DSH_DESKTOP_PRODUCT_NAME` and `DSH_DESKTOP_ICON_DIR` with fail-loud validation, the application icon set under `apps/desktop/assets`, and the Office engine beside the archive so its conversion helper reads real filesystem paths with real modes. All are restored on the release's own structure, including `mac.signIgnore` and both runtime mappings' engine exclusions. `mac.identity` keeps the release's ad-hoc `'-'` for unsigned builds: the fork had chosen `null`, but the release added ad-hoc signing with the reason that a modified Electron executable needs it to run, and the packaging specs pin that behavior. Two merge defects fall out of the same file: a duplicated `mac.extendInfo` key was silently dropping `CFBundleLocalizations`.
- **Specs move to the API the fork's production code calls.** patent-teams, self-evolve, and subagent specs stub `startActivation` instead of the retired `start`/`startContinuable`; real-Loader compositions and inline contexts mount `workingDirectory`, which `SubagentRuntime` now injects. `gen-tool-catalog.spec.ts` expects the multiset union of both sides' tool names rather than the merge's triplicated literal, and the deprecated `one-shot` traversal case follows the release's model, where a local activation settles as `continuable`.
- **The persistence history fork is reconciled by a new record.** The fork's `2026-09-22-fork-source-attribution` and the release's `2026-10-05-working-directory-attribution` each named `2026-09-21-user-question-reply` as their predecessor for four roots. The release's record now follows the fork's, and `2026-10-10-fork-attribution-resync` acknowledges the union the merged tree carries, because neither predecessor's schema snapshot described it.
- **The gates the release added are satisfied rather than waived.** Eleven fork packages plus `dsh-im` gain explicit roles in `PRODUCT_PACKAGE_POLICY` — each naming the composition that mounts it — so `verify-product-use` reads their absence from the default product as a declared role instead of a gap. `verify-plugin-record-callers` follows the declaration into `session.ts`, where the fork's refactor moved it, and admits the entry that re-exports it. `rescope-vendor` gains the release's `optional-bundle-transitions.e2e.ts` site, which names the `cordis` preset id rather than the package. `publint` ignores the nested-manifest warning for a `package.json` shipped inside a skill's `templates/` tree: it is example data the creator copies to a real package root, and Node never resolves through the published copy.
- **Three gates raise the `git ls-files -z` buffer past Node's 1 MiB `execFileSync` default.** `verify-concrete-terms`, `verify-public-repository-links`, and `rescope-vendor` all crashed with ENOBUFS once the tracked-file list crossed that ceiling. The release's own copies carry the same default, so the ceiling is a scale limit rather than a fork divergence.
- **Authored pages are brought along, not regenerated.** `docs/tool-catalog.zh.md` receives the release's two package rows and its two package sections, and its `Source` links and verbatim schema blocks are aligned with the generated English page — six distinct package paths had moved. `docs/capability-seams.zh.md` receives the four service rows the release added, and its diagram and rows are realigned to the generated page. `verify-persistence-formats` and the pairing records for every page this sync edited are re-recorded.

## Consequences

The fork ships upstream's v0.2.1-alpha.2 baseline with its patent, self-evolve, desktop, better-sidebar, plugin-market, and document surfaces intact. The unit suite goes from 141 failures to the count in the Testing section, and the residual failures are named there rather than fixed here.

Three divergences now need attention at each release, unchanged from the previous sync: the fork's presets are the merge's landing place for upstream's composition changes, the archived-note seals must match upstream's for the notes it retires, and the fork's notes must track upstream's workflow paths into `workflows-disabled/`. A fourth joins them: the fork's own preset layers and manifests name packages the release may move into `experimental/`, and the three isolation gates read every such name.

The fork's `ptc-runtime-python` still does not carry the release's sandbox support or its stdin bootstrap. The fork split that runtime into `config`/`supervisor`/`output-ledger`/`frame-reader` modules while the release kept one `index.ts` and added a file-confinement policy to it; the merge kept the fork's split and the release's `py/` scripts, which do not fit it. The package is restored to the fork's own consistent state and `snapshots/session/ptc-python-read-only` is removed, because that scenario exercises the release's read-only sandbox semantics. Absorbing the release's confinement into the split runtime is its own change.

`packages/subagent/subagent/src/continuation.ts` no longer exists: the release's managed-activation rewrite replaced it with `manager.ts`. The debt ledger's god-file inventory and the split plan note now name the successor.

## Alternatives considered

- **Re-resolving the merge conflict-by-conflict instead of restoring the fork's commits.** Rejected: the merge had already been committed and reviewed, and the losses are not in the conflicted files — they are in shared files the merge auto-resolved. Replaying the fork's own commits onto the release's structure produces the same content, with each original change reviewable as its own commit.
- **Adopting the release's desktop packaging layer and updating the fork's specs.** Rejected: the branding parameters are shipped, documented fork behavior with an Agent Note, and the fork's local packaging recipe depends on them. Adopting the release's icons would have removed `DSH_DESKTOP_ICON_DIR` and the Office beside-archive placement, both of which the fork uses.
- **Keeping the fork's `startContinuable` call sites and the release's spec fixtures separate.** Rejected: the release replaced the continuation manager outright, so the fork's call sites cannot run against it. Migrating the callers and their stubs together is what makes the merged tree coherent.
- **Recording the new gates' failures instead of satisfying them.** Rejected for the isolation gates: each names a real dependency the release removed, and following the release there is a two-line manifest change. The `publint` filter is the one exception, and it is narrow: it names a message code and a path shape rather than disabling a rule.
- **Chaining the persistence records the other way.** Rejected: the fork's record is older and was committed first, so the release's record is its successor; and neither order makes an existing schema snapshot describe the merged tree, which is why the new record exists either way.

## Testing

`pnpm run test` reports 5 failing cases in 49,913 passing, one expected fail, and 217 skipped. Three were already red on this host before the sync and are not this branch's surface: `packages/util/http-proxy/tests/install.spec.ts` (an `origin.test` lookup that does not resolve here and fails alone), `packages/subprocess/subprocess-local/tests/spawn-runner.spec.ts` (the launching shell exports `NoDefaultCurrentDirectoryInExePath`, which CI does not), and `packages/client/ui-trajectory/tests/views.client.spec.tsx`. Two are residual gaps this sync carries rather than fixes: that trajectory case and `packages/client/ui-trajectory/tests/table.client.spec.tsx` both assert the release's request-status model against the fork's extracted `RecordInspector`, and both mount the plugin through its built client bundle, so a source edit does not reach them without a rebuild. The other 21 files the first run reported are fixed in this sync: 62 cases in `patent-teams`, 26 in `self-evolve`, 8 in `subagent`'s descendant listing, 8 in `ci-workflow`, 5 in the tool catalog, plus the packaging, session, and connection specs named in the Decision section.

`pnpm run test:snapshot` replays 204 keyless cases across the session, sdk, acp, and web lanes with 2 skipped. Two compaction scenarios stay red because their replay scripts supply three model calls where the fork's composition makes a fourth, and re-recording them needs `pnpm run test:snapshot:record` with `DEEPSEEK_API_KEY`; they are red on the pre-sync fork tree as well, so the composition and not this merge is the cause.

`pnpm run typecheck` exits 0 on both compiler faces, `pnpm run lint` exits 0 with one non-fatal unused-disable warning, and `pnpm run build` exits 0 while recording 371 client artifacts. `pnpm run constraints` passes with one version across the family, and `pnpm exec tsx scripts/release/verify.ts --family dsh` resolves 379 members at `0.2.1-alpha.2` with the publish order resolved.

`pnpm run doc-sync` reports 49 of 49 gates passing, and `pnpm run hygiene` reports 20 of 20. Both sets were red before this sync's fixes and on material this sync owns: 11 doc gates failed on stale generator output and on the paths the release moved, and 5 hygiene gates failed on the release's new isolation checks. `pnpm run duplication` reports 0 repository-wide clones.
