# 现有技术检索

检索先于结论。任何新颖性/创造性判断必须先完成检索并引用对比文件；本技能产出可追溯的检索报告与对比文件集。

## 作业步骤

1. 从交底书理解提取检索要素：技术关键词、同义词、IPC 分类号（可用 patent_kg_query 或 ipc 分类辅助）、申请人/发明人。
2. 构建多组检索式（关键词 + 分类号 + 布尔），覆盖中国（CNIPA）与全球（Google Patents / Espacenet）两个检索面。
3. 检索式先用 ask_user 向用户确认（或至少说明取舍理由），再执行。
4. 执行检索：patent_search 查专利公开（nuo 引擎）、web_search 补充、paper_search 查学术文献；对候选用 patent_metadata / patent_legal_status 补公开日、申请日、法律状态。
5. 结果落盘：`01-检索/YYYY-MM-DD_<主题>.md` 保存检索式、数据来源、检索日期、覆盖范围、命中与取舍理由。
6. 遴选对比文件并编号 D1/D2/…，重命名为 `02-对比文件/D1_<公开号>.pdf`（pdf 转 txt 后留原文）。

## 硬规则

检索未覆盖的领域（分类号、日期范围、数据库）必须显式列出；"未检索到"不等于"不存在"，未覆盖的领域不得下新颖性/创造性结论。

## 检索报告模板

每份报告写明：检索主题、检索式（逐条）、数据来源、检索日期、覆盖范围、命中概况、对比文件遴选理由、未覆盖领域清单。

## 质量门禁

每篇对比文件的公开日须早于目标申请日/优先权日（有 web_fetch 时打开原文核验，不信摘要）；关键事实（公开日/法律状态/申请人）双源交叉（Google Patents + CNIPA 互证）。
