# 专利无效宣告意见 / 无效请求书 — 版式惯例（Conventions）

> 生成或修改本模板前必读。与 `checklist.md` 配套。

## 1. 文书结构（固定顺序）

1. 页眉（所名 + 密级）
2. 文书抬头（类型徽标 / 标题 / 意见编号）
3. 案件信息表（涉案专利号 / 专利名称 / 授权公告日 / 专利权人 / 请求人 / 分析日期）
4. 一、总体立场
5. 二、涉案专利权利要求分析（特征分解表）
6. 三、证据清单
7. 四、无效理由（按法条逐条组织）
8. 五、逐权利要求无效结论
9. 六、引用日志
10. 七、结论与请求
11. 落款 + 免责声明 + 页脚

## 2. 无效理由法条体系

| 法条 | 适用场景 |
|---|---|
| A22.2 新颖性 | 权利要求全部特征被一篇现有技术单独公开 |
| A22.3 创造性 | 权利要求相对于现有技术结合显而易见 |
| A2/A25 客体 | 属于科学发现、智力活动规则等 |
| A26.3 充分公开 | 说明书未清楚完整地公开技术方案 |
| A26.4 清楚支持 | 权利要求不清楚、 unsupported、超范围概括 |
| A33 修改超范围 | 修改后的权利要求超出发明原申请公开范围 |
| A20.2 必要技术特征 | 独立权利要求缺少必要技术特征 |
| A31.1 单一性 | 多项发明不属于同一发明构思 |

### 2.1 从属权利要求的法条路径

从属权利要求的技术方案是所引用权利要求的全部技术特征与附加技术特征的组合；判断其新颖性、创造性时比对的是**全部**技术特征。

- **不得以附加技术特征被公开为由认定从属权利要求不具备新颖性。** 所引用的权利要求相对某篇对比文件具备新颖性时，该对比文件未公开其全部技术特征；从属权利要求包含这些未公开特征，相对同一篇对比文件同样具备新颖性。以「附加特征已被该篇公开」主张从属权利要求不具备新颖性，与引用权利要求的结论自相矛盾。
- **从属权利要求与其引用的权利要求使用同一法条路径。** 引用权利要求以 A22.3 主张的，从属权利要求以 A22.3 承接，结论写「在引用权利要求不具备创造性的基础上，权利要求 X……不具有创造性」。
- 附加技术特征无对比文件直接覆盖时，主张其为公知常识或本领域常规技术选择，按 §3 四段式给出事实与理由；不得替换为「本项无覆盖」「无效前景有限」一类己方评估。

## 3. 无效理由四段式

每个无效理由按以下结构组织：

1. **事实认定**：涉案专利权利要求/说明书对应内容。
2. **证据分析**：D1/D2/公知常识证据的公开内容 + pin-cite。
3. **法条适用**：引用具体法条及审查指南章节。
4. **结论**：权利要求是否无效。

## 4. 证据时间线

- 对比文件公开日必须早于涉案专利优先权日/申请日。
- 中间文件（P）的公开日介于优先权日与申请日之间。
- 冲突申请（E）的相同申请人/同日申请单独标注。

## 5. 逐权利要求结论表

- 结论三档：可无效（证据充分）、可无效（存疑）、难以无效。
- 法条依据写法：`A22.2`、`A22.3`、`A26.4` 等。
- 从属权利要求应说明引用关系。

## 6. 视觉与版式纪律

- 沿用 `assets/templates/patent/tokens.css` 品牌变量；agent 不改样式。
- 表格数字列使用 `tabular-nums`。
- 无证据支撑的法条适用结论降级为「模型推断」或「假设」。

### 6.1 对外提交件与内部记录的分离

本模板产出对外提交件。下列内容属内部工作记录，不得出现在正文任何章节：

- 引用核验记录、法条与判例的 source_path 清单
- 待填项、待办清单、交付前检查项
- 己方证据缺口汇总、成功率分档、最坏情形说明
- 修订记录、增量修订说明、版本差异
- 内部任务编号（如 `t1`／`t4`／`t19`）及其衍生的表述
- 证据篇数口径、编辑过程的说明

内部记录写入案卷内部文件，与对外件分开发布。缺口披露与核验记录会向合议组与对方提示己方弱点，且不属于请求书应当记载的内容。

上列各项中，**标题**一类由渲染器机械检查并把发现写进 `warnings`：章节编号非章节级、重复、乱序，以及标题命中内部用语表（待办／待填／核验记录／引用核验／修订记录／修订说明／最坏情形／缺口汇总／口径）。规则与用语表在 `packages/patent/patent-document/src/document/documentCompliance.ts`，`scripts/verify-patent-document-output.ts` 对产出的文件或随包模板样例离线施加同一检查。用语表只覆盖标题、且只覆盖上列各项的一部分——内部任务编号、成功率的内部表述、source_path 清单都不在其中；其余各项（含正文里的同类内容）为人工检查项，渲染器不检测。
