# Agent Note: 附图工具报告图面用语缺陷

Status: implemented

[English](2026-09-16-drawing-wording-warnings.md) | 中文

## Problem

中国专利附图带有生成器可能无意违反的形式要求。《专利法实施细则》第二十一条：「附图中除必需的词语外，不应当含有其他注释。」《专利审查指南》第一部分第一章 4.3 另有「附图中的词语应当使用中文，必要时可以在其后的括号里注明原文」与「附图标记应当使用阿拉伯数字编号」。调用方传入「注：仅用于说明」这样的部件名、纯英文部件名、或 `S101` 这样的参考标号时，得到的是渲染成功且没有任何提示——而这些正是会被补正通知书指出的情形。

提示所需的信息本来就在工具输入里：进入 DOT 的标签，以及分配给部件的标号。

## Decision

**`figure/wording-rules.ts` 从图面自身的词语与标号推导用语警告，两个附图工具都返回这些警告。**

- `figureWordingWarnings(labels, numerals)` 只返回警告文本，绝不改写输入。标签按换行拆分（DOT 的 `\n` 换行写法）后逐行判定；重复的词语与标号只提示一次，顺序为首次出现顺序。
- 四类注释特征各带自己的说明：注释前缀（注／注意／说明／备注／提示 后接冒号）、正文引用（如图／见图／参见图／见附图、`see fig`）、尺寸标注（数字后接长度单位，含 英寸／毫米／厘米／分米／微米／纳米）、句末标点（。；;）。
- 不含 CJK 字符且不属于允许的非中文形式的词语出警告。允许形式为全大写缩写（CPU、EPROM、GB、I2C、A/D）与不含拉丁字母的字符串（数字、符号、单位写法），与指南对中国专利文本允许保留的非中文形式一致。
- 参考标号不是纯 ASCII 数字时出警告，并引用标号条款。
- `generate_patent_figure` 收集它将要绘制的词语——节点名、边标签，`raw_dot` 则取其双引号 `label` 属性值——并在单图与 `panels` 两条路径上追加这些警告。`add_patent_figure_references` 检查它被要求绘制的标号；它的 `label` 是用于匹配调用方既有图面的键，不是本工具放置的词语。

## Alternatives considered

**规则命中时拒绝出图。** 起草人认为必需的注释仍应由申请人判断，工具无法区分「必需」与「非必需」词语。拒绝出图要么丢掉合法图，要么逼调用方绕过工具，因此检查只作提示，渲染器从不改动标签。

**改为扫描渲染后 SVG 的文本，而不是输入端。** 读取产出的图面能覆盖输入未命名的内容，但 png/pdf 输出没有文本可读，`raw_dot` 无论如何都要先解析 DOT，而在 `add_patent_figure_references` 里扫描调用方提供的 SVG 会指出调用方自己的图面，而不是本工具的放置结果。

**把检查做成独立工具。** 单独的 `check_patent_figure` 调用没有自己的工件，还把判定与它所评判的图分开；调用方得把同样的标签再传一遍。由绘制这些词语的那次调用返回警告，每张图只留一条记录。

**按标签长度或分类模型判断词语是否必需。** 长度阈值在条文里没有出处；分类模型会为一项条文已给出具体文本模式的检查引入模型调用。实现的规则直接引用条文自身的类别。

## Consequences

- 部件名为纯英文的图现在会出警告。以英文标注软件图的调用方每次生成都会看到它，直到改用中文标签或全大写缩写——这是条文要求，不是工具偏好。
- 报告既不阻断也不改写，忽略 `warnings` 的调用方拿到的工件与之前一致。
- `add_patent_figure_references` 只报告非数字标号；它的警告列表把「未命中参考」与标号报告混在一起，按条数判断的调用方需要读文本。
