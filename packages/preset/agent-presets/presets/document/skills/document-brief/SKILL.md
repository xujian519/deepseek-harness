# Document Brief（交付规范）

把一条需求拆成可执行、可验收的交付规范。规范不完整不进入撰写阶段。

## 必须捕获的字段

1. **交付目标**：这份产物的用途（说服/记录/教学/汇报），一句话说清。
2. **受众**：读者是谁、ta 最关心什么、需要什么背景铺垫。
3. **格式**：Markdown / Word(.docx) / HTML 单页 / PPTX；是否要 PDF 导出。
4. **设计系统**：品牌名或 DESIGN.md 路径；没有则声明"使用默认基线"。
5. **成功标准**：交付时如何判定完成（结构齐全、P0 自检通过、指定导出格式）。
6. **约束**：篇幅/页数预算、语言、截止时间、禁用的表述（如"以后再说"）。

## 流程

1. 逐项询问或用 ask_user 确认缺口字段；可以从用户的原话中提取已给出的项。
2. 输出结构化 brief（一段 markdown，含上述六字段），写进工作区 `brief.md`。
3. 与用户确认后进入大纲阶段（html/report/deck 技能各自继续）。

## 检查清单

- [ ] 六字段全部非空（或显式标注"用户未提供，采用默认"）
- [ ] 成功标准可验证，不是形容词
- [ ] 设计系统决策已记录（默认基线或具体 DESIGN.md）
