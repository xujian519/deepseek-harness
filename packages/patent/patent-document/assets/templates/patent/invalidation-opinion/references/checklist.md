# 专利无效宣告请求书 — 自查清单（Checklist）

> 输出 `<artifact>` / 定稿前逐项勾选。P0 必须全部通过。本件为**对外提交件**；内部无效意见（可载引用日志、结论分档与缺口披露）用 `invalidation-analysis` 模板，不要在本件里夹带内部记录。

## P0 — 必须通过

- [ ] 文书结构完整且顺序正确（`conventions.md §1` 的六节）
- [ ] 章节编号唯一、按序，与 `conventions.md §1` 的固定顺序一致
- [ ] 案件信息表填满（涉案专利号、专利名称、授权公告日、专利权人、请求人/委托方、分析日期）
- [ ] 总体立场明确，列出**实际主张**的全部无效理由
- [ ] 涉案专利权利要求特征分解表覆盖全部独立权利要求
- [ ] 证据清单逐条登记完整：专利文献写公开号与公开日，出版物写 ISBN、出版信息与所引页码，无标识可写的在标识列写「—」；全件编号一致（`conventions.md §4.1`）
- [ ] 证据编号两侧对齐：正文引用的编号全部登记在表 2，表 2 登记的编号全部在正文引用过，编号列无空行（`conventions.md §4.1`，渲染器的证据编号核对零告警）
- [ ] 对比文件公开日早于涉案专利优先权日/申请日（有优先权的以优先权日为准）；抵触申请单独标注
- [ ] 无效理由节的节标题由结构与法条生成（未手写小节标题），且正文按「事实认定 → 证据分析 → 法条适用与结论」四段式组织
- [ ] 只写实际主张的理由：不得为凑模板填写未主张的理由
- [ ] 法条引用精确到条款号；未把单一性（A31条第1款）作为无效理由提出
- [ ] 逐权利要求结论表覆盖全部目标权利要求
- [ ] 每项从属权利要求的无效理由与其引用的权利要求使用同一法条路径，结论写明「在引用权利要求不具备创造性的基础上」（`conventions.md §2.1`）
- [ ] `claim_chart_build` 的 `invalidity_conclusion` 报出的「仅附加特征被覆盖」形态已处置（改法条路径或补足证据）
- [ ] 无编造公开号、日期、段号
- [ ] 免责声明与密级完整，品牌变量已注入
- [ ] 无占位文案泄漏给用户（`________` 类占位全部替换）
- [ ] 正文无内部工作记录（核验记录／待办／缺口披露／成功率分档／修订记录／内部任务编号），见 `conventions.md §6.1`；其中标题与正文用语表两项以及证据编号核对由渲染器机械检查（内部任务编号仍为人工项）

## P1 — 应当通过

- [ ] 无效理由之间不重复、不矛盾
- [ ] 无以「附加技术特征被公开」为由认定从属权利要求不具备新颖性的表述
- [ ] 从属权利要求引用关系在结论表中说明
- [ ] 证据分析与法条结论一一对应
- [ ] 表格数字列使用 tabular 数字

## P2 — 锦上添花

- [ ] 同时产出 `.md` 源稿与 `.pdf`
- [ ] 导出 PDF 后抽查表格是否跨页断裂
- [ ] 如需向国家知识产权局提交，请求书另按官方 101001 表格 + 100014 附页出件，补充意见与答复转送文件通知书按 100902 表格 + 100014 附页出件；101001 的 ⑨栏、100902 的 ⑦栏须逐条写明附件的名称、份数、页数、原件或复印件（本件证据清单只登记标识、名称与日期，这三项在出件时按附件实物补填）（口径见 `references/conventions.md` §7）
