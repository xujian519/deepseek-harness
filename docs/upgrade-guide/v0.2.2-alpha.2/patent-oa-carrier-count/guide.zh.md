# 篇幅预算不再把表格算进去

[English](guide.md) | 中文

## 变更

成文的口径一直是「可见字符，不含表格与修改后的权利要求全文」（`conventions.md` §10），实现却只剔了标记，表格单元格照算。差距不是小数点：在一份真实录制的答复稿上，2892 个计入字符里有 987 个（34%）是表格文字。

`visibleChars` 现在先剔载体块再计数——Markdown 表格行、HTML `<table>`、`claim-text` 元素，以及「修改后的独立权利要求」标题下的整节（到同级或更高级标题为止）；随后照旧剔除标记与空白。`slop-gate` 的篇幅维度与 `tighten` 的前后字数核对都调它，于是「告诉模型的字数」与「判它达标的字数」终于是同一个数。

`tighten` 也不再拿载体当余量。它在调模型前数一遍表格块与权项全文块，事后比对；少一块就写一条 `tighten_violations`，即使字数已经达标。删掉表 1 或 2.1 全文，是少了一份交付物，不是把答复写短了。

原样交回的正文现在照实报：「模型原样返回、未删除任何内容」并给出还要删多少字，不再混在「仍超预算」里——「一句没删」与「删得不够」是两种失败，修法不同。

提示词加了两条：表格与权项全文不计入字数、也不得整块删除；`removed` 里列了什么，正文里就必须已经不在。

## 迁移

1. 带表格的答复稿字数会下降：同一份稿子由 2892 变为 1905。预算与通过线不必跟着改；若当初是拿旧的（含表格）字数定的标，需重新核一遍。
2. `slop-gate` 的分数只在贴着分档边界的文本上变化，分档本身没动。
3. 只剩表格可删的答复稿，`tighten` 现在会更常降级。这正是它该给的结论：载体不是余量，降级后流程回落到 `draft`。
4. 若你自己的检查把表格当散文计，它看到的文本会比以前少；`patent-oas` 的篇幅观测本来就是这套口径。
