# Agent Note: upstream v0.2.1-alpha.1 sync

Status: implemented

[English](2026-10-04-upstream-v0.2.1-alpha.1-sync.md) | 中文

## Problem

本 fork 从上游的 `dsh-v0.2.0-rc.2` 标签前进到 `dsh-v0.2.1-alpha.1` 发布：266 个上游提交（不含合并 201 个），覆盖 4190 个文件。合并基点正落在 rc.2 的发布提交上，因此本次合并报告的是两个发布之间真实共享的 128 处冲突（102 处内容冲突、25 处「他们删除/我们修改」、1 处「我们删除/他们修改」），而不是重新推导更早的发布。

上游本次发布退役了一个本 fork 仍在使用的子系统，并改动了三处由本 fork 塑造过的面。运行时不变式栈整体消失：`@deepseek-ai/dsh-invariants`、每个包的 `./invariant` 伴随入口、`sdk-minimal` 的五行挂载，以及证明它们的门禁（`scripts/package-invariants.ts`、`verify-package-invariants`、`test-invariants`）。发布方为该移除附带了升级指南，并把它标注为破坏性变更。Workspace 注册去掉了显式标题参数（`create(path)` 自行推导显示标题）；随包发布的 preset 重新纳入 rc.1 曾移入可选包 `dsh-experimental-schedule-bundle` 的 `time-context` 与 `tool-schedule` 两行——而该 bundle 在同一次发布中被退役——桌面宿主默认改用操作系统分配的端口。与新面一同到来的还有：基于 `experimental/claude-code-mods` 的 `ctx.claudeCodeMods`、可选的 `experimental/inspector-profile` 开发者工具包、Web 的 `--public-url`、插件管理页由 Agent 创建插件的入口，以及未发送的初始提示词。

本 fork 拥有 Electron 桌面 profile 目录、`@deepseek-ai/cordis/...` 事件名、`dsh-timeout-guard` 与 `dsh-prompt-cache` 包名，以及其专利、self-evolve、桌面、better-sidebar、plugin-market 与 document 面。

## Decision

- **运行时不变式子系统随上游的移除一同删除。** 本 fork 剩余的伴随（`patent-teams`、`patent-workflow`、`self-evolve`、`prompt-cache`）与被本 fork 修改过的上游伴随都随机制一并删除：18 个源码与测试、5 个 `./invariant` 导出、9 处 `runtime-diagnostics/invariants` 的 tsconfig 引用、`apps/cli` 与 `examples` 的依赖、better-sidebar 的 `SidebarInvariantsService` 镜像、两处包的 tsdown 伴随入口，以及 `package-invariants` 门禁注册。保留本 fork 自己的检查意味着重新采纳被删除的服务、被退役的 profile 行以及上游刻意放弃的 emitter 重抛行为。根与包的 AGENTS.md 不变式规则属于上游的删除，随之同行。
- **版本、pin 与生成物随发布同步。** 46 个 fork 独有 manifest 与 `SIDEBAR_SERVICE_VERSION` 并入根 manifest 的 `0.2.1-alpha.1`；9 个 `snapshots/acp/*/stdout.expected.jsonl` pin 随行，因为 `agentInfo.version` 来自 acp 包的 manifest。所有生成器都在解析后的树上重跑（`gen-tsconfig-paths`、`gen-cordis-catalog`、`gen-client-catalog`、`gen-cordis-inspect-catalog`、`gen-tool-catalog`、`gen-config-catalog`、`gen-persistence-catalog`、`gen-doc-graphs`、`gen-module-graph`、`gen-plugin-packages`、`gen-dependency-catalog`、`gen-session-format-catalog`），`pnpm run verify-no-unknown-casts --prune` 未报告新增的 `unknown` 断言。
- **上游归档的笔记保留上游的封存内容，本 fork 的链接随之前往归档路径。** 上游归档了 13 篇本 fork 在 `implemented/` 下编辑过的笔记；合并把两侧融合，改变了「归档冻结」门禁所拥有的封存哈希。归档对恢复为上游内容、本 fork 为被删除的 `implemented/` 侧所录的配对记录被删除，26 条指向被移动笔记的链接改指 `.agents/notes/archived/<kind>/`。同一次清理把笔记里的 `.github/workflows/` 链接改指 `.github/workflows-disabled/`，也就是这些工作流在本 fork 的存放位置。
- **`docs/capability-seams.zh.md` 是手工镜像而非生成。** 英文页由生成器产出，本次失去了 `ctx.invariants` 行与图节点；中文页是人工撰写，因此手工删除该表行、图节点与边，并同步 `ctx.sessions` 的消费方列表，同时把上游新增的 `ctx.claudeCodeMods` 行与图节点翻译补入。
- **`packages/bundle/web-app` 同时保留两侧的发布清单。** 该 manifest 保留本 fork 的专利与 document preset 指南及 `skills` 目录，并补入上游的 `lib/public-url-*.js` chunk。`scripts/check-workspace-constraints.ts` 因合并在 `packageFileExtras` 中出现了第二个 `@deepseek-ai/dsh-web-app` 条目（上游新增条目落在本 fork 条目之后）；两者合并为本 fork 条目的单一列表，这也是该约束所要求的形式。
- **`dsh-experimental-schedule-bundle` 离开 `apps/cli`。** 上游退役了该 bundle 并让自动化任务重新成为 Web 的一部分，因此删除该依赖，以及合并留下的两个空包目录（`packages/experimental/schedule-bundle`、`packages/runtime-diagnostics/invariants`）。
- **桌面宿主采纳操作系统分配的端口。** `--port 0` 取代本 fork 继承的 `19387`；壳层本就从就绪消息读取实际服务地址。本 fork 的组合 overlay 与其 `@deepseek-ai/dsh-desktop-host` 解析锚点保留。
- **上游新增的 e2e 测试改接本 fork 的 workspace API。** `apps/web/tests/draft-initialization.e2e.ts` 原本调用 `workspaceRegistry.create(path, title)`；本 fork 的 `create(path)` 自行推导标题，因此该夹具去掉该参数，改为对返回的 `title` 断言。
- **preset 分歧基线按两个 `tool-subagent` 行重新录制。** 上游本次发布在共享 preset 中对 subagent 禁用四个 schedule 工具，改变了三份 preset 中这两个行的块哈希；其余行的哈希均未变。
- **其余冲突按并集解析。** `packages/boot/app-boot/src/profile-resolution/service.ts` 保留本 fork 的 `installedByProfile` 并采纳上游的 `refresh`；`packages/client/ui-conversation` 保留本 fork 的「按选择与认领推导活跃 target」模型，并采纳上游的路由化事件分发、`bindDraftPersistence` 改名与携带 `Match` 的 `acceptMatch`；`packages/core/tools/src/ptc.ts` 保留本 fork 抽出的 `run-code-flavor.ts`，上游的参数顺序文案落入该模块；`packages/client/ui-agent-preset/src/client/AgentPresetSeat.tsx` 保留 `SEAT_PRESET_LOCKED` 并采纳上游的结构化拒绝错误与其 `errorText` 翻译；`scripts/run-gates.ts` 保留本 fork 的 mode 集合并采纳上游的 Electron 供给拆分；`scripts/run-gates.spec.ts` 保留两边的 Electron 断言；`packages/schedule/schedule/src/index.ts` 采纳上游的 `delegationDepthOf` 导入与本 fork 的 `dsh-session/types` 说明符；`packages/test-support/session-snapshot/src/harness.ts` 保留本 fork 的 `waitForPersisted` 等待，取代 `vi.waitFor`。
- **锁文件、归档 manifest 与生成页重生成。** 在解析后的 manifest 上运行了 `pnpm install --lockfile-only`，`verify-archived-agent-notes --write` 把本 fork 自己的归档笔记与上游的一并重新封存，凡任一侧改动过的页面都重录了配对记录。

## Consequences

本 fork 在保留其专利、self-evolve、桌面、better-sidebar、plugin-market 与 document 面的前提下交付上游 v0.2.1-alpha.1 基线，历史保持连通：`git merge-base HEAD dsh-v0.2.1-alpha.1` 即该发布的提交，因此下一次同步读到的是真实的冲突集。此后每次发布有三处分歧需要留意：本 fork 的 preset 是上游组合变更的落点；归档笔记的封存必须与被上游退役的那些笔记一致；本 fork 笔记里的工作流路径必须跟随上游进入 `workflows-disabled/`。

机制被移除之前由本 fork 拥有的四处不变式检查已消失；它们所做的载荷校验（patent-teams 的持久事件、patent-workflow 状态、self-evolve 记录、prompt-cache 前缀契约）如今只在各包自身测试覆盖到的地方存在。债务账本在专利域条目里仍按行号引用已删除的 `invariant.ts`；这些引用写的是不带 `packages/` 前缀的 `src/` 路径，不在路径门禁的扫描面上，因此留待下次债务清理。

`pnpm run doc-sync` 门禁与完整检查集已在该树上运行；结果见下方 Testing，仍然失败的项目在那里记录，而不在本轮修复。

## Alternatives considered

- **通过恢复服务来保留本 fork 自己的不变式伴随。** 拒绝：这等于重新采纳上游删除的子系统，需要恢复 `sdk-minimal` 的五行为与 emitter 重抛行为，并在此后每次同步中反复冲突；本 fork 的 AGENTS.md 规则本就主张在观测无法分歧时省略不变式。
- **保留合并后的归档笔记内容并重新封存。** 拒绝：归档冻结门禁把封存变更视为错误，且没有重新签名模式；归档副本必须保持上游封存的内容。
- **从上游重新播种 `apps/web/tests/draft-initialization.e2e.ts`。** 拒绝：本 fork 的 `create(path)` 才是现役 API，而该测试的要点是草稿生命周期，不是标题参数。
- **`packageFileExtras` 的重复条目原样保留。** 拒绝：对象字面量只保留后一个条目，本 fork 的四个指南文件与 `skills` 目录会静默停止发布。
- **删掉 `packages/bundle/web-app` 的 preset 行以与上游列表完全一致。** 拒绝：本 fork 交付专利与 document preset 层，而该约束期望的列表正是本 fork 自己条目所声明的并集。

## Testing

`pnpm run typecheck` 在两个编译面上均以 0 退出；`pnpm run lint` 在 6458 个文件、90 条规则下以 0 退出；`pnpm run build` 以 0 退出（Host 类型检查、两遍 tsdown、桌面 bundle 与 Web 构建）并记录 369 个 client 产物。`pnpm run constraints` 通过，全族共享一个版本；`pnpm exec tsx scripts/release/verify.ts --family dsh` 在 `0.2.1-alpha.1` 下解析出 367 个成员，发布顺序可解。

`pnpm run doc-sync` 报告 47/47 门禁通过。合并前的树在其中一项上失败，且属于本轮面内：`verify-package-paths` 引用了已删除的不变式与 chat partial 模块，`verify-md-links` 无法解析目标笔记被本次发布归档的链接；两者本轮均已改指。同一次运行中，本轮应交的门禁全部通过：`verify-archived-agent-notes`（2775 个冻结产物）、`verify-translation-pairing`（1175 对，按本轮改动重录）、`verify-md-links`（2351 个文件）、`verify-package-paths`（7154 个文件）、`verify-no-unknown-casts`（保留 1873 条既有断言，无新增）、`verify-preset-divergence`（27 个分歧行 id，其中两个 `tool-subagent` 行已重录）、`verify-persistence-changes`（82 个根对应 12 条历史记录）与 `verify-persistence-formats`（v0 至 v4）。

`pnpm run test:snapshot` 在 session、sdk、acp 与 web 四条车道上回放 195 个 keyless 用例，2 例跳过。本次发布的模型可见文案落地后，14 处 request header 比较失配（`description` 先于 `command` 的句式、`todo_write` 的 `tags` 字段、`edit` 参数文案），`pnpm run test:snapshot:refresh` 重写了 14 个期望文件；每处 diff 均已复核，只含上述措辞与 schema 变更。

`pnpm test` 通过 47,859 个用例，含 1 个预期失败，以及两个本机固有、且都能在本轮面之外复现的失败：`packages/util/http-proxy/tests/install.spec.ts` 的 `origin.test` 查询在本机永不解析（单独运行同样失败），`packages/api/workspace-files/tests/changes.spec.ts` 的真实本地 watcher 用例如单独运行该文件则 43/43 通过。首次运行报出的另外三处失败已在本轮修复：`scripts/ci-workflow.spec.ts` 曾以现役路径读取已归档的发布工作流，`ui-trajectory` 与 `ui-document-studio` 的构建产物规格在 locale 服务就绪之前挂载了插件。

`pnpm run hygiene` 报告 17/17 门禁通过，其中 `rescope-vendor --check` 的白名单补入了本次发布新增的 `cordis` preset id 站点。`pnpm run duplication` 报告仓库级 0 克隆，收紧域 85 对与 `scripts/duplication-baseline.json` 一致。
