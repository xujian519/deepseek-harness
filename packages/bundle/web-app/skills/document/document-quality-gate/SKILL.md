# 交付质量门（P0/P1 自检）

交付前逐项核验；P0 全过才允许交付，P1 尽量满足并在交付摘要中标注未满足项。

## P0（不通过不得交付）

- [ ] **命名**：产物用规范名——`index.html` / `report.md`+`report.html` /
      `deck.html` / `<name>.docx`；路径在交付摘要中给出
- [ ] **自包含**：HTML 单文件内联资源，不引用外部 CDN / 远程字体
- [ ] **无占位残留**：无 "Lorem ipsum"、无 `[TBD]` / `[REPLACE]` / `{{变量}}` / 空槽
- [ ] **断链**：目录锚点、图片引用、站内链接全部可解析
- [ ] **来源**：每个事实性断言（数据/日期/引用/版本）有可验证来源；
      无来源的断言已删除或标注"待核实"
- [ ] **语言**：无错别字、无半角/全角混排硬伤、术语全文一致

## P1（尽量满足）

- [ ] 可访问性：语义化标签、对比度 ≥ 4.5:1、键盘可导航（Deck 翻页含键盘）
- [ ] 移动端：920px 断点重排正常，无横向滚动
- [ ] 字数预算：落在 brief 篇幅约束的容差内（容差见 `document_deliver` 工具说明）
- [ ] 单一强调色，每屏至多两处
- [ ] 每个 `<section>` 有 `data-doc-id`
- [ ] 文档含页脚（文档名 + 日期 + 版本）

## 工具侧确定性核验（不靠自述）

`document_deliver` 会自己读取交付文件并做一遍确定性核验，结论与你的 P0/P1 自述并列写入会话日志，交付物面板同时展示：

| 检查 | 判定 |
|---|---|
| 占位符残留（`{{变量}}`、`[TBD]`、Lorem ipsum、待补充） | 引用文本之外**阻断登记**；代码块或行内代码之内仅提示（复述规则时用行内代码写这些串） |
| 样式禁用词（`style` 指定的风格） | 风格标为 block 的词阻断登记，标为 warn 的仅提示 |
| 空章节（标题下无内容） | 提示 |
| 断链（本文档未声明的锚点） | 提示 |
| 字数预算（`char_budget`，容差见工具说明） | 提示 |

阻断项会让 `document_deliver` 调用失败并列出位置；修复后重新登记。提示项不阻断登记，但应逐条修掉或在交付摘要中说明。

.docx 会经 DOCX 文本投影后同样核验；pdf/pptx 等无文本读取器的格式标记为"未核验"，不得声称已核验。

## 流程

1. 打开成品文件逐项核验（用 fs 读实际文件，不凭记忆）。
2. P0 未过：立即修复后重跑本清单。
3. 通过后交付摘要里附：文件路径清单、导出格式、未满足的 P1 项。
4. **登记交付物**：调用 `document_deliver`，`files` 列出全部成品与格式（path + format），
   `gate.p0` 填本次通过的 P0 项、`gate.p1` 填满足的 P1 项（无则省略），
   `brief_ref` 填 `brief.md`（若有），`style` 填本文使用的书写风格，`char_budget` 填 brief 声明的字数预算（若有）。
   工具会校验文件存在并跑确定性核验；报出阻断项或你自己不满意的提示项时，先修复再重试。
