# Agent Note: upstream v0.1.2-alpha.1 sync and the ApiProxy/Runtime removals

Status: implemented

English | [中文](2026-08-28-upstream-v0.1.2-alpha.1-sync.zh.md)

## Context

The fork tracked upstream `b150a551b8` (v0.1.1-rc.2). Upstream master moved to `cd5ef81481` (v0.1.2-alpha.1): 1,079 commits, 5,000+ files. This merge is the fork-regular `sync/upstream-v0.1.2-alpha.1` integration. Three upstream removals cut through fork-owned code, and each needed a deliberate disposition rather than a textual conflict resolution.

## Dispositions

**ApiProxy transport.** Upstream deleted `packages/host/apiproxy` and moved host access onto the Remote gateway with one-time-token network auth. The fork's electron pick capability (`packages/client/ui-directory-picker-browse` desktop preload bridge) and the strict-UTF-8 `readFileText` lost their host surface: the desktop chooser bridge survives client-side (it needs no host round-trip for the chooser itself), while `readFileText` is now a loud-failing inject with a `FIXME(port)` in `ui-document-studio` — upstream exposes no host file-read Remote. Restoring file preview over the gateway is a follow-up against upstream's new connection contracts, not a merge regression to paper over.

**Client Runtime.** Upstream removed `@deepseek-ai/dsh-client-runtime`; its types moved to owner packages (`ClientContext` is plain Cordis `Context`, session types live in `dsh-api-session-controller`, `shallowEqual` in `dsh-client-store`). The fork's `synapse`, `ui-patent-teams`, and `ui-document-studio` were re-pointed. The conversation view-switch write path (`registerViewSetter`/`setActiveView`) is re-applied onto upstream's `conversationStore`: the seat registers the store's `setView` on mount and releases it on unmount, so peer plugins keep jumping a session to their own view without touching the apply-local store handle.

**Session-event vocabulary.** Upstream removed the read-side `ignorable` envelope marker (fail-closed vocabulary). The merge restores `ignorable?: true` on the read envelope deliberately: `patent-teams` writes ignorable records and asserts the round-trip, and its events are in-repo known types. `persistence.md` currently carries upstream's wording; if the divergence stands, the persistence catalog needs a fork note.

## Dispositions (smaller)

- The `patent` and `document` agent presets moved from `apps/cli/config/agent-presets/` into upstream's shipped root `packages/preset/agent-presets/presets/`; the roster expectation lists six entries.
- The Windows console-flash fix (`STARTF_USESHOWWINDOW` + `SW_HIDE`) re-landed in `packages/subprocess/win32-process` after upstream extracted the process primitives out of `sandbox-windows-acl`.
- The DSH Patent rebrand re-applied through upstream's locale-driven brand (`packages/client/locale`) instead of the component literal upstream's `localBuildTitle` structure replaced.
- The patent figure feature (committed `patent-tools` sources import the figure modules) is carried in and adapted: `CallId`→`ToolCallId`, discriminated `ToolExecutionResult` assertions, and the `SubprocessOutputRead` protocol fields in the graphviz spec mocks.
- `examples/opendesign` stays fork-owned; upstream's deletion of everything else under `examples/` is accepted, with `examples/package.json` kept (minus the dead `dsh-acp-demo` dependency) as the dependency-resolution manifest for the remaining leaf.
