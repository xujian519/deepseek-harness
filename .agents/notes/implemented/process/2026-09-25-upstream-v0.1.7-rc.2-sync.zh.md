# Agent Note：上游 v0.1.7-rc.2 同步

Status: implemented

[English](2026-09-25-upstream-v0.1.7-rc.2-sync.md) | 中文

## Problem

本 fork 从上游的 `dsh-v0.1.7-rc.1` tag 前进到 `dsh-v0.1.7-rc.2` 发布，上游领先 346 个提交。本次合成报了 223 个冲突，而这次同步首先要回答的不是每个冲突取哪边，而是为什么一次 `rc.1 → rc.2` 的推进会产生冲突：rc.1 同步（#264）以单父提交落库，因此 fork 的 merge base 仍停在 `dsh-v0.1.7-alpha.2`，直接合成 rc.2 会重新推导出 672 个冲突，其中几乎全部是 fork 已以不同历史携带的 rc.1 内容。

两处上游改动对本 fork 自有的内容作出裁决。上游把 `*.i18n.yaml` 中整文件的 blob 哈希换成按 heading section 逐段记录，并移除了 `dsh-translation-pairing` merge driver、其 resolver 以及注册它的安装器接线——223 个冲突中有 109 个是这些记录，而 fork 已注册的 driver 指向的脚本正在被本次合成删除。上游还把 `packages/schedule/schedule` 从 agent 作用域的提醒存储重写为 host 级实现，并删除了 fork 副本所 import 的 `persistence.ts`／`transaction.ts`。

## Decision

- **本次同步以两次 merge-forward 执行，而第一次正是让第二次变成普通合成的那一步。** `git merge dsh-v0.1.7-rc.1` 解决 25 个冲突——与 rc.1 同步当时面对的是同一批——并产生第二个父提交为真实 rc.1 提交的 merge commit；随后 `git merge dsh-v0.1.7-rc.2` 报出两个发布之间真正共享的 223 个冲突。后续同步应先读 `git merge-base HEAD <上游 tag>`：base 比上一次同步的 tag 更旧，说明先前的某次同步以 squash 落库，此时先合入被跳过的那个 tag，比把它的内容解决两遍更便宜。
- **桌面端保留 fork 的托盘与 bridge，并吸收上游的相邻模块。** `apps/desktop/src/tray.ts` 保持 fork 的纯函数，`main.ts` 继续自行构造 Electron `Tray` 并交给 `bridge.initTray`，使插件仍可贡献托盘条目；上游新增的 `DesktopTray` 类被丢弃，其第二处 `window.on('close')` 处理器同样丢弃。上游独立的 `quit-confirmation.ts` 与 `background-notice.ts` 不依赖该类，予以保留，fork 的关闭处理器吸收它们的更新对话框与后台通知分支。上游类所携带的 `tray.dispose()` 调用改为裸 Electron 对象上的 `tray.destroy()`。
- **`packages/schedule` 整体采用上游重写。** fork 的副本 import `./persistence.ts` 与 `./transaction.ts`，而这两者在同一发布中被上游删除，因此由该包自身的历史裁决：host 级服务及其 `./typert`／`./remote` 导出条目落地，fork 的 Config 字段只在仍有消费方处保留。
- **`packages/subagent` 的 `list-children.ts` 保留 fork 的 `coldReadConcurrency` Config 字段。** fork 把并发上限从模块常量提升为带 README 契约与三个测试用例的受校验 `Config` 字段；上游的重写把它重新内联。该字段属于 fork，因此该文件解析为 fork，上游的简化不落地。
- **客户端面按「改动是否携带 fork 内容」分别裁决。** `packages/client/locale` 对 `brand.localBuild` 保留 `DSH Patent`，并吸收上游新增的 `workspace.defaultName`。`packages/client/ui-primitives/tsconfig.json` 与 `packages/client/tsdown.client.ts` 解析为并集（上游的 `util/code-language` 引用与 `default-workspace` inline-safe 条目加入 fork 的 `util/values` 与 `value`）。`packages/client/ui-schedule` 与 `packages/client/ui-sidebar` 的冲突 spec 解析为 fork 的副本，它们与 fork 自身的服务类型一致；随后 sidebar 夹具补上上游 `SidebarRoot` 现已要求的 `useShortcuts` hook。
- **`Session.toolHistory()` 是移植而非合并。** 上游把该方法加到 `packages/core/session/src/index.ts`；fork 已拆分该文件，类留在 `session.ts`、入口只剩 re-export。该方法及其 `ToolHistoryProjection` 字段按 fork 的字段名移植进 `session.ts`，入口采用 fork 的结构——字面合并两个入口会产生三个 `Session` 声明。
- **trajectory 的 tool-addition 渲染移植进 fork 的拆分文件。** 上游对 `TrajectoryTable.tsx` 的两处改动分别落到 `trajectory-markdown-content.tsx`（source-block 集合全为 tool add/remove 时的原文分支）与 `trajectory-row.tsx`（不可选中的 `singleToolNotice` 行），因为 fork 从拆分文件而非单体文件渲染这些行。
- **fork 采用上游的译文配对机制。** heading-section 记录、`gen-translation-brief` 的恢复路径，以及 merge driver 的移除都来自上游；fork 从 `.gitattributes` 与 worktree git config 中移除该 driver，并用 `pnpm run verify-translation-pairing --write --all` 迁移仅 fork 携带的记录。`docs/tool-catalog` 与 `docs/capability-seams` 的中文页补入上游新增的 schedule 段落，因为 fork 的副本早于该 host 级重写。
- **fork 删除的两个整段 schema 回归。** `ChatSettingsSchema` 与 `ConversationSettingsSchema` 曾以「无消费方」为由在 `refactor(client): drop dead chat and conversation surface` 中删除；上游的 `apply.client.spec.ts` 及其同类重新成为消费方，因此该删除不再成立，两个定义回归。
- **版本族与 ACP 钉值随发布移动，放在后续提交中。** `pnpm run constraints` 要求每份 manifest 等于根版本，因此上游并不发布的 43 份 manifest 连同 `SIDEBAR_SERVICE_VERSION` 移到 `0.1.7-rc.2`；`packages/api/remotes` 补回冲突解决中丢失的 `@deepseek-ai/cordis` devDependency——正是 `constraints` 报出的那一条。九份 `snapshots/acp/*/stdout.expected.jsonl` 钉值随发布移动，`DSH_SNAPSHOT=refresh … --update` 重新生成该发布同时改动的 header。
- **类型等价文档跟随所移植的源码，且双语同步。** `docs/subsystems/session.md` 补入 `toolHistory()` 声明，`docs/subsystems/subagent.md` 采用源码的 `SubagentDescendantListEntry` JSDoc，两份 `.zh.md` 逐字节镜像它们，因为 `verify-type-equiv` 只在中英块完全相同时才把中文块配为其英文同侪。
- **`tsconfig.host.json` 改为 extends `tsconfig.base.json`，仅 fork 有的 `tsconfig.base.host.json` 删除。** 上游的 host aggregate 读同一份 base 配置；fork 多出的 face 文件携带的 `paths` 遗漏了 host aggregate 中 `apps/web/tests/shortcuts-*.e2e.ts` 所 import 的 client 包，这正是那些文件无法解析 `@deepseek-ai/dsh-client-shortcuts/protocol` 的原因。`apps/desktop/src/print.ts` 出于同样的原因加入 keyboard-test program。

## Consequences

fork 携带上游 v0.1.7-rc.2 基线出包，其 patent、desktop、better-sidebar 与 plugin-market 面保持完整，且历史重新成为连通图：`git merge-base HEAD dsh-v0.1.7-rc.2` 即 rc.2 提交，因此下一次同步读到的是真实冲突集，而不再重新推导既有发布。桌面托盘、subagent 并发字段与 tool-todo 描述是 fork 与上游当前真正分歧的三处，每次触及它们的发布都会再次冲突。`dsh-translation-pairing` driver 已移除，因此 `*.i18n.yaml` 走 git 默认文本合并，记录以 section 而非整文件为键；fork 的 `type-equiv.manifest.json` 中指向其拆分文件的条目保持指向 `session.ts` 与 `tools/src/types.ts`。`pnpm run doc-sync` 携带一个失败：`verify-package-paths` 指向 `docs/TECH_DEBT.md:225`，其被引用的路径早在本次合成之前就已离开本树。

## Alternatives considered

- **直接合成 rc.2。** 不可行：merge base 停在 `dsh-v0.1.7-alpha.2` 时，672 个冲突把 fork 自身的 rc.1 内容描述成分歧工作，解决它们等于重新裁决 24 处已作出的合并。
- **用 `git merge -s ours dsh-v0.1.7-rc.1` 重连历史而不解决其冲突。** 已否决：fork 的内容与 rc.1 足够接近，真实合并只需 25 个冲突，而 `-s ours` 在不加检查的情况下断言 fork 包含 rc.1，squash 遗漏的任何内容都会被静默且永久地跳过。
- **保留上游的 `dsh-translation-pairing` driver 及其脚本。** 不可行：上游在弃用该机制的同一提交中删除了脚本，而一个指向缺失命令的已注册 driver 会把每次配对冲突变成无标记的未暂存文件。
- **采用上游的 `list-children.ts` 重写并放弃 `coldReadConcurrency`。** 已否决：该字段是带文档化契约与测试覆盖的受校验 `Config` 字段，而本仓库的规则是「随部署变化的取舍是 `Config` 字段，而非常量」。
- **采用上游的 `tool-todo` 描述。** 已否决：fork 的 schema 携带 `tags` 字段，描述必须说明它；fork 保留自己的段落，并在两份 README 中补入上游的「每次调用替换整个列表」一句。
- **字面合并两个 `packages/core/session/src/index.ts` 入口。** 已否决：那会产生三个 `Session` 类声明。fork 的拆分就是结构，上游的新增是要移植进 `session.ts` 的方法。
- **恢复 `tsconfig.base.host.json` 并补上 client 路径。** 已否决：一份 `paths` 与 base 配置重复的 host face 文件会让同一份清单有两个来源，而上游的布局直接读 base 配置。

## Testing

`pnpm run typecheck` 覆盖两个编译面并以 0 退出，`pnpm run build` 的 host 与 client 打包均成功，`pnpm run lint` 以 0 退出。`pnpm run constraints` 在 43 份仅 fork 发布的 manifest 处于根版本时通过，`pnpm exec tsx scripts/release/verify.ts --family dsh` 在 `0.1.7-rc.2` 解析出 357 个成员且发布顺序已解析。`pnpm run doc-sync` 报 44 个门禁通过、1 个失败，失败即上述长期存在的 `verify-package-paths` 条目；`pnpm run verify-type-equiv` 在 53 份文档中以 466 个块保持 1:1 配对，`pnpm run verify-translation-pairing` 接受全部 1418 对。`pnpm exec vitest run --config vitest.snapshot.config.ts snapshots/acp` 在钉值刷新后无密钥回放全部 16 个用例。生成物均由其在已解析树上的生成器产出（`gen-config-catalog`、`gen-tool-catalog`、`gen-doc-graphs`、`gen-module-graph`、`gen-persistence-catalog`、`gen-cordis-catalog`、`gen-plugin-packages`），且 `git merge-base HEAD dsh-v0.1.7-rc.2` 报出 rc.2 提交。
