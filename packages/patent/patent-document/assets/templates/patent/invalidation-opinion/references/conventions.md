# 专利无效宣告请求书 — 版式惯例（Conventions）

> 生成或修改本模板前必读。与 `checklist.md` 配套。本模板产出**对外提交件**；内部无效意见（可载引用日志、结论分档与缺口披露）用 `invalidation-analysis` 模板。

## 1. 文书结构（固定顺序）

1. 页眉（所名 + 密级）
2. 文书抬头（类型徽标 / 标题 / 案件编号）
3. 案件信息表（涉案专利号 / 专利名称 / 授权公告日 / 专利权人 / 请求人 / 分析日期）
4. 一、总体立场
5. 二、涉案专利权利要求分析（特征分解表）
6. 三、证据清单
7. 四、无效理由（按法条逐条组织）
8. 五、逐权利要求结论
9. 六、结论与请求
10. 落款 + 免责声明 + 页脚

## 2. 无效理由法条体系

法条与理由的对应以确定性理由表为准：`packages/patent/patent-core/src/notice/grounds.ts`。下表按该表口径列出，改动其一须同步另一处。细则条号为 2023 年修订（2024-01-20 施行）后的条号；识别他人文书时，2024-01-20 之前出件的旧条号（细则第20条第2款、第43条第1款）按同一理由归入，本所出件一律写现行条号。

| 法条 | 适用场景 |
|---|---|
| A22.2 新颖性 | 权利要求全部技术特征被一篇现有技术单独公开 |
| A22.3 创造性 | 权利要求相对于现有技术结合显而易见 |
| A22.4 实用性 | 不能制造或使用、无积极效果 |
| A2 / A5 / A25 客体 | 不属于技术方案；违反法律、社会公德或妨害公共利益；属于不授予专利权的范围 |
| A26.3 充分公开 | 说明书未清楚完整地公开技术方案 |
| A26.4 清楚支持 | 权利要求不清楚、得不到说明书支持 |
| 细则第23条第2款 必要技术特征 | 独立权利要求缺少解决技术问题的必要技术特征 |
| A33 / 细则第49条 修改超范围 | 超出原说明书与权利要求书记载的范围；分案申请同理 |
| A9 重复授权 | 同样的发明创造 |

**不属于无效理由的条款**：单一性（A31条第1款）不在无效理由之列，不得作为无效请求的理由提出。

### 2.1 从属权利要求的法条路径

从属权利要求的技术方案是所引用权利要求的全部技术特征与附加技术特征的组合；判断其新颖性、创造性时比对的是**全部**技术特征。

- **不得以附加技术特征被公开为由认定从属权利要求不具备新颖性。** 所引用的权利要求相对某篇对比文件具备新颖性时，该对比文件未公开其全部技术特征；从属权利要求包含这些未公开特征，相对同一篇对比文件同样具备新颖性。以「附加特征已被该篇公开」主张从属权利要求不具备新颖性，与引用权利要求的结论自相矛盾。
- **从属权利要求与其引用的权利要求使用同一法条路径。** 引用权利要求以 A22.3 主张的，从属权利要求以 A22.3 承接，结论写「在引用权利要求不具备创造性的基础上，权利要求 X……不具有创造性」。
- 附加技术特征无对比文件直接覆盖时，主张其为本领域常规技术选择，按 §3 四段式给出事实与理由；不得替换为「本项无覆盖」「无效前景有限」一类己方评估。
- 该口径由 `claim_chart_build`（mode=invalidity）随图表算出的 `invalidity_conclusion` 机械核验：它逐权项判定单篇全覆盖（从属权项已并入引用链的全部要素），并报出「权项自身要素已覆盖、所引用权项未完整覆盖」的形态。核验报出该形态时，必须先改法条路径或补足证据，不得照原写法出件。

## 3. 无效理由四段式

每个无效理由按以下结构组织（节标题与四段式小标题由渲染器按草案结构生成，模型只填三段正文）：

1. **事实认定**：涉案专利权利要求/说明书对应内容。
2. **证据分析**：D1/D2/本领域常规技术选择的公开内容 + pin-cite。
3. **法条适用**：引用具体法条及审查指南章节。
4. **结论**：权利要求是否无效。

节标题形如 `4.1 权利要求 1、2 不具备创造性（专利法第22条第3款）`：法条、理由名与被主张的权项号取自草案的结构化字段，**起草时不得手写小节标题**——写死理由的小节标题会让只主张其他理由的请求书被迫编造一段不存在的主张。

## 4. 证据时间线

- 对比文件公开日必须早于涉案专利优先权日/申请日；有优先权的以优先权日为准。
- 中间文件（P）的公开日介于优先权日与申请日之间。
- 抵触申请（E，同一申请人的在先申请在后公布）单独标注。
- 原始申请文件不是现有技术，只作修改超范围（A33）的核对基线，与对比文件分列。

### 4.1 证据清单的登记口径（按证据类型）

无效程序中的证据不限于专利文献。表 2 的列按下列口径登记，列名见 `assets/template.html`：

- **专利文献**：标识列写公开号或申请号（如 `CN20151234567A`），日期列写公开日，用途列写所引段落号与所支撑的权项或理由。
- **出版物与公知常识证据**（教科书、工具书、期刊）：标识列写 ISBN 或 ISSN，名称列写全称并带编著者、出版社、版次，日期列写出版年月，用途列写书名后另附所引页码与该页公开的内容。单独以公知常识主张的，另说明该内容属本领域公知的范围与理由。
- **使用公开**：标识列写「实物」「销售记录」一类凭证名称，名称列写行为与载体，日期列写使用行为发生日，用途列写该行为公开了哪些技术特征。
- **原始申请文件**：标识列不写公开号，写「—」（可写申请号），关系列写「修改超范围核对基线」。
- 标识列不得留空：没有公开号、ISBN 或凭证名称可写的证据写「—」，一处不留空。
- 编号列写 `D` 前缀加序号（`D1`、`D2`…），编号列不留空；正文引用的编号必须已登记，登记的编号必须在正文引用一次。
- 一处证据全件只用一个编号：正文（§3 证据分析、§5 结论表）与表 2 的编号必须一致，同一份证据不得在清单里叫 D4、在正文里叫「附件 4」。

## 5. 逐权利要求结论表

- 「请求结论」列写请求的结果（请求宣告无效 / 部分无效），法条依据写法 `A22.2`、`A22.3`、`A26.4` 等，从属权利要求应说明引用关系。
- **本件不写己方成功率分档**（可无效／存疑／难以无效）：分档是内部评估，属 §6.1 禁止的内部记录，写在 `invalidation-analysis` 件或案卷内部文件里。
- 无证据支撑的法条适用结论降级为「模型推断」或「假设」——此类标注同样只在内部件出现。

## 6. 视觉与版式纪律

- 沿用 `assets/templates/patent/tokens.css` 品牌变量；agent 不改样式。
- 表格数字列使用 `tabular-nums`。

### 6.1 对外提交件与内部记录的分离

本模板产出对外提交件。下列内容属内部工作记录，不得出现在正文任何章节：

- 引用核验记录、法条与判例的 source_path 清单
- 待填项、待办清单、交付前检查项
- 己方证据缺口汇总、成功率分档、最坏情形说明
- 修订记录、增量修订说明、版本差异
- 内部任务编号（如 `t1`／`t4`／`t19`）及其衍生的表述
- 证据篇数口径、编辑过程的说明

内部记录写入本所的内部件（`invalidation-analysis`）或案卷内部文件，与对外件分开发布。缺口披露与核验记录会向合议组与对方提示己方弱点，且不属于请求书应当记载的内容。上文「无证据支撑的结论降级为模型推断/假设」是内部标记，不随对外件发布。

上列各项中，渲染器机械检查并把发现写进 `warnings` 的有三类。**标题**：章节编号非章节级、重复、乱序，以及标题命中内部用语表（待办／待填／核验记录／引用核验／修订记录／修订说明／最坏情形／缺口汇总／口径）。**正文**：命中正文用语表——待办／待填、核验记录／引用核验、修订记录／修订说明、最坏情形、缺口汇总／缺口清单、成功率／胜诉率／成功概率／胜率、`source_path` 一类内部数据键。正文用语表按语义表达式匹配（如 `成功率|胜诉率|成功概率`）而非裸词，以免命中对外文书中正常的同形词。**证据编号**：正文在表 2 之外引用的编号未登记、表 2 登记的编号未被正文引用、编号列未填的行。编号形态取自编号列本身（`D1` 的 `D`、`对比文件1` 的 `对比文件`），专利号与附图标记里的数字不会被当成编号；`D1–D4` 一类区间按逐个编号展开；编号列写成纯数字时只报未填的行（纯数字无法与正文中的序号区分）。标题与正文两处检查都只取可见文本：样式表、脚本与 HTML 注释不计入，注释掉的标题既不参与编号也不构成内部记录。规则与两张用语表在 `packages/patent/patent-document/src/document/documentCompliance.ts`，`scripts/verify-patent-document-output.ts` 对产出的文件或随包模板样例离线施加同一检查。内部记录模板（`invalidation-analysis`，清单 `manifest.json` 的 `internalRecords` 列出）是这些记录的存放处，跳过标题与正文两条内部记录检查；证据编号核对在两种范围都做，内部件同样按一套编号记账。仍为人工检查项：内部任务编号（如 `t1`／`t4`）及其衍生表述、证据篇数口径与编辑过程说明。

## 7. 正式提交件的载体（所外）

本模板产出的 HTML/PDF 是**所内复核稿**。向国家知识产权局提交时使用官方标准表格，正文转入附页：

- **提出无效宣告请求**：`101001 专利权无效宣告请求书`。栏位顺序为 ①案件编号、②国家知识产权局填写框、③无效宣告请求人、④收件人、⑤专利代理机构、⑥请求声明、⑦无效宣告请求的理由/范围/所依据的证据、⑧结合证据对无效宣告请求理由的具体陈述意见、⑨附件清单、⑩药品专利链接声明，末尾为签章与日期。
- **补充意见、答复转送文件通知书**：`100902 复审、无效宣告程序意见陈述书`。⑤栏勾选「针对 ×××× 年 × 月 × 日提出的复审或无效宣告请求 补充意见」或「针对国家知识产权局于 ×××× 年 × 月 × 日发出的……通知书（发文序号……）陈述意见」，正文写 ⑥栏，附件列 ⑦栏。
- **正文续写页**：`100014 附页`。101001 的⑦⑧⑨栏填写不下时用 A4 附页续写，⑨栏须写明附具证明文件的名称、份数、页数、原件或复印件；证明文件为专利文献的，在文件名称一项注明专利号或申请号（表格注意事项原文）。100902 同理：⑥栏填写不下的，使用 A4 纸作为附页续写。
- **份数、页数与原件/复印件状态不入本件**：本件（所内复核稿）的证据清单只登记标识、名称与日期（§4.1），件数、页数与原件/复印件状态在按 101001 ⑨栏、100902 ⑦栏出件时逐条填写；出件前按本件证据清单核对附件实物，核对结果记入案卷内部文件。
- **⑥栏请求声明**按官方表格的表述写「根据专利法第45条及专利法实施细则第69条的规定，对上述专利权提出无效宣告请求」。细则第69条是 2023 年修订（2024-01-20 施行）后的条号；该日之前的出件写第65条。
- **委托文件**：专利权无效宣告程序授权委托书另行取件，本所模板库未收录。
- 本地模板库：`~/.dsh/patent-ops/templates/cnipa-标准表格/`。
- 版式源＝本地模板库（上列路径，仓外维护）；口径源＝本节；更新任一者时须核对另一者。
