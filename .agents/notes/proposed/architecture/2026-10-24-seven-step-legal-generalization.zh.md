# Agent Note: Seven-step legal generalization boundary

Status: proposed

[English](2026-10-24-seven-step-legal-generalization.md) | 中文

## Problem

对抗式七步法是为专利审查场景构建的：审查意见通知书会写明法条、权项与对比文件。七步是：争议定位、耦合采集、规则锁定、三元绑定、风险排序、有界修订回路、双轨检查。R1 的问题是：当法律事实是叙事性的、程序阶段会改变适用规则、且「对手」可能是法院而不是审查员时，这套结构是否还能迁移。

答案决定 M4（法律模式挂载）的范围。把专利流水线原样搬进法律模式，会引入法律任务不成立的假设；什么都不挂，则 `rule_check` 与知识工具只是孤立辅助。本记录给出映射、三个桌面走查与有边界的建议。它是设计证据：没有运行法律基准，所有关于模型输出的判断都标为推断。

## Proposal

结论是**条件泛化**：M4 只保留那些输入与输出能跨域存活的步骤。

1. 保留**规则锁定**作为共享的一等步骤。`rule_check` 已按随包法条索引与沿革判定条文有效性与生效日期；法律引用需要同样的四态结论。
2. 保留**三元绑定**，但绑定的是法律要件而不是专利权利要求特征：`要件 → 支撑事实 → 证据`，每条要件附法条引用。不复用 claim-chart schema。
3. 保留**风险排序**：对未决争点按严重度、概率、影响与缓解措施排序。排序保持确定性；条目由模型给出。
4. 保留**双轨检查**：一轨查形式合规（引用格式、质量门 P0/P1），一轨查实质支撑（所引条文是否承载该命题）。现有 `legal-citation-check` 与 `legal-quality-gate` 就是这两轨。
5. **改写耦合采集**。专利采集从技术交底书提取 PFIE 特征；法律采集从叙事与证据清单出发，输出的是事实/证据缺口表，不是特征向量。
6. **有界修订回路**只在显式人工决策点保留。法律 preset 已禁止未经批准的策略、和解与对外交付；回路必须停在这些点上，而不是绕过它们修订。
7. 不原样移植专利的**争议定位**。专利定位把驳回理由对齐到法条清单；法律定位把请求、案由或合同条款对齐到程序阶段。需要法律专用的争点定位原子，而不是改名的专利原子。

因此 M4 继续，包含四个改写步骤加两个法律专用新增（争点定位与证据映射）；它不会变成第二套专利工作流。

## Mapping matrix

判定：**复用**指专利机制的输入输出原样成立；**改写**指步骤保留但 schema 或提示词必须改变；**不适用**指该任务族不满足步骤前提。

| 步骤 | 诉讼 / 仲裁 | 合同审查 | 合规 / 监管 | 法律研究 | 非诉 / 公司 |
|---|---|---|---|---|---|
| ① 争点定位 | 改写：争点来自诉状与程序阶段，不是驳回理由 | 改写：条款与风险分配替代案由 | 改写：义务与触发条件替代争议 | 不适用：研究问题没有对手 | 改写：交易条款与交割条件 |
| ② 耦合采集 | 改写：叙事事实、证据清单、举证责任 | 改写：合同文本、附件、历次修订 | 改写：许可、备案、监管指引 | 改写：官方法源与版本历史 | 改写：尽调文件与附表 |
| ③ 规则锁定 | 复用：法条、司法解释、现行版本 | 复用：《民法典》与合同专门规则 | 复用：法规与指引版本 | 复用：这是任务核心 | 复用：公司法与登记规则 |
| ④ 三元绑定 | 改写：要件 → 事实 → 证据，含举证责任 | 改写：条款 → 风险 → 后果 | 改写：义务 → 控制 → 证据 | 改写：命题 → 权威源 → 引文 | 改写：条件 → 文件 → 交割步骤 |
| ⑤ 风险排序 | 复用：按严重度与概率排序争点 | 复用：按敞口排序条款 | 复用：按执法可能性排序缺口 | 改写：按决定性排序未决问题 | 复用：排序交割风险 |
| ⑥ 有界修订回路 | 改写：停在策略与和解批准 | 改写：停在对外发送批准 | 改写：停在申报与提交 | 改写：停在依赖未核验权威之前 | 改写：停在签署与交割 |
| ⑦ 双轨检查 | 复用：引用轨 + 质量门 | 复用：引用轨 + 质量门 | 复用：引用轨 + 质量门 | 复用：引用轨 + 权威核查 | 复用：引用轨 + 质量门 |

## Desk walkthroughs

以下是设计走查：输入是代表性样例，中间产物是下文提议的 schema，没有调用模型。它检验每一步是否有可复核的产物，不度量准确性或成本。

### Walkthrough 1 — 诉讼争点分析

输入：一份买卖合同纠纷叙事、证据清单、程序阶段（一审）。

| 步骤 | 中间产物 | 失败点 |
|---|---|---|
| ① | 争点清单：付款请求、质量抗辩、诉讼时效、管辖 | 叙事没有点明案由；模型必须提问或声明假设 |
| ② | 事实/证据表，带缺口列 | 事实没有对应文件；举证责任分配隐含未写 |
| ③ | 锁定规则：《民法典》合同与时效条文，含生效日期 | 容易凭记忆引用已废止的司法解释 |
| ④ | 每个争点的要件 → 事实 → 证据行 | 同一事实支撑两个要件时必须标注，不能静默重复 |
| ⑤ | 按严重度与概率排序的争点 | 没有写明依据的排序会显得很精确 |
| ⑥ | 针对对方最强论点的一轮修订；停在策略批准之前 | 模型可能把合理的反面论证当成改变策略的理由 |
| ⑦ | 引用检查 + 质量门 | 引用可以形式有效，却不承载该命题 |

### Walkthrough 2 — 合同风险审查

输入：一份含管辖法、竞业限制与责任上限条款的保密协议。

| 步骤 | 中间产物 | 失败点 |
|---|---|---|
| ① | 条款级审查计划：范围、期限、违约、救济 | 把商业偏好当成法律瑕疵 |
| ② | 条款清单，标出缺失附件与未定义术语 | 模型按行业惯例补全未定义术语 |
| ③ | 锁定合同成立、效力与责任规则 | 在确认管辖法之前就选规则 |
| ④ | 条款 → 风险 → 后果 → 修改建议行 | 没有后果的风险不可执行 |
| ⑤ | 带建议责任人的风险排序 | 每条都「高」导致严重度膨胀 |
| ⑥ | 一轮修改；停在对外发送之前 | 模型改写未被要求改动的商业条款 |
| ⑦ | 引用检查 + 质量门 | 条款合法但违背客户指示 |

### Walkthrough 3 — 法条适用研究

输入：某类行为是否落入某法定禁止范围的问题。

| 步骤 | 中间产物 | 失败点 |
|---|---|---|
| ① | 问题拆解：行为、主体、时间、地域 | 问题隐藏了程序前提 |
| ② | 带检索日期的官方法源清单 | 用搜索摘要替代原文 |
| ③ | 锁定条文，含生效日期与有效性状态 | 凭记忆假定现行版本 |
| ④ | 命题 → 权威源 → 引文行 | 把转述当成引文 |
| ⑤ | 按决定性排序的未决问题 | 备忘录回答了简单子问题，留下决定性问题 |
| ⑥ | 权威核查后的一轮修订；停在依赖未核验来源之前 | 模型把二手资料当权威 |
| ⑦ | 引用检查 + 权威核查 | 引用有效但不支持该命题 |

## Required legal-domain schema and atoms

法律域需要这些记录；前两项是新增，其余在专利域有对应物，但不得逐字照搬。

- `LegalIssue`：争点 id、案由或抗辩、程序阶段、要件、举证责任。
- `LegalElement`：要件 id、命题、支撑事实 id、证据 id、法条引用。
- `EvidenceItem`：来源、真实性、合法性、关联性、保管链、检索日期。
- `RuleBinding`：法律、条、款、生效日期、有效性状态、裁判要旨。
- `RiskItem`：争点 id、严重度、概率、影响、缓解措施、责任人。
- `DecisionPoint`：人工批准、选项、后果、批准状态。
- `ReviewRecord`：轮次、改动、未决缺口、复核人。

要新增或改写的原子：`legal-issue-framing`（新增）、`legal-element-binding`（新增）、`legal-evidence-mapping`（改写现有证据引擎）、`legal-risk-ranking`（改写专利排序）、`legal-adversary-review`（新提示词，沿用有界回路契约）。`rule-lock`、`legal-citation-check`、`legal-quality-gate` 已存在，保留。

## Alternatives considered

**原样移植专利流水线。** 第一天就有可用引擎，但它的争点定位与 claim-chart schema 编码了专利前提（驳回理由、权项特征、对比文件）。法律走查在步骤 ① 就失败，到不了可复用的步骤。

**保持纯提示词法律模式。** 当前 legal preset 已有八步提示词与一百多个技能，不加结构没有成本。但它留下 R1 发现的两个失败：叙事事实没有与证据分离；引用能过形式检查却过不了实质支撑。

**从零构建独立的七步法律引擎。** 它贴合领域，但会重复 `rule_check`、证据引擎与质量门。走查显示可复用步骤占多数；从零构建会重新挣一遍同样的契约。

## Acceptance criteria

- 矩阵覆盖至少五个法律任务族，每个单元格写明复用、改写或不适用。
- 至少两个走查产出可复核的中间产物，并逐步写明失败点。
- 建议明确回答 M4 是否继续、包含哪些步骤。
- 记录反例与失败点，不只报成功案例。
- R1 本身不改产品代码。

## Risks

证据是设计级的：没有运行法律基准，引用准确率与遗漏争点的收益都未度量。法律任务随法域与程序变化，五个任务族是粗切。结构化步骤增加成本；低风险工作可能更适合纯提示词模式。若新增原子不映射到现有证据与质量门服务，它们会变成第二套词汇。
