# Agent Note：上游 v0.1.5-rc.1 同步与逐面构建维护

Status: implemented

[English](2026-09-10-upstream-v0.1.5-rc.1-sync.md) | 中文

## 问题

fork 在 v0.1.5-alpha.1 同步后继续追踪上游；上游 master 前进到 `aa8262ec09`（发布为 `dsh-v0.1.5-alpha.2` 与 `dsh-v0.1.5-rc.1`，自合并基 `5dda764ed3` 起上游 288 个提交对 fork 398 个提交）。上游增量围绕：Sidebar 文档预览（Markdown、代码、HTML、PDF、图片）取代 fork 自有的 `ui-sidebar-textpreview`；显式的模型文件交付与新 `present` 工具、`sessionFeedback` remote；`command-feedback` 反馈包；模型目录中的 `DeepSeek-V41-Flash`；`ui-deliverables` 的逐面 tsconfig 拆分；以及一个遍历每个 client bundle 的第三方声明生成器。

## 决策

- **注册并集。** remote 挂载清单保留 fork 的 `pluginMarketRemote` 并加入上游的 `sessionFeedbackRemote`；standard 预设在 fork 的插件目录工具之外加入上游的 `present` 工具；`tsconfig.base.json` 增加 `chunked-list`、`tool-present`、`command-feedback/types`，fork 独有的 `tsconfig.base.host.json` 面映射增加其中非 client 的子集（`chunked-list`、`tool-present`、`tool-present/types`、`command-feedback/types`）。
- **依赖分类。** `ui-trajectory` 采用上游把 `@tanstack/react-virtual` 与 `diff` 移入 `devDependencies` 的做法，同时保留 fork 的 `^3.14.10` 下限（debounce timer 的 jsdom 修复）；`llm-deepseek` 在 fork 的 `dsh-brand` 之外加入上游的 `dsh-attachment-local`；`ui-deliverables` 接受上游扩充的 devDependency 集与 fork 的 `dsh-value`。
- **`ui-deliverables` 的逐面 tsconfig。** 上游把该包拆为 `tsconfig.host.json` / `tsconfig.client.json` 加 solution 风格根配置；fork 的 `../../util/value` 项目引用移入其 `isRecord` 导入所在的 client 面。
- **测试适配跟随上游的测试基建。** `user-patches.spec.ts` 改为驱动注入的假 `FSWatcher` 显式 emit，fork 的逐用例 20 秒 FSEvents 预算随之删除，而 `eventually` helper 保留 fork 的 loadavg 失败诊断；`spill-local` 的边界测试改用上游"写入后回读 mtime"的截止值，取代 fork 的整秒取整。
- **第一方 sidebar 的浏览器声明。** 上游的声明生成器按 `<package>/client` 的 tsdown 配置名解析每个 client bundle；`dsh-better-sidebar` 的自定义 bundle 配置（惰性预览 chunk、自有 `/sidebar/bundle` 路由）原本没有名字，现命名为 `@deepseek-ai/dsh-better-sidebar/client`，`THIRD_PARTY_NOTICES.md` 由此记录其内联的外部依赖。
- **版本族与过期元数据。** 三十七个 fork 独有清单移到 `0.1.5-rc.1` 以满足工作区版本约束，并同步更新 `SIDEBAR_SERVICE_VERSION` 镜像；`desktop-seam` 的 `repository.directory` 从改名前的过期路径 `packages/desktop/desktop` 修复为现路径。
- **生成表面。** config-catalog、event-producer-consumer、module-graph、tool-catalog、persistence-catalog、slot-catalog、cordis 目录与 `known-event-types` 从合并后的源码重新生成；zh 侧经 pairing 跟进，lockfile 由 pnpm 重新生成。上游的 `2026-09-09-cancel-superseded-ci` agent note 的 workflow 链接按 fork CI 政策改指 `workflows-disabled/` 归档；fork 的 `ui-sidebar-textpreview` 表面由上游的 `ui-sidebar-documentpreview` 取代。
- **预览打包器与专利包。** Web 预览的 VFS 打包在专利 face 上报出四个不可解析请求：工作区排除表会剥掉 `dist/**`，而 vendored 的 `nuo-patent` 制品只发布 `dist/`（其 manifest 就指向那里），`patent-knowledge` 的 `./bin` face 又解析到被可执行丢弃规则移除的 shebang 脚本。打包器现在在包 manifest 把运行时平面指向 `dist/` 时保留该目录，把 vendored 预编译制品按第三方对待请求容忍（node-only 请求仍在 require 时响亮失败），并容忍目标被可执行丢弃移除的 roster face。打包全绿之后，Cloudflare 上传仍然拒绝运行：四个部署 secrets（`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、`CF_ACCESS_CLIENT_ID`、`CF_ACCESS_CLIENT_SECRET`）从未在本 fork 配置过，预览工作流按 fork 对"本仓库不运营其外部账户的工作流"的既定政策移入 `workflows-disabled/`。

## 后果

fork 在上游 v0.1.5-rc.1 基线之上完整保留其 desktop、patent、self-evolve、synapse、plugin-market、openviking 与 better-sidebar 表面。声明生成器遍历的每个 client bundle 现在都必须携带 `<package>/client` 配置名，拥有自定义 tsdown 管线的第一方包也不例外。host 面的别名映射仍然要在每次同步时手工维护：上游包若缺位于此，只会在打包阶段以 typert 解析错误的形式失败，`tsc -b` 阶段不会报错。

## 备选方案

- **sync 分支 + 开 PR 进 `master`，而非直接合并到 `master`。** v0.1.2-rc.1 起的每次同步都以评审中的 PR 落地；约 2100 个文件的跨仓库合并保持历史可评审。
- **保留 spill 边界测试中 fork 的整秒截止值取整。** 否决：上游回读舍入后真实 mtime 的做法检验同一个 strictly-older 约定，又不把断言耦合到 `utimesSync` 的秒精度。
- **整体照搬上游的 zh 目录文档。** 否决：它们缺少 fork 独有包的区块（patent、better-sidebar、plugin-market、self-evolve）；用重新生成的 en 目录加定向 zh 增量，两侧都完整且配对一致。
