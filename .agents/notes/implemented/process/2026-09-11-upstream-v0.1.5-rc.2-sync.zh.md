# Agent Note: 上游 v0.1.5-rc.2 同步与 client 面类型子路径维护

Status: implemented

[English](2026-09-11-upstream-v0.1.5-rc.2-sync.md) | 中文

## Problem

fork 在 v0.1.5-rc.1 同步之后继续跟踪上游；上游 master 推进到 `c291e7961a`（发布为 `dsh-v0.1.5-rc.2`，自 `aa8262ec09` 起 134 个上游提交）。本次上游增量以公共包 manifest（带插件格式、标签与宿主兼容性的 `dsh-package-manifest` 类型）、agent 预设选择设置、composer 命令菜单分组与 plan/compact/shield 图标、侧栏文件与 skill 引用预览、类型化的 `remote-mock` 原生 mock、同步会话事件读取弃用、以及桌面启动加固（即时窗口、原位 profile、未签名本地构建）为中心。上游还把 linux scope 的空 cgroup 释放改写为查询 `TasksCurrent` 并执行 `systemctl --user stop`，其新的桌面启动测试在 mock Electron 时不带 fork 独有的 `BridgeServer` 与 `globalShortcut` 接缝。

## Decision

- **descriptor 接缝改用 client 面 type-only 子路径。** `subagent` 的 descriptor 从 `@deepseek-ai/dsh-session` 与 `@deepseek-ai/dsh-tools` 裸标识符导入 `SessionEvent` 与 `ToolRestriction`；在 fork 的 per-face tsconfig 拆分下，client 程序解析这些裸标识符会把 host `Context` augmentation 一并拉入，产生约 27 个错面错误。`SessionEvent` 现改从 `@deepseek-ai/dsh-session/types` 导入；`ToolRestriction` 从 `dsh-tools` host index 移入 `types.ts`（index 再导出），descriptor 改从 `@deepseek-ai/dsh-tools/types` 导入。`scripts/type-equiv.manifest.json` 随声明移到 `packages/core/tools/src/types.ts`，与现有非 index 条目一致。
- **手工维护的 host 别名表补入新包。** fork 独有的 `tsconfig.base.host.json` 用 host 面映射覆盖 workspace `paths`；上游新生成的 `@deepseek-ai/dsh-package-manifest` 别名（生成进 `tsconfig.base.json`）到不了 host 程序，`packages/util/package-manifest/README.md` 的 doc-typecheck 代码块因此报 TS2307，直到该别名补进 host 映射（位于 `dsh-output-retention` 旁）。
- **linux scope：上游的空区间释放优先，fork 的残留落定其次。** 冲突解决的 `rangeActive()` 曾把 fork 的残留落定块（已终止、请求文件仍在、无存活成员的 scope）放在上游 `emptyRange` 检查之前，cgroup 清空的 scope 永远得不到释放，新增的 `systemctl --user stop` 测试随之失败。现在 `emptyRange`/`releaseEmptyRange` 检查先执行，fork 的落定块在后，下游重复的 empty-range 块已删除。fork 的僵尸情形（tasks 非零）仍跳过空区间释放，经残留块落定。
- **桌面启动测试采纳上游 Electron mock 并补齐 fork 接缝。** 上游新的 `main-startup.spec.ts` mock Electron 时不含 `BridgeServer` 与 `globalShortcut`；fork 的 mock 工厂补上 `globalShortcut`（`register`/`unregister`/`unregisterAll`/`isRegistered`）与 `app.getName()`，13 个启动测试全部保持绿色。
- **Web roster 的 inject 边只指向 roster 行。** fork 独有的 `ui-todo-board` 不再把 `@deepseek-ai/dsh-tool-todo` 列入 `dsh.client.inject`——上游的 `assembly-bundle-roster` 门禁拒绝 inject 目标不是 roster 行的条目；依赖保留供类型导入。
- **上游 CI note 遵循 fork 的工作流归档政策。** 合并进来的 `2026-09-09-blacksmith-failover-leg` note 的 `ci.yml` 链接改指 `.github/workflows-disabled/ci.yml`，与所有其他 implemented note 一致。
- **生成目录及其 zh 对侧。** `gen-config-catalog`、`gen-persistence-catalog` 与 `gen-doc-graphs` 基于合并后源码重新生成英文配置目录、持久化目录与事件生产/消费图。zh 对侧不做整文重译，而是经配对重建：合并进来的上游 zh 缺失的章节与清单行（全部为 fork 独有包）从 fork master 已评审的 zh 重新插入，代码围栏与来源链接同步到再生成后的英文；事件表在译后表头下逐行镜像英文；每个 pair 用 `verify-translation-pairing --write` 重新记录（988 对全部一致）。

## Consequences

fork 在桌面、专利、自演化、synapse、plugin-market、openviking 与 better-sidebar 各面完整的前提下，交付上游 v0.1.5-rc.2 基线。client 面导入纪律现覆盖 `dsh-tools/types`，与既有 `dsh-session/types`、`dsh-subagent/client` 子路径并列：client 程序消费的新共享类型必须位于（或再导出经由）该包的 `types.ts`，否则同样的错面失败会在 `tsc -b tsconfig.client.json` 复发。host 面别名表每次同步仍需手工维护，而缺失条目如今会在 doc-typecheck 时刻暴露——每个新包的 README 都带可编译的示例块。

## Alternatives considered

- **把 `ToolRestriction` 留在 `dsh-tools` index，只改文档 manifest 映射。** 已否决：descriptor 是 client 可达模块，无论文档 manifest 指向何处，host index 都会把 host `Context` augmentation 拖进 client 程序。
- **整体上收上游的 zh 目录文档，fork 章节留待后续。** 已否决，理由与 rc.1 同步相同：上游的 zh 缺少全部 fork 独有章节，而配对门禁以结构对比标题、围栏、表格形状、清单计数与链接目标——fork master 已评审的 zh 翻译可以机械地合并前进，推迟只会留下红色的 doc-sync 而换不到翻译收益。
- **保留 fork 块在前的 linux scope 冲突解法。** 已否决：残留落定的前置条件（未被消费的请求文件 `existsSync`）在空 cgroup 情形下同样为真，会完全饿死上游的 `stop` 释放；把共享释放排在前面既保留两种行为，又不必合并两组谓词。

## Testing

`pnpm run typecheck`（Host `tsc -b` + tsdown + Client `tsc -b`）、`pnpm run doc-sync`（34 项门禁）与 `pnpm run test` 在 macOS 本地通过：27667 个测试通过，含两个已知环境抖动——`util/http-proxy` bypass 直连（在合并前 master 基线 worktree 上同样复现超时）与 HMR 文件监听计时用例（单独重跑 3/3 通过）。双语 pair 用 `verify-translation-pairing --write` 重新记录。Linux 通道 CI 仍是本次合并的平台权威运行。
