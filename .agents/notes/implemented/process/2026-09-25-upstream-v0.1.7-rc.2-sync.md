# Agent Note: upstream v0.1.7-rc.2 sync

Status: implemented

English | [中文](2026-09-25-upstream-v0.1.7-rc.2-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.1.7-rc.1` tag to the `dsh-v0.1.7-rc.2` release, 346 upstream commits further on. The merge reported 223 conflicts, and the first question this sync had to answer was not which side each conflict took but why a `rc.1 → rc.2` move conflicts at all: the rc.1 sync (#264) landed as a single-parent commit, so the fork's merge base still sat at `dsh-v0.1.7-alpha.2` and a direct merge of rc.2 re-derived 672 conflicts, nearly all of them rc.1 content the fork already carried in different history.

Two upstream changes judge content the fork authors. Upstream replaced the whole-file blob hashes in `*.i18n.yaml` with one record per heading section and removed the `dsh-translation-pairing` merge driver, its resolver, and the installer wiring that registered it — 109 of the 223 conflicts were those records, and the fork's registered driver pointed at a script the merge was deleting. Upstream also rewrote `packages/schedule/schedule` from an agent-scoped reminder store into a host-wide one and deleted the `persistence.ts`/`transaction.ts` modules the fork's copy imports.

## Decision

- **The sync runs as two merge-forwards, and the first one is what makes the second an ordinary merge.** `git merge dsh-v0.1.7-rc.1` resolves 25 conflicts — the same set the rc.1 sync faced — and produces the merge commit whose second parent is the real rc.1 commit; `git merge dsh-v0.1.7-rc.2` then reports the 223 conflicts the two releases actually share. A future sync reads `git merge-base HEAD <upstream tag>` first: a base older than the previous sync's tag means an earlier sync landed as a squash, and merging the skipped tag first is cheaper than resolving its content twice.
- **The desktop keeps the fork's tray and bridge, and takes upstream's adjacent modules.** `apps/desktop/src/tray.ts` stays the fork's pure helpers and `main.ts` keeps constructing the Electron `Tray` itself and handing it to `bridge.initTray`, so a plugin can still contribute tray entries; upstream's new `DesktopTray` class is dropped, as is its second `window.on('close')` handler. Upstream's independent `quit-confirmation.ts` and `background-notice.ts`, which do not depend on that class, stay, and the fork's close handler gains their update-dialog and background-notice branches. The `tray.dispose()` calls upstream's class carried become `tray.destroy()` on the bare Electron object.
- **`packages/schedule` takes upstream's rewrite whole.** The fork's copy imports `./persistence.ts` and `./transaction.ts`, both of which upstream deleted in the same release, so the package's own history decides this one: the host-wide service and its `./typert`/`./remote` export entries land, and the fork's Config field survives only where its consumer does.
- **`packages/subagent`'s `list-children.ts` keeps the fork's `coldReadConcurrency` Config field.** The fork promoted the concurrency cap from a module constant to a validated `Config` field with a README contract and three spec cases; upstream's rewrite inlines it again. The field is the fork's, so the file resolves to the fork and upstream's simplification does not land.
- **The client surfaces split by whether the change carries fork content.** `packages/client/locale` keeps `DSH Patent` for `brand.localBuild` and takes upstream's new `workspace.defaultName`. `packages/client/ui-primitives/tsconfig.json` and `packages/client/tsdown.client.ts` resolve as unions (upstream's `util/code-language` reference and `default-workspace` inline-safe entry join the fork's `util/values` and `value`). `packages/client/ui-schedule`'s and `packages/client/ui-sidebar`'s conflicting specs resolve to the fork's copies, which match the fork's own service types; the sidebar fixture then gains the `useShortcuts` hook upstream's `SidebarRoot` now requires.
- **`Session.toolHistory()` is ported, not merged.** Upstream added the method to `packages/core/session/src/index.ts`; the fork had already split that file, leaving the class in `session.ts` and the entry as re-exports. The method and its `ToolHistoryProjection` field are ported into `session.ts` against the fork's field names, and the entry takes the fork's structure — merging the two entries literally produced three `Session` declarations.
- **The trajectory tool-addition rendering is ported into the fork's split files.** Upstream's two changes to `TrajectoryTable.tsx` land in `trajectory-markdown-content.tsx` (the raw-text branch for a source-block set that is all tool add/remove) and `trajectory-row.tsx` (the `singleToolNotice` row that is not selectable), because the fork renders those rows from the split files rather than the monolith.
- **The fork adopts upstream's translation-pairing mechanism.** The heading-section records, the `gen-translation-brief` recovery path, and the removal of the merge driver are all upstream's; the fork drops the driver from `.gitattributes` and from its worktree git config, and `pnpm run verify-translation-pairing --write --all` migrates the records the fork alone carried. The Chinese pages of `docs/tool-catalog` and `docs/capability-seams` gain the schedule sections upstream added, since the fork's copies predated the host-wide rewrite.
- **The two whole-section schemas the fork deleted come back.** `ChatSettingsSchema` and `ConversationSettingsSchema` were removed as consumerless in `refactor(client): drop dead chat and conversation surface`; upstream's `apply.client.spec.ts` and its siblings are consumers again, so the removal no longer holds and both definitions return.
- **The version family and the ACP pin move with the release, in a follow-up commit.** `pnpm run constraints` requires each manifest to equal the root version, so the 43 manifests upstream does not ship move to `0.1.7-rc.2` with `SIDEBAR_SERVICE_VERSION`; `packages/api/remotes` regains the `@deepseek-ai/cordis` devDependency the conflict resolution dropped, which `constraints` reported. The nine `snapshots/acp/*/stdout.expected.jsonl` pins move with the release, and `DSH_SNAPSHOT=refresh … --update` regenerates the headers the release also changed.
- **The type-equivalence docs follow the ported source, in both languages.** `docs/subsystems/session.md` gains the `toolHistory()` declaration, `docs/subsystems/subagent.md` takes the source's `SubagentDescendantListEntry` JSDoc, and both `.zh.md` pages mirror them byte-for-byte, because `verify-type-equiv` pairs a Chinese block with its English sibling only while they are identical.
- **`tsconfig.host.json` extends `tsconfig.base.json`, and the fork-only `tsconfig.base.host.json` is deleted.** Upstream's host aggregate reads the one base config; the fork's extra face file carried a `paths` set that omitted the client packages the host aggregate's `apps/web/tests/shortcuts-*.e2e.ts` files import, which is why those files could not resolve `@deepseek-ai/dsh-client-shortcuts/protocol`. `apps/desktop/src/print.ts` joins the keyboard-test program for the same reason on the desktop side.

## Consequences

The fork ships upstream's v0.1.7-rc.2 baseline with its patent, desktop, better-sidebar, and plugin-market surfaces intact, and its history is once again a connected graph: `git merge-base HEAD dsh-v0.1.7-rc.2` is the rc.2 commit, so the next sync reads the real conflict set instead of re-deriving previous releases. The desktop tray, the subagent concurrency field, and the tool-todo description are the three places where the fork and upstream now genuinely differ, and each will conflict again on the next release that touches it. The `dsh-translation-pairing` driver is gone, so `*.i18n.yaml` merges with git's default text merge and the records are keyed by section rather than whole file; the fork's `type-equiv.manifest.json` entries for the files it split stay pointed at `session.ts` and `tools/src/types.ts`. `pnpm run doc-sync` carries one failure, `verify-package-paths` on `docs/TECH_DEBT.md:225`, whose quoted path left the tree long before this merge.

## Alternatives considered

- **Merge rc.2 directly.** Not available: with the merge base at `dsh-v0.1.7-alpha.2`, 672 conflicts describe the fork's own rc.1 content as if it were divergent work, and resolving them would re-decide 24 merges that were already made.
- **`git merge -s ours dsh-v0.1.7-rc.1` to reconnect the history without resolving its conflicts.** Rejected: the fork's content matches rc.1 closely enough that the real merge costs 25 conflicts, and `-s ours` asserts the fork contains rc.1 without checking, so any content the squash dropped would be skipped silently and permanently.
- **Keep upstream's `dsh-translation-pairing` driver along with its script.** Not available: upstream deleted the script in the same commit that retired the mechanism, and a registered driver pointing at a missing command turns every pairing conflict into an unstaged file with no markers.
- **Take upstream's `list-children.ts` rewrite and drop `coldReadConcurrency`.** Rejected: the field is a validated `Config` field with a documented contract and spec coverage, and the repository's rule is that a deployment-varying choice is a `Config` field rather than a constant.
- **Take upstream's `tool-todo` description.** Rejected: the fork's schema carries the `tags` field, so the description has to describe it; the fork keeps its paragraph and adds upstream's whole-list replacement sentence to both READMEs.
- **Merge the two `packages/core/session/src/index.ts` entries.** Rejected: it produced three `Session` class declarations. The fork's split is the structure; upstream's addition is a method to port into `session.ts`.
- **Restore `tsconfig.base.host.json` with the client paths added.** Rejected: a host face file whose `paths` duplicate the base config is a second source of truth for one list, and upstream's layout reads the base config directly.

## Testing

`pnpm run typecheck` covers both compiler faces and exits 0, `pnpm run build` succeeds for the host and client bundles, and `pnpm run lint` exits 0. `pnpm run constraints` passes with the 43 fork-only manifests at the root version, and `pnpm exec tsx scripts/release/verify.ts --family dsh` resolves 357 members at `0.1.7-rc.2` with the publish order resolved. `pnpm run doc-sync` reports 44 gates passed and 1 failed, the failure being the long-standing `verify-package-paths` entry above; `pnpm run verify-type-equiv` holds its 1:1 pairing at 466 blocks across 53 docs, and `pnpm run verify-translation-pairing` accepts all 1418 pairs. `pnpm exec vitest run --config vitest.snapshot.config.ts snapshots/acp` replays all 16 cases keyless after the pin refresh. The generated catalogs come from their generators on the resolved tree (`gen-config-catalog`, `gen-tool-catalog`, `gen-doc-graphs`, `gen-module-graph`, `gen-persistence-catalog`, `gen-cordis-catalog`, `gen-plugin-packages`), and `git merge-base HEAD dsh-v0.1.7-rc.2` reports the rc.2 commit.
