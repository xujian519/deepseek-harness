# Video Deliver（交付与质检）

先自检，再登记。`video_deliver` 只核它能机械判定的事实；画面内容是否达标由你与用户判断。

## 交付前自检

- [ ] **完整性**：每个镜头有选中片段；EDL 覆盖全部镜头。
- [ ] **技术**：MP4、H.264/AAC、目标画幅与分辨率、30fps、`faststart`。
- [ ] **时长**：与 brief 目标偏差不超过 10%。
- [ ] **声音**：有音轨；对白可辨；BGM 不压过对白；响度接近 -14 LUFS。
- [ ] **字幕**：SRT 存在、时间轴单调；烧录或明确声明软字幕。
- [ ] **来源**：每个镜头记录 provider、model 与 prompt；BGM/歌曲/切片源有授权记录。
- [ ] **合规**：AI 标识写入元数据或清单；需要可见水印时已加水印。
- [ ] **成本**：上报成本不超过预算；超支先向用户说明。
- [ ] **画面**：有视觉模型时抽帧审阅；没有时明说“未做画面审阅”。

## 登记

```text
video_deliver {
  project_path: "video/<id>/project.json",
  files: [
    { path: "out/ep01.mp4", format: "video" },
    { path: "out/ep01.srt", format: "subtitles" },
    { path: "out/ep01-poster.jpg", format: "poster" },
    { path: "out/ep01-manifest.json", format: "manifest" }
  ]
}
```

阻断项（缺文件、镜头不完整、无可读视频流、成本超预算）会拒绝登记；先修再登记。告警项（时长偏差、无音轨）写入交付摘要，由用户决定是否接受。

## 交付摘要

给用户的摘要只含：成片路径、时长与画幅、字幕与封面路径、总成本、未通过或未核验的项、下一步可选的返工点。不要把成片全文或大段 JSON 贴进对话。

## 检查清单

- [ ] 阻断项为 0
- [ ] 交付摘要列出全部路径与成本
- [ ] 未核验项明确标注，不伪装为通过
- [ ] 用户已终审
