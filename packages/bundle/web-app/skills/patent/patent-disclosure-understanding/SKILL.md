# 交底书理解

将技术交底书转成结构化理解，作为后续检索、新颖性/创造性分析与撰写的唯一输入基线。先读原文再分析，禁止凭标题或摘要臆断技术内容。

## 作业步骤

1. 读取交底书（docx/pdf/md，必要时用 tool-bash 的 pdftotext 转文本），定位四段：技术问题、背景技术、技术方案、技术效果。
2. 将技术方案分解为最小技术特征单元并标号（F1/F2/…），每个特征标注类型：structure（结构）/ method（方法）/ parameter（参数）/ material（材料）。
3. 提炼 PFE 三元组表：技术问题（Problem）、技术特征（Feature，标号化）、技术效果（Effect），逐项对应，不混用。
4. 对发明点分级：核心发明点（决定新颖性/创造性的特征组合）、从属改进（可进从属权利要求）、常规手段（不主张）。
5. 标注隐含特征：交底书未明说但实施该方案必需的特征（连接关系、配合关系、必要参数），列出待与发明人确认项。
6. 与背景技术初步分界：哪些特征疑似现有技术、哪些疑似新，仅作检索方向的假设，不作结论。
7. 技术矛盾与补强清单（发明人侧）：用 `triz_contradiction_analysis` 过一遍交底书原文（`text` 传原文，可用 `focus` 收窄到具体指标）。产出两样东西：① 技术矛盾（改善某工程参数同时牺牲另一工程参数）与矩阵推荐原理——据此给出发明人可选的替代方案方向，供方案探索或规避设计讨论；② 交底书提到却没给取值的工程参数（缺现状值／目标值／单位／测量口径）——这就是向发明人提问的清单。工具已丢弃证据无法回溯到原文的矛盾，报告里不得把它们当作交底书内容。

## 产出

写入 `03-分析/XX_交底书理解.md`（XX 为案号），包含 PFE 表、特征分解表、发明点分级、隐含特征清单、现有技术初步分界、技术矛盾与参数完备性表（含交底书补强清单）。需要出具补充建议函时，补强清单是其主要输入。

## 质量门禁

PFE 三元组完整且逐项对应；特征已标号且类型明确；发明点分级明确；技术矛盾的证据均可回溯到交底书原文；参数缺口逐项写明缺失维度；不确定处标注"待确认"，不臆断补全。

## 边界

- 技术矛盾属于发明构思层面的参数取舍，**不得**写进创造性三步法第二步的"实际解决的技术问题"——该问题必须相对区别特征确定且不含解决手段，二者混用会直接违反创造性问题表述的检验。
- 本步骤不产出检索结论，也不替代 `patent-novelty-inventiveness`；矩阵推荐原理是发明人侧的方法提示，不是法律依据。

## 人工确认

发明点分级与检索方向先用 ask_user 与用户确认，再进入 patent-prior-art-search。
