# 审查意见答复 / 意见陈述书 — 版式惯例（Conventions）

> 生成或修改本模板前必读。与 `checklist.md` 配套。

## 1. 文书结构（固定顺序）

1. 页眉（所名 + 密级）
2. 文书抬头（类型徽标 / 标题 / 答复编号）
3. 案件信息表（申请号 / 发明名称 / 通知书编号 / 发文日 / 答复日期 / 申请人或代理人）
4. 一、总体立场
5. 二、本次修改（表 1 修改对照表 + 2.1 修改后独立权利要求全文——两份都写，见 §11）
6. 三、本案事实（3.1 申请文件记载的事实 / 3.2 对比文件公开的事实）
7. 四、适用规则
8. 五、意见陈述（5.1 新颖性 / 5.2 创造性 / 5.3 其他争点）
9. 六、其他缺陷的处理
10. 七、证据与引用（7.1 证据清单 / 7.2 引用日志——两份都保留，见 §11）
11. 八、结论与请求
12. 落款 + 免责声明 + 页脚

## 2. 论证骨架：事实 → 规则 → 论证

全文按三段推进，缺一段即为不合格：

1. **事实**（第三部分）。只写"本申请记载了什么、对比文件公开了什么"，逐项编号（F1…／P1…）并注明出处（权项号、说明书节次与页码行号、对比文件段落）。**每项不超过两句**，只保留与争点相关的特征；不带评价、不带结论。
2. **规则**（第四部分）。逐条列明本案据以论证的规则，编号 R1…，注明法条条款号或《专利审查指南》节号。
3. **论证**（第五部分）。每条论证回指事实编号（F/P）与规则编号（R），按争点组织。

**禁止把评价写进事实部分**：「本发明与对比文件有本质区别」是论证结论，不是事实。事实与评价分离，既是论证清晰的前提，也是审查员复核的便利。

## 3. 组织单元是争点，不是审查意见编号

- 论证按法律命题分节（新颖性／创造性／其他争点），**不按通知书的审查意见项号分节**。
- 审查意见项号只在需要让审查员定位时以括注出现，例如「（审查意见第 3 项）」；不得作为小节标题。
- 存在多个独立争议（如同时涉及 26.3、26.4、22.3）时，仍按争议主题分节，不按通知书顺序铺陈。
- 形式缺陷（笔误、附图标记、摘要撰写、用词）一律收入第六部分「其他缺陷的处理」，逐项列处理方式与依据，不与实体论证争篇幅。
- **通知书未提出的争点不设节**：某节无实体内容就整节删掉，不写空节，也不写「本案不涉及新颖性」式的占位句——占位句既占篇幅，又让随争点收缩的结构又长回去（篇幅口径见 §10）。

## 4. 法条与指南引用

- 新颖性：《专利法》第 22 条第 2 款。
- 创造性：《专利法》第 22 条第 3 款；判断方法引《专利审查指南》第二部分第四章第 3.2 节、第 3.2.1.1 节。
- 修改依据：《专利法实施细则》第 57 条第 3 款（针对通知书指出的缺陷进行修改）。
- **条号必须核验后引用**，不得凭记忆书写；旧版条号（如 2010 年细则第 51 条第 3 款）应换算为现行条号。
- 随包索引已转录《专利审查指南》2023 年修订版的节正文，逐字引用前用 `law_verify` 核验命题是否落在所引节及其子节内；索引里的节正文不是 2026 年版，引用 2026 年版改动过的节时另行提供该版文本来源。
- 本案域在用指南节号（集中登记；引用前对照原文核验——本仓索引不含指南节号）：第四章第 3.2 节、第 3.2.1.1 节（创造性）；第二章第 2.1.3 节（26.3 判准）；第二章第 3.2.1 节（功能性限定，见 writing-patterns `07-oa-clarity-support.yaml`）。
- 无来源支撑的断言删除，不降级为模糊表述。

## 5. 事实的 pin-cite 精度

- 本申请：权项号 / 说明书节次 / 页码行号。
- 对比文件：文献号 + 权利要求项号 / 说明书段落号或页码行号 + 附图标记。
- 结构性定位（"说明书'发明内容'部分""实施例 1"）只用于工作稿；**正式稿必须落到页码行号**。

## 6. 权利要求修改标注

- 新增内容用下划线 + 加粗（`<span class="added">`）。
- 删除内容仅在修改对照表中用删除线（`<span class="deleted">`），正式权利要求文本中不保留删除线。
- 修改后的独立权利要求必须全文呈现，不能只写「参见修改对照表」。
- 表 1 与全文是两份、都要写（D-1 裁决，见 §11）：表 1 记「改了哪几处、依据是什么」，全文给「改完的独立权利要求是什么」。表 1 里登记过的独立权利要求，全文必须能对上；反向不要求——从属权项的修改只出现在对照表里是合规体例。

## 7. 视觉与版式纪律

- 沿用 `assets/templates/patent/tokens.css` 品牌变量；agent 不改样式。
- `claim-text` 区块用于权利要求全文，左侧 accent 竖线标识。
- 表格数字列使用 `tabular-nums`。

## 8. 正式提交件的载体（所外）

本模板产出的 HTML/PDF 是**所内复核稿**。向国家知识产权局提交时使用官方标准表格：

- 载体：`100012 意见陈述书`（①著录项、②陈述事项、⑤附件清单、⑥签章）+ `100014 附页`（正文）。
- 表格 ② 栏写称呼与引子（如「××审查部 ××（审查员代码）审查员：您好！根据您的审查意见，现答复如下：」）；正文转入附页时写「下转附页第②栏」。
- 正文较短（仅同意修改、无实体争辩）时直接写在 ② 栏，不启用附页。
- 附件清单须列明份数与页数，且与实际提交页数一致。
- 本地模板库：`~/.dsh/patent-ops/templates/cnipa-标准表格/`。
- 版式源＝本地模板库（上列路径，仓外维护）；口径源＝本节；更新任一者时须核对另一者（2026-10-16 审阅乙4）。

## 9. 品牌契约注入点

同 `assets/templates/patent/DOCS.md` 与 `tokens.css`。抬头所名、密级、免责声明由 CSS 变量注入。

## 10. 篇幅预算与删减纪律

预算的单一来源是 `patent_oa_response_v1` 的 `OA_RESPONSE_DRAFT_BUDGET`（`packages/patent/patent-workflow/src/workflow/manifests.ts`），本节数字与它逐项一致；改预算须同时改本节。"硬上限"列是 `OA_RESPONSE_SLOT_QUOTAS`（`patent-document` 的 `draftSchema/generic.ts`，取预算 × 1.25 向上取整），渲染前 fail-closed，只拦明显失控的草案。

计数口径：去掉空白后的**可见字符**，不含表格与权利要求全文。这条口径由实现执行，不靠自觉：`patent-tools` 的 `visibleChars` 先剔除载体块（Markdown 表格行、HTML `<table>`、`claim-text` 元素与「修改后的独立权利要求」整节）再计数，`slop-gate` 的篇幅维度与 `tighten` 的字数核对都走它。所以删表、删权项全文既减不了字数，也不允许——它们分别是表 1/2/3 与 2.1（见 §11）。

| 位置 | 预算 | 硬上限 |
| --- | --- | --- |
| 全篇正文 | 4000 字 | — |
| 一、总体立场 | 200 字 | — |
| 三、本案事实 | 每小节 5 项、每项 2 句（约 800 字） | 1000 字 / 7 项 |
| 四、适用规则 | 6 条 | — |
| 五、意见陈述 | 新颖性 1200 字、创造性 1200 字 | 各 1500 字 |
| 五、5.3 其他争点 | 3 条 | — |
| 八、结论与请求 | 150 字 | — |
| 表一修改对照 / 表二证据 / 表三引证 | 每处修改一行 / 每份证据一行 / 每条引证一行 | 20 / 15 / 30 行 |

四条删减纪律：

1. **不设空节**：见 §3 最后一条。
2. **不写模板指导语**：「本部分应当说明…」「以下逐项分析…」这类交代写作动作的句子不是正文，删掉；每段第一句直接给结论。
3. **每句都要有读者理由**：删减按此顺序——复述审查意见、复述法条原文、与争点无关的事实、同一论点的第二遍表述。
4. **超预算先整段删，不先缩句**：把 4300 字同义改写成 4000 字仍属超预算写作；先按上一条的顺序删到预算内，再打磨句子。

判定由三方分担：`draft` 阶段按本节数字写，渲染前由 §10 的硬上限 fail-closed，`slop_gate` 阶段按全篇预算判 concision（超预算即扣分，不再按段数计）。

## 11. 两处双份的边界（D-1 裁决）

第二部分的「修改对照表 × 修改后独权全文」与第七部分的「证据清单 × 引用日志」都是**两处都写**，不合并。2026-10-31 裁决（D-1）：

- **修改对照表 × 独权全文**：对照表是差异视图（改了哪几处、依据是什么），全文是生效文本（改完的权利要求长什么样）。审查员先按对照表定位改动，再读全文确认保护范围；只给对照表要读者自己拼出改后的权项，只给全文则看不出改动位置与修改依据。故 §6「必须全文呈现」与表 1 同时成立。
- **证据清单 × 引用日志**：清单是材料登记（一份证据一行，记客观属性：公开号、公开日、可引用段落），日志是断言溯源（一条断言一行，含来源类型与置信度）。一条证据可支撑多条断言，一条断言也可跨多份证据；合一就把一对多压成一对一，不是丢掉映射就是重复登记同一份证据。

两份是同一事实的两种视图，因此要守的是**互相对应**，不是逐字一致：

| 对照关系 | 机械检查 | 判定 |
|---|---|---|
| 表 1 登记的修改 ↔ 2.1 全文的权项 | `amendment-cross-reference` | 表 1 有行、章节里没有全文 → 报；全文写的权项表 1 没登记 → 报。**反向不报**（从属权项只在对照表里出现是合规体例） |
| 证据清单编号 ↔ 正文引用 | `evidence-cross-reference` | 引用日志表也计入「正文」：日志引用的 D 编号必须登记在清单，清单登记的编号必须在正文或日志里出现 |
| 表 1 / 表 2 / 表 3 的数据行 | `empty-table` | 只有表头没有数据行、或数据行整行是模板占位符 → 报 |

三条都由 `patent-document` 的 `checkDocumentCompliance` 在渲染后执行，命中写入渲染告警。

文字级一致性（对照表「修改后」列与全文逐字相同）**不做机械判定**：对照表是差异摘要，允许用省略号略去未改动部分，按子串比对必然误伤。这一层靠 `checklist.md` 的人工复核。
