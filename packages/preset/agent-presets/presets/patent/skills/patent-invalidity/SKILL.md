# 无效宣告分析

分析目标专利的无效理由，评估证据组合与成功率。

## 必查清单（先查再分析）

- 用 patent_case_search 查相似无效决定的证据认定：多文件结合技术启示、单文件+公知常识、现有技术认定、不清楚认定、充分公开认定、修改超范围与优先权。
- 用 patent_kg_query 追查复审无效推理模式裁判规则。
- 用 cnlaw MCP 的 `mcp__cnlaw__*` 或 patent_case_search 核验 A22.2 / A22.3 / A26.3 / A26.4 / A33 / A9 法条原文，需要打开页面时用 `web_fetch`。

## 无效理由地图

- A22.2（新颖性）/ A22.3（创造性）：证据公开日须早于申请日/优先权日。
- A26.3（说明书充分公开）/ A26.4（权利要求得到说明书支持、清楚）：不依赖外部证据，聚焦文本。
- A33（修改超范围）/ A9（同样的发明创造，重复授权）。

## 分析流程

1. 拆解独立权利要求，识别核心创新点与弱点（必要特征/上位概念/功能性限定/不清楚之处）。
2. 理由识别走确定性内核：用 patent_workflow_run（manifestId=patent_invalidation_v1；input=无效宣告请求书或对方理由，claims=权利要求书）跑一遍，grounds 阶段按无效理由表识别文书援引的理由（新颖性 / 创造性 / 公开不充分 / 权利要求不清楚或得不到支持 / 修改超范围），claim-chart 阶段（mode=invalidity）做要素级证据映射，novelty 与 inventiveness 收口阶段同时读到理由与对照表。识别结果只表示正文提到了该条款，是否被实质论证须人工核对；无命中时不得替文书认定理由。
3. 检索申请日前公开的证据并评估相关度。
4. 每条权利要求构建至少 2 个无效理由（主理由 + 备选理由）。
5. 证据组合策略至少 3 种（D1 单独 / D1+D2 / D1+公知常识 / 证据链），并用 claim_chart_build（mode=invalidity）逐要素钉住每篇证据的公开内容与段落位置。
6. 基于复审无效决定评估成功率，每个理由给出成功与失败风险点。

## 输出

无效策略报告：证据清单 + 无效理由 + 成功率 + 风险评估。

## 质量门禁与人工确认

证据公开日逐一核验；无效理由组合先 ask_user 确认再起草；报告附免责声明；交付前经 patent-quality-gate。
