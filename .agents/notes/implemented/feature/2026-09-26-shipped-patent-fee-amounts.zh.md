# Agent Note: 随包转录的专利费用金额，以及条目模型定价不了的部分

Status: implemented

[English](2026-09-26-shipped-patent-fee-amounts.md) | 中文

## Problem

`patent_fees` 随包带的费用索引记录了案件该缴哪些费种、每个费种怎么计数，却没有任何金额：每一项的 `amount` 都是 null。人设与质量门禁都要求金额由工具算出，因此专利域的数字纪律正好在"钱"这一处漏了洞——工具交得回费种清单、拒绝得了合计，却定不了任何价。文件里已有的字段取自本仓自身的陈述，而不是官方收费标准；而本仓已记录过其《专利法实施细则》编号混用了不同修订版本。

## Decision

按官方收费标准转录金额，并让**条目模型**（而不是转录工作）决定哪些价格表达不了。

- **金额取自国家知识产权局缴费服务指南的收费标准（附件2）。** 每一项都记下抄录的文书与抄录日期。`effectiveFrom` 保持 null：指南的国内费用表没有给出生效日期，填成指南自己的发布日期等于断言指南没说的事。
- **一条费种只承载一个金额，因此一个价格就是一条费种。** 申请费、复审请求费、无效宣告请求费对发明与对实用新型／外观设计是两个价，三种专利类型的年费分档也各自不同，因此它们拆成了按 `patentTypes` 限定的独立条目。消费方按查询的专利类型过滤，所以一个案件只会命中其中之一。
- **两个费种保持无金额，原因是模型、不是没做完。** 说明书附加费按页分档收费（第 31 页起 50 元、第 301 页起 100 元），延长期限请求费按次数分档（第一次每月 300 元、再次 2000 元）。条目只有一个 `freeUnits` 和一个 `amount`，查询也不带档位选择或次数，因此把任一项拆成两条都会把其中一档的单价套到所有单位上。它们保持 null，工具因此扣住合计，而不是给出一个对案件的一部分来说是错的数字。
- **减缴连同一条说明清楚的近似一起记录。** 减缴比例 85%（个人）与 70%（企业）已记录，`reducible: false` 用来标注标准划在减缴之外的费种——此前 `null` 同时承担"不在减缴范围"与"未登记"两种含义。官方口径是"自授权当年起十年的年费"，而查询不带授权年度，因此 `reductionMaxYears: 10` 是专利年度上限，不是规则本身。
- **移除印花税。** 2023 年修订的《专利法实施细则》第一百一十条列举费种时没有它，缴费服务指南也不收该费，因此该条目没有保留的依据。

## Alternatives considered

**新增分档价格字段（`bands: [{from, to, amount}]`）把两项都精确计价。** 那样能一次补上两个缺口。它因本次改动的范围而落选：它会触到类型、读取器、数量运算、工具参数 schema，以及每一个构造费种的测试，而价格模型该长什么样本身就该是一次独立决定，而不是搭着转录一起做。在它落地之前，两个 null 让缺口保持可见。

**说明书附加费只按第一档计价。** 多数说明书写不到第 301 页，因此多数时候是对的。它落选，是因为"多数时候对"就是一张算错的单：320 页的说明书会把 300 页以上的每一页少收，而报告里没有任何东西会说出来。

**索引保持不转录，由各部署自己填自己要报的费种。** 那正是随包的状态。它落选，是因为人设本已要求金额由工具拥有，空索引让这条纪律从"范围窄"变成"做不到"。

## Consequences

默认部署现在能为一个案件定价申请、审查、授权、年费与各项程序费用并给出合计，而且只在需要凭空造一个单价的地方扣住合计。剩下的，是两个分档计价的费种——它们需要能承载档位的价格模型——以及一条长期限制：金额是机械抄录。`verifiedOn` 记录的是抄录何日对照来源核过，本次改动没有在任何地方断言有人回读过它。
